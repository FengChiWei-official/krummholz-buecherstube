# 体系问题审查（CRITIQUE v1）

> 审查对象：`/tmp/krummholz-migration/PLAN.md` v4。方法：日常使用 + 逻辑自洽两个角度。
> 数字口径：`[复验 2026-10-06]` 在 `/tmp/km-copy`（迁移副本）与真库（只读）重跑实测；与 session 实测不同处以复验值为准。

### 总评一

v4 的迁移是内容无损的，但它验证的是「搬家不出事」，不是「新家住得下去」。§6 的八条校验全 PASS 证明的是 wikilink 零破坏、去向无冲突；而体系成立的前提——捕获规则被执行、主干可收敛、检查门有效——v4 一条都没有验证。本次审查把镜头从「迁移」转回「住」：十四个问题里，四条是体系内部的自相矛盾（A 组中标高/中者），三条是会让体系按旧模式死掉的使用问题（B1/B3/B5）。

### 总评二

旧体系的三大死因——**门常红 → 门失效**（check 长期红灯，人学会无视）、**tag 三份状态漂移**（status/in-progress 129 篇陈年不动，等于没有状态）、**周期流程停摆无告警**（trend-radar 停摆 9 天无人察觉）——在 v4 里各有至少一个复发路径：A5 重演门常红，A1+B1 重演状态漂移（只是漂移的位置从 tag 挪到 todo 树与零出链信号），B3 原样保留停摆不可见。v5 的修法不是发明新机制，而是把这三个复发路径逐一堵死：不变量分两级（硬门可阻断、报告级给增量）、半成品信号单列（时间窗脱离存量噪声）、节律可见性进 `status` 顶部。

## A 组｜逻辑自洽

### A1｜状态单点化把半成品盲区放大了

**结论**：旧体系未挂钩的半成品至少有 `status/in-progress` 自报；新体系状态只在 todo 树，忘挂钩的半成品唯一代理信号是「零出链」，而该信号已被存量噪声淹没。

**证据**：零出链 392/741（52%）`[复验 2026-10-06]`（session 实测 393/53%，以复验为准）。一半笔记零出链时，「写了一半」和「从来就不链」无法区分，信号失效。

**严重度**：高。

**状态**：已裁决修法（v5 并入）——rawindex 把「近 7 天创建 + 零出链 + 无 todo 挂钩」单列为**疑似半成品**；时间窗让信号脱离存量噪声。

### A2｜聚类粒度与主干粗粒度矛盾

**结论**：每簇一个 Raw Index 的隐含假设会把主干长成几十篇细文件，违反 D10-P3（粗粒度低频重估）。

**证据**：六轮模拟（v4 §4.1）累计 68 簇（34+19+15）；`--clusters` 复验单轮即得 L1 粗簇 42 个、L2 细分 31 簇 `[复验 2026-10-06]`。68+ 篇 Raw Index 不是主干，是另一棵语义树。

**严重度**：已裁决（原判高）。

**状态**：已裁决——**AI 把簇归组，一个粗 Raw Index 包含几个簇**，细结构（簇 + 共性）进 Index。v5 落点：§2 主干定义、§4.1、`--clusters` 输出格式（簇 → 建议归入的粗 Raw Index）。

### A3｜Links 判据把「没写完」和「写错了」混为一谈

**结论**：I2 要求 Links 成员横跨 ≥2 个 Index 区域，但 Index 是涌现的、只覆盖部分笔记；「无区域」不是体裁错误，是语义树还没长到那儿。

**证据**：跨界 4 / 同区域 6 / 无区域 22 `[复验 2026-10-06]`。22 篇无区域的 Links 成员所在领域（如语言学习、编码实践）尚未建立 Index 区域。

**严重度**：中。

**状态**：v5 并入——I2 分两档：「同区域」=真违规（并入 Index 或降级 Node）；「无区域」=提示（随 Index 生长自动消解，不计违规）。

### A4｜「会变的删」与永久主干自相矛盾

**结论**：原则判据是「变不变」，但主干成员集每轮聚簇都在变，主干却是永久机制——按字面执行，主干也该删。

**证据**：§1 理念 3 原文「会变的删，不变的留」；§4.1 六轮收敛 674→108 本身就是成员集持续变化的证据。

**严重度**：中。

**状态**：v5 并入——理念 3 改写为「**人维护的会变之物才删；变化由 AI 承载的可以留**」（复杂度守恒的推论）。

### A5｜I1–I4 上线即全红 = 重演「门常红→门失效」

**结论**：把 I1–I4 做成阻断性硬门，上线第一天 674 篇未登记、392 篇零出链全部亮红；旧体系的 check 正是因长期红灯而失去门的效力，v4 原样重演。

**证据**：I1 未登记 674、I3 零出链 392/741 `[复验 2026-10-06]`；旧体系 stale in-progress 129 篇（mtime >90 天，`[复验 2026-10-06]`，与 session 实测一致）。

**严重度**：已裁决（原判高）。

**状态**：已裁决——两级制：**硬门** = root 排空 / material 出处 / wikilink 新增悬空（可阻断）；**I1–I4 报告级**，每周输出增量（队列 674→…、零出链 392→…）。

### A6｜唯一归属 vs 跨领域笔记

**结论**：跨领域卡（如 Linear Algebra × ML）在主干里必须二选一，v4 没有说明这个「二选一」的争议空间。

**证据**：多重登记 13 篇里已有跨领域实例（如 Principle of Reduction 同时挂在 Mathematical Heuristics 与 Limitation Toolkits）`[复验 2026-10-06]`。

**严重度**：低（写明即可）。

**状态**：v5 并入——doctrine 补一句「归属是登记不是判决，可改可争议；跨领域卡的**第二归属由 Index 承载**」（延伸 D10-P1）。

### A7｜「AI 自动追加成员」与「链接改变意义需 owner 批准」冲突

**结论**：Spec S2 规定提链接须 owner 批准（链接改变笔记意义），v4 的聚簇流程却说主干归属可自动登记——两条规则在同一动作上打架。

**证据**：v4 §4.2 人机分工把「登记主干」划给工具/AI；Collaboration Workflow Spec S2 要求新增链接经 owner 批准。

**严重度**：中。

**状态**：v5 并入——明确例外条款：**登记边（Raw Index → Node）是结构动作，AI 可直接追加；Node↔Node 与 Index→Node 仍是 owner 批准**。

## B 组｜日常使用

### B1｜todo 树成为唯一状态存储，却没有 GC

**结论**：状态单点化把全部维护压力集中到 todo 树；现有工具只查「死引用」，不查「陈年未动」——todo 树会重演 tag 状态漂移。

**证据**：旧体系 129 篇 in-progress 陈年不动（mtime >90 天）`[复验 2026-10-06]`；`a_sticker/todos/archived/` 已有 2 个手工归档的旧 todo 文件——人工 GC 已经在自发发生，说明缺的是机制不是意愿。

**严重度**：高。

**状态**：v5 并入——triage 增加「todo 条目 >90 天未动」报告；S6 每周清理动作并入。

### B2｜材料「拆完没有」无表示

**结论**：材料被拆过与否没有任何状态表示，靠记忆。

**证据**：`archives/material/` 122 篇，v4 无任何字段或链接表示「已拆」；按 v4 原设计需新增状态字段，违反 D3（状态只存一处）。

**严重度**：已裁决（原判中）。

**状态**：已裁决——**出链 = 已拆**：拆过某材料 = 该材料笔记有指向所拆 Node 的出链；rawindex 报告「零出链材料 = 未拆」。零新增状态字段。

### B3｜节律无停摆可见性

**结论**：体系的验收标准「检索回报惊奇」依赖每周聚簇 + 问箱，但同类周期流程 trend-radar 已停摆 9 天无人察觉——周期流程的停摆在本体系里同样不可见。

**证据**：trend-radar 最后原始产物 `TR-raw-D-2026-09-27.md` `[复验 2026-10-06]`，距今 9 天，无任何告警。

**严重度**：高（有前科）。

**状态**：v5 并入——`vault.py status` 顶部加「上次整理 / 上次聚簇 / 上次问箱：距今 N 天」（从 git log 与文件 mtime 推导，零手工记录）。

### B4｜问箱是纯仪式：无记录、无检查

**结论**：「问箱」写了产出判据（补链接），但没有任何东西证明它发生过——不可观测的流程等于没设计。

**证据**：v4 §4 问箱行检查列为「—」；无落盘产物、无检查项。

**严重度**：中。

**状态**：v5 并入——不新增仪式账本；问箱的产出**直接落为 Links 卡**（已有机制），B3 的节律行让「没做」可见。

### B5｜捕获规则 53% 未被执行，新体系没有降低它的成本

**结论**：「当场链 ≥1」是体系的第一规则，实测过半笔记零出链；模板删掉了（少一个决策），但链接的成本本身没变——诚实地说，新体系没有解决旧体系最大的执行缺口。

**证据**：零出链 392/741（52%）`[复验 2026-10-06]`（session 实测 393/53%）。

**严重度**：高（诚实项）。

**状态**：v5 并入——S2 明写「捕获时 AI 必给 3 个候选链接（带 why），你选一个」——把自律变一键；清零需要数周，I3 报告级给增量，不设硬门。

### B6｜主干根 `Raw Index of Everything` 是空壳却是生成树的根

**结论**：主干的根笔记现状正文只有 1 条链接，起不到「入口」作用，且 v4 没有任何机制维护它。

**证据**：迁移后 `library/Raw/Raw Index of Everything` 正文仅 1 条链接（v4 §6 台账）。

**严重度**：低。

**状态**：v5 并入——`rawindex --sync` 自动维护根的成员列表（登记边 = 结构动作，AI 可直接做，D22）。

### B7｜输出回路缺失被 v4 静默接受

**结论**：「理解→产出」没有任何机制，v4 只把它列在缺口表里就不再处理；但这是体系存在的最终理由，静默接受等于把验收标准无限期悬置。

**证据**：zzz_output 仅 2 篇（Root.md、我的底座.md）`[复验 2026-10-06]`，全库 .md 1041 篇（复验口径：除 .git/.obsidian 外全部 .md；session 口径 1037）；Links 卡是理解的产物，但「理解→产出」无机制。

**严重度**：高。

**状态**：**挂账不修**——CRITIQUE 挂账、v5 §8 置顶；**不发明机制**（没有 owner 输入之前写任何机制都是捏造）。
