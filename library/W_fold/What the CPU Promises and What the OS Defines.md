## Definition

**CPU 承诺机制与数据结构的格式；OS 定义内容与政策。** 三项职责（地址、主体权利、例外处理）必然有人承担——承担者叫不叫 OS 不重要，判据是职责不是名字。

> 原句：OS 是一定要被或简单或复杂的实现的。CPU 承诺提供地址的处理机制，但是具体数据结构、基于虚拟地址的进程等概念需要 OS/软件自行按照需求定义。CPU 承诺可以按照设计处理不同主体之间的权利，但是主体的数据结构、划分需要 OS 来实现。CPU 承诺定义各种例外情况，并保证通过中断机制保证让 OS 处理例外，但是处理逻辑要 OS 实现。

## 修正（AI 补边）

- **「数据结构」要分两层**：**硬件定义格式**（PTE、IDT 项、段描述符、陷阱压栈内容），**软件定义内容与上层结构**（页表树、PCB、进程表、地址空间布局）。CPU 不是"提供机制让软件自定义结构"——机制与格式本身就是架构的一部分。
- **CPU 不承诺「主体」**：它只有「当前特权级 + 合法性检查表」。「进程 / 用户」是 OS 造的抽象；CPU 不知道它存在。
- **异常与中断是两类**（内部同步 / 外部异步），但走**同一入口**（陷阱 → 向量表 → 处理程序）。陷阱表：格式在 ISA，内容在 OS。
- **CPU 只承诺保存最小现场**（x86 压 EFLAGS/CS/EIP；RISC-V 写 sepc/scause/stval），**其余现场由 OS 保存**——这是上下文切换成本的来源。
- **「一定要被实现」是功能必然，不是文件必然**：裸机 `main` + 向量表也能承担三项职责，那时它就是一个 OS。
- **顺序**：特权是前提（没有它，页表与陷阱表都保不住）；地址与例外互相咬合（缺页是地址的兜底，也是例外的主要来源）。
- **空白区**：时间与 I/O 上 CPU 承诺弱或不管（TSC 历史上有非单调、跨核不一致；设备走第二套约定）——OS 必须自己造时基。
