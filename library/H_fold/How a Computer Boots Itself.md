## Definition

**自举：机器用一条硬连线约定启动自己（复位矢量），然后把「改写解释规则的权力」逐级移交给软件。**

链路：复位矢量 → POST → MBR 0x7C00 → bootloader 切保护模式 → 建 GDT / 临时 IDT / 页表 → 开分页（+ 进长模式）→ 建最终 IDT → 进内核 → 起第一个进程 → 之后被中断驱动。

> 原句：……内核完成初始化后创建用户进程，然后就退居幕后了（大量的服务都通过中断来实现，包括每个分片时间的进程调度）。

## 三层特殊意义

1. **可见性刚好够加载下一级**：复位矢量只够取一条指令 → 实模式 1MB → 保护模式 4GB 线性 → 分页给任意虚拟地址 → 长模式 64 位。**地址空间的能力是层层攒出来的。**
2. **特权从「无人拥有」到「OS 拥有」= 元层的诞生**：这才是「存储程序」的完整含义——不只是程序存在内存里，而是**连「什么算程序、地址怎么解释」都能被存储的位串改变**。
3. **顺序即安全**：先建合同、后开通道（GDT/IDT/页表先就位才能开中断；开分页那条指令必须先被恒等映射）。自举的失败几乎全是**顺序错**，不是逻辑错。

**合流点**：距离链（ROM → 磁盘 → 内存 → Cache → 寄存器）与能力链（可见性 + 特权）在**第一个用户进程**处合流——两级名字（虚拟/物理）与两级权限（用户/内核）同时就位，OS 退居幕后，只等中断唤醒。

## 修正（AI 补边）

- 主板**不加载** BIOS：固件本就在 ROM/flash 里，主板只是按硬连线约定把 PC 置到复位矢量。
- POST 在找启动设备**之前**。
- 内核早期是**保护模式 + 未开分页**（线性地址 = 物理地址），不是实模式。三态：实模式 → 保护模式（未分页）→ 分页。
- 顺序：建临时 IDT/GDT → 建页表 → 开分页 → 建**最终** IDT。实模式那张叫 **IVT**（0x0000，4 字节/项），保护/长模式那张叫 **IDT**（IDTR 指向，8/16 字节/项）。
- 缺的三条边：**GDT**、**开分页前关中断（CLI）**、**恒等映射（开分页瞬间的鸡与蛋）**。
- 分页不是可选优化：x86_64 长模式要求先开 PAE 分页。

## 边界

- UEFI 把移交前置（固件已给保护模式/长模式/分页），级数变少、本质不变。
- 虚拟机 / 容器没有真复位，第一级约定换成 hypervisor 的 ABI。
- 移交**不彻底**：SMM（固件）与 hypervisor 保留后门特权——是分层的、带保留条款。
