# 树的定义与碎片自动聚合 (研究笔记)

> AI 研究笔记。回答两个问题:① 树该怎么定义(少领域相关、好检索、有内容联系);② Raw Index 类零碎知识如何启发自动聚合流程。末尾是 doctrine 增量提案(需 owner 批准)与 archives/tricks 演示聚类。

## Text

### 一、证据:工作例 vs 反例

- **工作例 `Raw Index of Tricks in Math`**:General → Focused → Structure-based → Strategy 四层;每个聚类节点(Toolkit)带一条**共性陈述**——Function Toolkits 写"单调性,脱去函数后为不等式;中值定理→含未知量的等式;**共性→构造差分结构**"。这条陈述是新知识,不是目录。
- **反例 `archives/tricks/`**:22 篇系统技巧只做了线性链(Trick Install Windows via Libvirt → fix virt-manager → windows can not find disk → …),零聚类节点、零共性陈述、零索引入度。**永远是碎片。**

结论:知识形成不发生在碎片本身,而发生在聚类节点上**陈述共性**的那一刻。

### 二、树定义:四候选评估

| 候选 | 定义 | 裁决 |
|---|---|---|
| A. 主题分类树 | Index of Math/Algebra/Calculus… | 领域相关、「编书」式,拒绝 |
| B. 流程主干 | 状态分区 mailbox→library→zzz_output | 领域无关但一维,只管生命周期 |
| **C. 类型化聚合树** | 边来自闭环思考操作 + 综合层级 | **采用** |
| D. 纯计算生成树 | 从 Root BFS,不作者编辑 | 作**验证**,不作定义 |

**主树 = C 定义,D 验证。**

### 三、树的规则(C)

1. **边类型闭集**(领域无关,因为都是通用思考操作):
   - `⊃ subsumes` 原理 ⊃ 模式 ⊃ 实例
   - `∈ part-of` 工具箱 ⊃ 工具包 ⊃ 碎片
   - `≈ contrasts/bridge` 跨领域对照(结构化联想)
   - 每条边带 link context(已确立的约定)。
2. **综合层级 = Luhmann 三层**:层0 内容(碎片)→ 层1 结构(Toolkit,聚类+共性)→ 层2 主结构(Toolbox/Strategy)。层级与领域无关。
3. **聚类节点必须陈述共性**:没有共性陈述的聚类是目录,不是知识节点(工作例的 Function Toolkits 正面示范)。
4. **树是 raw 的**:聚类临时、可重排;根 = Raw Index(入口,原语已定:「不确定性落到 Raw Index」)。
5. **领域无关的检验**:同样的规则必须能直接长在零碎领域上(archives/tricks)而不需要新规则。
6. 检索 = 层级 + 边类型 + 标签/图/搜索;连接 = 边必须带 why(不是任意边)。

### 四、自动聚合流程(碎片 → 知识,五步,热/冷分离)

1. **热捕获(碎片)** — 零结构负担:模板建卡 + 一条出链(模板已改:「链至少一个旧笔记,写一句为什么」)。
2. **自动落桶** — 新碎片按 tag/惯例挂进归属 Raw Index,不分类(捕获时刻零决策)。
3. **冷聚类(AI 提议,owner 定稿)** — 批量扫描 Raw Index 下碎片,**按共同模式聚类(不是主题)**:AI 提簇 + 每簇一条共性草稿;owner 用自己的话定稿 → Toolkit 节点。
4. **复用检测 → 升层** — 某 Toolkit 模式在第二个领域复用 → 提炼为 Principle/Heuristic 卡(层3),碎片降为实例(`⊃` 边)。知识形成 = 碎片→模式→原理。
5. **沉降** — 模式已升层的 Toolkit 归档;Raw Index 保持 raw。

**自动化在哪**:捕获出链(模板,已做)、落桶(triage 机制)、聚类提议(AI 批量,human-in-the-loop)、跨域复用检测(AI)。人只做两件事:确认簇 + 用自己的话写共性——与提炼后的核一致(人脑只做思考)。

### 五、Doctrine 增量提案(需 owner 批准)

1. **Vault System Design** 增一节「树的定义」:主树 = 类型化聚合树,四条规则(边闭集、三层、共性陈述、raw),D 验证连通性。
2. **Spec S3** 增第四步:体系摄入时,各自助碎片按模式聚类为 Toolkit 节点(共性由 owner 定稿),而非只挂进 Index 的 Core Concepts。

### 六、演示聚类:archives/tricks(AI 提议,owner 定稿)

可从现有链/heuristic 读出的簇(每簇共性为草稿):

- **簇 A Windows 驱动管道**:VirtIO FS / install virtio nic driver / WinFsp / installing all virtio driver / Windows ISO Fall back → 共性:「驱动与组件安装有严格顺序,后面的失败常源于前面缺一步」。
- **簇 B 虚拟化启动链**:Install Windows via Libvirt / fix can not open virt-manager / windows can not find disk or NIC / Can not Find ISO / qemu → 共性:「启动失败按 组件→驱动→镜像 三层排查」。
- **簇 C Wayland/桌面服务**:keep hyprland and wayland plasma / Solve confliction swaync and KDE D-bus → 共性:「桌面组件冲突根因常在会话服务层(D-bus)」。
- **簇 D 跨文件系统**:mount ntfs / UMU set up → 共性:「跨文件系统兼容 = 挂载语义 + 符号链接」。

四簇共性 = 四条 method/principle 卡候选;批准后 omp 建 `Raw Index of Tricks (System)` 聚类骨架,owner 定稿共性。
