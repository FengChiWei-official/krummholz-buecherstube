# 减负式联想学习:理念整合与微调方案 (AI 提案)

> AI 提案。理念整合部分请消化后用自己的话写入 [[减负式联想学习]];微调方案 M1–M8 每一项都需要 owner 批准后才执行。

## Text

### 一、理念整合(博采众长,命名为「减负式联想学习」)

7 个命题:

1. **人脑只做两件事**:产生自己的知识(own voice)与联想(链接)。其余全部外包。
2. **结构涌现而非预设**:知识从底向上自然生长;链接定义意义;任何预设分类都是「提前几十年锁死目录」。
3. **树是生成树,不是真相**:树状结构(主树)只是链接图的一棵生成树投影,服务于检索;随时可以重新投影。
4. **惊奇是产出信号**:系统必须能反过来让你吃惊(沟通伙伴);问箱是刻意练习惊奇的方式。
5. **检索练习是底座**:连接需要记忆做基材;规则与核心概念用间隔重复对抗遗忘(采信 Scott Young 2023 修订)。
6. **复杂度守恒**:人类省掉的每一分结构负担必须有一个明确承载体(AI/工具/模板/惯例),否则负担只是换了地方。
7. **状态驱动而非分类驱动**:热捕获、冷整理;放置决定从「每篇笔记当时」移到「批量冷静时」。

### 二、核心理念 → 现有体系的映射(结论:规约 = 微调,不是重构)

| 理念元素 | 现有实现 | 缺口 |
|---|---|---|
| 减少非思维负担 | 状态分区 + 算法层 + hot/cool 分离 | 缺「最小记忆集」提词卡 (M6) |
| 图状网络 | wikilinks + backlinks + 径向捕捉 | 缺语义补链工具(可选,M-tools) |
| 跨域联想 | S3 强制 cross-topic 链接规则 | 有规则无工具强制 (M4) |
| 底向上生成 | 捕获→链接→promote;拒绝主题文件夹 | 无(已实现) |
| 树=生成树 | 主树 Root→Raw Index→topic Index | 缺连通性验证(可选工具) |
| AI 维护结构 | vault.py check/triage/promote/status + S1–S7 | 缺「问箱」场景 S8 (M2) |
| 链接带理由 | Links 笔记惯例 | 未成硬约定 (M3) |
| 记忆底座 | 无 | 完全缺失 (M7) |

### 三、微调方案 M1–M8(全部待 owner 批准)

- **M1 理念卡片**:owner 写 principle 卡「减负式联想学习」(骨架已建:`mailbox/减负式联想学习.md`),promote 后挂进主树 System 分支。
- **M2 问箱仪式 (S8)**:新增协作场景——owner 提出一个异构问题,omp 用 grep + 标签 + backlink 激活网络,报告惊奇连接(不写正文)。写入 `Collaboration Workflow Spec`。
- **M3 链接上下文约定**:S2 提链接与 owner 插链接时,每条带一句 why(仿 Luhmann link context)。写入 Spec 与 Links 模板。
- **M4 cross-topic 检查进 vault.py**:`check` 增加 informational 项——已 promote 的体系化笔记若无跨 Index 链接则列出(现有规则 S3 的工具化)。补丁 ~30 行。
- **M5 孤儿接驳**:当前 24 篇孤儿(all-zero-link)按主题挂进最近 Index。机械但链接改变意义 → 清单给 owner 逐条批准。
- **M6 最小记忆集**:README/提词卡压成 3 条:「① 写笔记、链一个旧笔记;② 中断就挂 todo;③ 不会就问 AI(status)」。其余规则永远不用记。
- **M7 间隔重复**:Anki 或 Obsidian 插件,先只喂「规则卡 + 核心概念卡」。对抗规则遗忘,直接服务疾病场景。per-machine 配置(.obsidian 已 gitignore)。
- **M8 捕获降摩擦**:QuickAdd/Daily Note 模板一键建卡(预填 tag 闭集)。per-machine。

### 四、运维门槛设计(疾病适配):记忆从人脑迁到三层外部

原则:**人只需要记住一条行为——「不会就问 AI」。** 其余规则存放在:

1. **AI 记忆层**:AGENTS.md + vault-ops 技能(载入顺序固定)。任何 vault 操作自动触发技能,AI 自带规则。
2. **强制记忆层**:vault.py(不变量硬校验)+ templates(预填 tag 闭集,建卡即合规)。
3. **检索记忆层**:README + todo 树(续写说明 = 重入点)+ 主树索引。

四个降低门槛的机制(已存在,用起来即可):

- **会话入口状态机**:`status` → 状态 + 编号选项,零记忆进入。
- **决策批处理**:热的放置决定移到冷静时批量做(triage)。
- **防丢**:S5 快存 + todo 续写说明;无 todo 条目不丢工作。
- **信号不裁决**:工具输出只是信号,内容优先;不会误伤。

### 五、工具采纳路线(按需渐进,全本地开源)

1. 先装 **Dataview**(纯读仪表盘:分区统计/孤儿/标签卫生)——零风险。
2. 需要显式主树时加 **Breadcrumbs**;需要验证生成树连通性/找桥梁笔记时加 **Graph Analysis**。
3. 想要「相似但未链接」的自动推荐时上 **Ollama + Smart Composer**(MIT)离线 embedding。
4. 定期离线跑一次主题建模(脚本 + tomotopy/BERTopic + topic-wizard)做惊奇发生器与标签卫生。
5. 一次性文本→KG 实验可用 **Microsoft GraphRAG**(MIT);vault 内日常图分析用自写 ~50 行 NetworkX 脚本即可。
