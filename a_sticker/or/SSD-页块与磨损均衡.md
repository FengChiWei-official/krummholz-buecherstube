# SSD：页、块与磨损均衡（概念辨析）

> **原材料（or/）**：用户列出的辨析点（SSD 页 vs 内存交换页、块 = 擦除单位、芯片层级、静态/动态磨损均衡）＋ 计组 ch3「五、外部存储器（SSD）」与 OS 外存管理的教材口径。**辨析稿**：只解释概念错位，不押题。
> 一句话：**SSD 的混乱全来自三级单位不重合**——读/写按页、擦除按块、报废按 P/E 次数；而「页」这个词刚好和虚存页同大小，纯属撞巧。

## 0. 单位阶梯

| 层 | 典型值 | 由谁定 | 能做的操作 |
|---|---|---|---|
| **页 page** | 4 KB（NAND 常见 4–16 KB） | 闪存器件 | **读、写（编程）**——写只能整页、且只能写一次 |
| **块 block** | 128 页 = 512 KB | 闪存器件 | **擦除**——只能整块擦，擦后才可重写 |
| plane | 数百～数千块 | 器件组织 | — |
| die（晶粒） | 多个 plane | 封装 | 可并行操作 |
| **芯片 chip（封装）** | 多个 die | 封装 | 对外是一个器件 |

408 只需前两级；「芯片」这一级只在算「一块盘有多少 die／多少并行通道」时出现。**三级单位不重合**（页 < 块 < 芯片）是后面所有复杂性的唯一根源。

## 1. 两个「页」：大小撞巧，机制无关

| 维度 | 虚存页 | SSD 页 |
|---|---|---|
| 大小 | 4 KB（**OS 定**，可改） | 4 KB（**器件定**，不可改） |
| 操作粒度 | 读、写、换入换出都是整页 | **读/写 = 页；擦除 = 块**（粒度不一致！） |
| 谁在管 | OS + MMU | FTL（闪存转换层）+ GC |
| 映射表 | 页表：VPN → PPN | FTL 表：LBA → 物理页号 |
| 修改方式 | 写回原页（脏页原地更新） | **不能原地改写**：写新页、旧页标记失效 |
| 失效/替换 | 页置换算法（LRU/Clock） | 磨损均衡 + 垃圾回收（GC） |

两句话收口：

1. **两个「页」不是一回事**，只是都取 4 KB。虚存页是「交换单位」，SSD 页是「编程单位」；题目让你「按页算」时必须问清是哪一层的页。
2. **真正同构的是「映射表 + 有效位」**：FTL 与页表都是「编号 → 物理位置」的表，都靠有效位淘汰；差别只在**能不能原地改**——能，就是页表；不能，就必须 FTL + GC（见 [[编址技术-编号空间与译层]] §4：这一层之所以必须存在，是因为它承担了「异地写」的转换）。

## 2. 为什么不能原地改写

NAND 的编程只能把位从 1 写成 0，擦除才能回到 1，而擦除单位是整块。于是「改一个字节」实际是：

```
写 4 KB 新页 → 旧页标记失效（有效位=0）→ 块里留下垃圾
   ↓ 垃圾攒够
GC：选一个"垃圾最多"的块 → 把其中仍有效的页搬到新块 → 擦除整块
```

由此得到两个必背量：

$$\text{写放大 } WA=\frac{\text{主机写入}+\text{GC 搬移写入}}{\text{主机写入}}$$

$$\text{可写总量 }=\frac{\text{容量}\times \text{P/E 次数}}{WA}$$

算例：256 GB、P/E $=3000$、$WA=2.5$ → 可写 $\approx307$ TB。

## 3. 磨损均衡：动态 vs 静态（**你括号里的名字对调了**）

教材口径：

| | **动态**磨损均衡 | **静态**磨损均衡 |
|---|---|---|
| 何时决策 | **写入时**：新数据要落块，在**空闲块**里选擦除次数最少的 | 后台额外动作：把**长期不改写的冷数据**搬走 |
| 覆盖对象 | 只有「正在写」的数据 | 「热的 + 冷的」全都算 |
| 具体动作 | 写时挑低磨损块 | 把冷数据从低磨损块迁到**磨损较高**的块，腾出低磨损块给热写 |
| 代价 | 几乎为零 | 额外搬移 + 写放大 |
| 失效场景 | 冷数据长期占着低擦除块 → 那些块永远"很新"，而热块先坏 | 基本覆盖全部块 |

记法（名字的由来，也是最不容易记反的方式）：**动态只动「动」的数据；静态连「静」的数据也动。** 所以「写入时决策」是动态，「冷块迁移」是静态——你原来的标注把两者对调了。

两个策略不是二选一：商用控制器同时做动态（平时选块）和静态（空闲时搬冷数据）。

## 4. 四个易混

| 别混 | 判据 |
|---|---|
| **GC ≠ 磨损均衡** | GC 解决**空间**（回收垃圾块）；磨损均衡解决**寿命**（摊平擦除次数）。两者共用「搬页」动作，目的不同 |
| **P/E 次数 ≠ 擦除次数** | P/E 是**规格上限**（SLC ~10 万、MLC ~3 千、TLC ~1 千）；擦除次数是**实际计数**，均衡的目标是让它均匀地逼近上限 |
| **TRIM ≠ 擦除** | TRIM 只是 OS 告诉器件「这些 LBA 已无用」（让 GC 提前知道哪些页是垃圾）；真正的擦除仍由 GC 在块级完成 |
| **SSD 页 ≠ 扇区** | 扇区是磁盘的最小物理单位（512 B / 4 KB，也是 LBA 单位）；SSD 页是编程单位。块设备层看到的是 LBA，看不到 SSD 页 |

## 5. 一次写入经过的四个编号空间

| 层 | 编号 | 译层 | 单位 |
|---|---|---|---|
| 文件 | 逻辑块号 + 块内偏移 | inode / 位图 | FS 块 |
| 块设备 | LBA | — | 扇区（512 B / 4 KB） |
| FTL | 逻辑页 → 物理页 | FTL 映射表 | SSD 页（4 KB） |
| 闪存阵列 | 物理页 / 块 / die | 器件译码 + 通道并行 | 页 / 块 |

这一次链把三件事串起来：**写放大发生在 FTL 层**（4 KB 主机写可能触发整块搬移）、**并行度发生在 die/通道层**（多 die 可并行 → 顺序写快）、**延迟抖动发生在 GC 层**（GC 抢占时延）。SSD 的性能题一般问的是这三层的哪一层。
