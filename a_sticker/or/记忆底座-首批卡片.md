## A 组 · 规则卡

> AI 生成，内容是 doctrine 的既有事实（不是新知识）。语法为插件单行式 `问::答`。

三条硬门是哪三条？::①G1 root 排空（只允许 `README.md` / `AGENTS.md` 常驻）；②G2 `archives/material/` 每篇有真实 `source:`；③G3 无新增悬空 wikilink。（源：`AGENTS.md` §Invariants）

硬门失败时工具怎么做？::`check` 返回 exit 1，阻断提交。（源：`AGENTS.md` §Invariants；`tools/vaultkit/cli.py` cmd_check）

报告级判据有哪些？::I1a 未登记；I1b 重复登记边；I1c Raw Index 环；I2 Links 跨区域（同区域=违规，无区域=提示）；I3 Node ≥1 出链；I4 doctrine 与 Raw 不做绑定邻居；I5 `## Mapping`；I6 `## 实例化`；I7 学科 Index `## 时间轴`；I8 挂点覆盖率；I9 未记录 source；D21 未拆材料。（源：`doctrine/Vault Design.md` §判据两级制；`tools/vaultkit/rules.py`）

报告级判据失败时工具怎么做？::只给每周增量数字，永不阻断。（源：`doctrine/Vault Design.md` §判据两级制）

为什么报告级判据不做成硬门？::会重演旧体系的死因——上线即 674 篇未登记、392 篇零出链，门常红就没人看，门随即失效。（源：`doctrine/Vault Design.md` §为什么这套不会重演旧死因；`archives/work/CRITIQUE.md` A5）

新笔记该放哪个分区？::外部材料→`archives/material/`；自己的档案与 AI 报告→`archives/work/`；稳定的自有知识→`library/`；草稿→根（入口队列，由 `triage` 排空）。（源：`AGENTS.md` §Hard rules 2）

体裁由什么决定？::名字（> 路径 > tag）。`Raw Index*`→`library/Raw/`；`Index of*`→`library/Index/`；`Links of*`→`library/Links/`；其余→`<A–Z>_fold`（数字头与 CJK 各有自己的 fold——名字在 `tools/vault.toml [zones]`）。（源：`AGENTS.md` §Hard rules 4）

登记边（Raw Index → Node）与语义边（Node↔Node、Index→Node）的权限差别是什么？::登记边是结构动作，AI 可直接追加；语义边改变笔记意义，须 owner 批准。（源：`doctrine/Vault Design.md` §关键 doctrine D22）

未完成的活记在哪里？::只在 todo 树（`a_sticker/todos/`）：一条 `- [ ] [[NAME]]` 挂钩 + 5–10 词续写说明。没有续写说明的 todo 条目是不允许的。（源：`AGENTS.md` §Hard rules 5）

笔记保留哪些 frontmatter 字段？::只有 `aliases:`（wikilink 解析依赖）与 `source:`（material 的硬门）。已退役：`tags` / `created` / `date` / `data-date`，以及 `status/*` `topic/*` `attr/*` 标签。（源：`doctrine/Vault Design.md` §字段）

wikilink 按什么解析？::按笔记名，不按路径（`aliases` 参与解析）。改名须先 `grep -rn '\[\[Old Name'`，并更新每一种写法（含 `|alias` 与路径式）。（源：`AGENTS.md` §Hard rules 1）

「出链 = 已拆」是什么意思？::一篇材料被拆过的标记，就是它有指向所拆 Node 的出链；零出链材料 = 未拆。零新增状态字段。（源：`doctrine/Vault Design.md` §关键 doctrine D21）

捕获一篇新笔记时，除了写下内容还必须做什么？::当场链接 ≥1 篇旧笔记，并写一句 why（为什么连）。AI 给 3 个候选链接，owner 选一个。（源：`README.md` §最小记忆集；`doctrine/Vault Workflow.md` S2）

三个动词加一个循环分别是什么？::捕获（学完即做）、整理（每周，`triage`）、聚簇（每周，`rawindex --clusters`）；加上问箱（每周或卡壳时）。（源：`doctrine/Vault Workflow.md` §三个动词）

AI 能写什么、不能写什么？::能写：问题、结构、骨架、检查、链接候选。不能写：own-voice 正文（永远是人写）。AI 生成的散文只进 `a_sticker/or/`，绝不直接进 `library/`。（源：`doctrine/Vault Workflow.md` §AI 边界）

删除、改名、提交这三件事的权限？::删除与改名须 owner 签字；提交（commit / push）除非 owner 要求，否则不做。（源：`AGENTS.md` §Hard rules 8）

主干是树还是 DAG？::DAG——登记是边不是父：每个 Node ≥1 条登记边；同一 (Raw Index, Node) 对不得重复；多重登记合法；`Raw Index → Raw Index` 子图无环（I1a/I1b/I1c）。（源：`doctrine/Vault Design.md` §两棵树；D37）

改了 doctrine，要一起改哪些文件？::见 `doctrine/Vault Extension.md` §同步面——README 工具节 / AGENTS Invariants / Agent Contract §6 / Vault Design §判据两级制 / cli.py 的 check 头行与 help 文案 / 本文件的规则卡。（源：`doctrine/Vault Extension.md` §同步面）

## B 组 · 概念卡骨架（答案由你写）

> 按 S1 边界：**AI 只给问题与骨架，正文永远是你写。** 先把答案写出来，再转成卡片语法。
> 这六题覆盖 §4 的四条机制，加两条系统自身的验收前提。

1. **类比** — 什么条件下「A ≈ B」是一个真映射，什么条件下只是表面相似？你的判据是什么？
2. **不变量** — 一个模式要满足什么，才算「不变量」，而不是「同一件事的重复描述」？
3. **引入时间** — 一个学科「为什么需要它」（目的）如何解释它「用什么方法」？举一个你亲自验证过的例子。
4. **地图册** — 整体层与局部块之间的「桥」，判据是什么？什么样的桥是假的？
5. **复杂度守恒** — 你省下的结构负担由谁承载？换过承载体之后，负担真的消失了吗？
6. **验收标准** — 为什么「检索时能否回报惊奇」是可检验的，而「我理解了」不是？
