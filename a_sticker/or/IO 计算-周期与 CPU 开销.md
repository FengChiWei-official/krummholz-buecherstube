# IO 计算：周期、CPU 开销与「为什么不加处理时间」

> 暂存稿（`a_sticker/or/`）。用途：给 [[IO 方式-条件与状态转移]] 补上它刻意留白的「数值计算」部分——三种方式共用一套量，差别只在**周期是谁的节拍**。
> 状态：**只讲不写**。记号：设备速率 $R$（B/s）、每次传送单位 $n$（B，即缓冲区/数据寄存器大小）、一次服务时间 $t$（CPU 侧）、总数据量 $M$（B）。

## 〇 结论先行

1. **周期是事件的间隔，不是「事件 + 响应」**。中断方式下事件由设备产生，节奏是 $T=n/R$；CPU 处理只占这个周期里的一段，**不相加**。
2. **加法的含义是串行**：把周期写成 $T+t$，等于假设「设备等 CPU 处理完才开始填下一单位」。408 的默认模型里设备不停，所以只算 $T$。
3. **判据一句话：下一事件的产生是否被本次处理阻塞？** 被阻塞（停等 ARQ）就加；并行（中断 I/O、DMA）就不加。
4. **边界**：当 $t\ge T$ 时 CPU 成为瓶颈，设备被迫等待，有效周期变成 $\max(T,t)$——这是「不加」公式的失效条件，也是中断只适合低速设备的原因。

## 一 三个量

$$T_{\text{fill}}=\frac{n}{R}\ \text{(设备账本)},\qquad t\ \text{(CPU 账本)},\qquad U=\frac{t}{T_{\text{fill}}}\ \text{(占用率)}$$

- $T_{\text{fill}}$：设备填满一个传输单位的时间，由设备速率决定，CPU 做什么都不影响它。
- $t$：一次中断响应 + 服务（或一次查询 + 搬运）的 CPU 时间。
- $U$：CPU 花在 I/O 上的时间比例。**分子分母不能混**：分子是 CPU 的时间，分母是设备的节拍。

这与 [[IO 方式-条件与状态转移]] 的判据同源：*设备慢、CPU 快，差值记在谁账上*。中断方式里设备不等 CPU，所以**两本账并行记，不相加**。

## 二 三种方式的公式

| 方式 | 事件 | 周期 | 事件次数 | CPU 时间 | CPU 占用率 |
|---|---|---|---|---|---|
| 程序查询 | 无事件，CPU 主动读状态 | 轮询间隔 | 总时间 / 间隔 | ≈ 总时间（全程忙等） | ≈ 100% |
| 程序中断 | 缓冲区满 / 一个单位完成 | $T=n/R$ | $M/n$ | $\dfrac{M}{n}\,t$ | $\dfrac{t}{n/R}=\dfrac{tR}{n}$ |
| DMA | 一个数据块完成 | $T_{\text{blk}}=n_{\text{blk}}/R$ | $M/n_{\text{blk}}$ | 次数 ×（预置 + 完成中断） | $\dfrac{t_{\text{init}}+t_{\text{int}}}{T_{\text{blk}}}$ |
| 通道 | 一组块完成 | $T_{\text{grp}}$ | $M/$组大小 | 每次只发通道指令 | ≈ 0 |

总时间（设备与 CPU 并行时）：

$$T_{\text{total}}=\max\left(\frac{M}{R},\ \frac{M}{n}\,t\right)$$

前一项是设备受限，后一项是 CPU 受限。**取 max 而不是相加**，这正是「周期不加处理时间」在总量层的体现。

## 三 为什么周期是 $T_{\text{fill}}$，不是 $T_{\text{fill}}+t$

### 3.1 事件产生端与处理端是解耦的

中断是设备发出的「缓冲区满了」通知。设备填满第 $k$ 个单位后立刻开始填第 $k+1$ 个（接口有数据寄存器，或双缓冲），所以第 $k+1$ 个事件在上一个事件之后恰好 $n/R$ 到来——**与 CPU 用了 10 µs 还是 10 ms 处理无关**。

$$t_1,\ t_2,\ t_3,\dots \quad\text{间隔恒为 } T=n/R$$

CPU 的处理落在这些间隔**内部**，它决定「这个周期里 CPU 被占用了多少」，不决定「下一个周期何时到来」。

### 3.2 加法的物理含义是设备停下来等

把周期写成 $T+t$，等于声明：设备发出中断后**停止填充**，等 CPU 取走数据才继续。这只在两种情况下成立：

- 单缓冲且设备没有本地缓冲（数据必须被读走才能覆盖）；
- 题面明说「CPU 处理期间设备暂停」。

408 的中断方式默认设备与 CPU 并行工作，所以不采用这个模型。

### 3.3 判据可以移植到别的章节

同一套「加不加」，取决于**下一事件的产生是否被当前处理阻塞**：

| 场景 | 下一事件依赖上一次处理？ | 周期 |
|---|---|---|
| 停等 ARQ | 是：不发下一帧，必须等 ACK 回来 | $t_s+RTT+t_{ack}$（**加**） |
| 中断 I/O | 否：设备自己继续填 | $T_{\text{fill}}$（**不加**） |
| DMA | 否：控制器自己搬下一块 | $T_{\text{blk}}$（**不加**） |
| 流水线 | 否：下一指令在下一拍进入 | 一个时钟周期（**不加**） |

这就是为什么 [[网络性能指标-带宽吞吐利用率与ARQ公式]] 里的 $1+2a$ 要加 RTT，而这里不加——不是公式风格不同，是**阻塞关系不同**。

### 3.4 失效边界：$t\ge T_{\text{fill}}$

若 CPU 处理一个单位的时间超过设备填一个单位的时间，设备填满后只能等待（或数据被覆盖、中断丢失）。此时：

$$T_{\text{eff}}=\max\left(T_{\text{fill}},\ t\right),\qquad \text{吞吐}=\frac{n}{T_{\text{eff}}}$$

CPU 占用 100%，吞吐由 CPU 决定。**所以「周期不加处理时间」的隐含前提是 $t<T_{\text{fill}}$**；跨过这条线，公式必须换成 max。

## 四 一套参数走到底

$R=1$ MB/s、$n=1$ KB、$t=50\ \mu s$、$M=100$ MB。

| 量 | 计算 | 结果 |
|---|---|---|
| 周期 | $1024/10^6$ | $1.024$ ms |
| 事件次数 | $100\times10^6/1024$ | $97\,656$ 次 |
| CPU 时间（中断） | $97656\times50\ \mu s$ | $4.88$ s |
| 总时间 | $100\ \text{MB}/1\ \text{MB/s}$ | $100$ s |
| 占用率 | $50\ \mu s/1.024$ ms | $4.88\%$ |

对照三种方式（同样参数、同样的设备）：

| 方式 | CPU 时间 | 占用率 | 说明 |
|---|---|---|---|
| 查询 | 100 s | 100% | 全程忙等 |
| 中断（每 1 KB） | 4.88 s | 4.88% | 每单位一次中断 |
| DMA（每 4 KB） | $24414\times50\ \mu s=1.22$ s | 1.22% | 每块一次中断 |

**同一台设备、同一份数据，CPU 开销只取决于「单位多大」和「谁来搬」**：单位越大、介入层级越深，次数越少。

若改 $t=1.5$ ms（> 周期 1.024 ms）：CPU 成为瓶颈，$T_{\text{eff}}=1.5$ ms，总时间 $=97656\times1.5\ \text{ms}=146$ s，吞吐降到 $0.68$ MB/s，占用率 100%。

## 五 常见错法

1. **周期加处理时间**：在 $t\ll T$ 时只差几个百分点，抄错也「算对」；一旦 $t$ 接近 $T$ 就全错，且看不出错。
2. **把 CPU 时间当总时间**：中断方式下总时间由设备决定，CPU 时间只是其中一小段。
3. **混淆「传送单位」与「缓冲区大小」**：中断次数按每次中断传送量算，不是按内存里那块缓冲区的总大小算。
4. **DMA 只算一次中断**：中断次数按**块数**，不是按字节数，也不是一次。
5. **查询方式用中断公式**：查询没有「事件」，CPU 时间是全程，不是次数 × 服务时间。
6. **单位混算**：$R$ 用 MB/s、$n$ 用 KB、$t$ 用 ms，最后占用率差 $10^3$ 倍。统一到 B 与 s。

## 六 练习

**1.** $R=2$ MB/s、$n=2$ KB、$t=20\ \mu s$。求周期与 CPU 占用率。

**2.** 上题要求占用率 $\le1\%$，$t$ 最大可取多少？

**3.** $T_{\text{fill}}=1$ ms、$t=1.2$ ms。求实际吞吐（$n=1$ KB 时）与 CPU 占用率。

**4.** $M=10$ MB、$R=1$ MB/s、$n=1$ KB、$t=50\ \mu s$。求总时间与 CPU 时间。

**5.** DMA 方式，块 $8$ KB、$R=2$ MB/s、每块完成中断 $100\ \mu s$。求占用率。

### 答案

**1.** $T=2048/2\times10^6=1.024$ ms；$U=20\ \mu s/1.024\ \text{ms}\approx1.95\%$。

**2.** $t\le1\%\times1.024\ \text{ms}=10.24\ \mu s$。

**3.** CPU 瓶颈：$T_{\text{eff}}=1.2$ ms，吞吐 $=1\ \text{KB}/1.2\ \text{ms}\approx0.833$ MB/s；占用率 100%。

**4.** 总时间 $=10$ s；CPU $=\lceil10^7/1024\rceil\times50\ \mu s\approx9766\times50\ \mu s\approx0.49$ s（4.9%）。

**5.** $T_{\text{blk}}=8192/2\times10^6=4.096$ ms；$U\approx100/4096=2.44\%$。
