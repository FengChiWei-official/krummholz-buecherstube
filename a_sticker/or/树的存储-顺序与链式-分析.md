## 0 一句话

**顺序存储 = 关系藏在编号里；链式存储 = 关系藏在指针里。** 判据只有一条：树的形状能不能由下标反算出来。能（完全二叉树、满二叉树、堆、线段树这类静态完全形），边就不必存，省掉全部指针；不能（一般二叉树、一般树、动态插删），边必须显式写在指针或父下标上。

## 1 顺序存储

### 1.1 形式

一组连续单元，按**完全二叉树的层序编号**落位；非完全二叉树补空位补成完全形再编。

### 1.2 关系由下标算出（教材口径）

| 根编号 | 左孩子 | 右孩子 | 父 |
|---|---|---|---|
| 从 1 起 | $2i$ | $2i+1$ | $\lfloor i/2 \rfloor$ |
| 从 0 起 | $2i+1$ | $2i+2$ | $\lfloor (i-1)/2 \rfloor$ |

两套式子没有谁更对，**帧不同**（0-based / 1-based）；库里 index 簇已把这件事讲成「位置 vs 距离」的问题，见 [[index 运算规范化-参考资料卡]]、[[Index Frame]]、[[0-index]]、[[1-index]]。

**408 的帧由题面给。** 2022·41 题面原文：「位置从下标 0 起，父 $i$ 的左孩子在 $2i+1$、右孩子在 $2i+2$」，不存在的结点用 `-1` 表示（[真题原文](https://www.codebrick.tech/exam-408/q/ds/2022/41.html)）。教材叙述反过来用 1 起、0 号单元闲置。所以**没有「必须从 1 开始」的题**：`-1` 哨兵与 0 起是一套，`0` 号闲置与 1 起是一套；题面给帧就按题面，题面不给才用教材默认。

### 1.3 代价

- 得：随机访问任意节点 $O(1)$、零指针、缓存友好；找父找子都是算式，不用遍历。
- 失：一般二叉树要补空到满形，空间随「最深一层的位置」而非节点数涨；结构一改（插删）就要搬元素；树的深度决定数组长度。
- 补到哪：也可以只补到最后一个非空位置——2022·41 的 $T_1$ 只占 10 个元素（4 层满形要 15 个），靠 `ElemNum` 与 `-1` 共同界定有效范围。
- 退化：一条单链形态的树（每层只有左孩子）在顺序存储里占 $2^h$ 个位置，而实际只有 $h$ 个节点。

### 1.4 默认与可选

- **默认用顺序存储的场合**：完全二叉树及其特化——[[Heap]]、[[Segment Tree]]、静态的完全形结构。
- **可选项**：补空策略（补到满形 vs 只补到最后一层最右节点，后者省空间但要额外的「是否存在」标记）。

## 2 链式存储

### 2.1 二叉树

| 结构 | 字段 | 拿到什么 |
|---|---|---|
| 二叉链表 | `lchild` / `data` / `rchild` | 子 $O(1)$，父 $O(n)$ |
| 三叉链表 | 二叉链表 $+$ `parent` | 父也 $O(1)$，代价是多一个指针 |

408 教材的默认是**二叉链表**；需要沿父方向上走（如 [[Lowest Common Ancestor]] 的倍增、[[Disjoint Set Union]] 的路径压缩）时，才把 parent 显式存下来。

### 2.2 一般树 / 森林（教材口径的三种表示法）

| 表示法 | 存什么 | 强在哪 | 弱在哪 |
|---|---|---|---|
| 双亲表示法 | 顺序表，每项存 `data` + 父的下标 | 找父 $O(1)$，结构稳定 | 找子要扫全表 $O(n)$ |
| 孩子表示法 | 顺序表 $+$ 每个节点的孩子单链表 | 找子 $O(1)$ | 找父要扫；孩子多时指针多 |
| 孩子兄弟表示法 | 二叉链表：左 = 第一个孩子，右 = 下一个兄弟 | 任意树/森林 ↔ 二叉树，零额外结构 | 父子与兄弟共用两个指针位，语义要记牢 |

第三条正是 [[Edgings Point of Trees]] 里「有序树可以用二叉树模拟」的机制，也是 [[标准错误答案清单]] 那条错答（「左孩子右兄弟变成左孩子右孩子」）的正面表述。森林转换时，根的兄弟指针连成一条链——树与森林共用一套转换。

### 2.3 库内已有的两个心智模型（正好对应两种链式面）

[[Tree Mental Models]] / [[Links of Properties of Trees]]：

- **棒棒糖模型（Lollipop）**：除根外每节点恰有一条**入边**，$E=V-1$——这就是双亲表示法 / parent 指针那一面，适合「往上问」。
- **八爪鱼模型（Octopus）**：节点自己管一群**出边**，$Tree = Node + List<Tree>$——这就是孩子 / 孩子兄弟那一面，适合「往下走」（DFS/BFS）。

一句话：**链式存储选哪面，取决于你主要往哪个方向走。**

## 3 选择表（顺序 vs 链式）

| 维度 | 顺序存储 | 链式存储 |
|---|---|---|
| 找父 | 算式 $O(1)$ | 二叉链表 $O(n)$；三叉/双亲 $O(1)$ |
| 找子 | 算式 $O(1)$ | `lchild`/`rchild` $O(1)$ |
| 第 $k$ 个节点 | $O(1)$ | $O(n)$ |
| 插删改形 | 搬元素 $O(n)$ | 改指针 $O(1)$ |
| 空间 | 按深度补空 | 按节点数个指针 |
| 适合的树形 | 完全形、静态 | 一般树、动态、需要父方向 |

与线性表那张表同构：[[Sequential List vs. Linked List]]、[[Links of How to Choose the Implementation of Linear List]]。区别只在**树多了一维「方向」**——链式存储还得选往父走还是往子走。
