# Cache · TLB · 页替换：同构与分界

> **原材料（or/）**：按 [[计算机组成考纲#第三章 存储系统]]「六、Cache（映射·替换·写策略）」「七、虚拟存储器（页表·地址转换·TLB）」与 [[操作系统考纲#第三章 内存管理]]「二、虚拟内存管理（页框分配·页置换算法）」整理。本篇只做**对照**：单点机制见 [[程序的三个身体-磁盘-虚拟内存-物理内存]]（地址翻译、缺页、页框），单点易错见 [[标准错误答案清单]] §三章。
> 一句话：三张表查的不是同一种东西，但共用「映射—替换—写回」三件套；分界只有四个数——粒度、候选集、代价、谁在处理 miss。

## 0. 三张表的分工

| 结构 | 缓存什么 | 粒度 | 命中省下什么 | miss 谁处理 | 量级 |
|---|---|---|---|---|---|
| Cache | 主存里的**数据块** | 64 B 块 | 一次访存（~100 周期） | 硬件（控制器），对指令透明 | 命中 ≈ 1–4 周期 |
| TLB | **页表项**（翻译结果） | 一项 = 一页 | 1～k 次页表访存 | 硬件；软件管理 TLB 的机器则陷入 | 命中 ≈ 1 周期 |
| 页表 | **全部映射**（不是缓存，是存档） | 一项 = 一页 | — | 缺页 → OS 陷入 | 缺页 ≈ $10^5$–$10^6$ 周期 |

**串联，不是二选一**：TLB 命中只给出物理地址，数据仍要过 Cache。这是本组最常错的一步。

## 1. 一条走线（44 题的骨架）

| 步 | 动作 | 结果 | 408 落点 |
|---|---|---|---|
| 1 | CPU 发出 VA | — | 地址形成（寻址方式、基址/变址） |
| 2 | TLB 用 VPN + ASID 查 | 命中 → PA | TLB 的 tag 是 VPN；组相联、替换、有效位 |
| 3 | 未命中 → 查页表（k 级 = k 次访存） | 得 PTE，P=1 → 回填 TLB | 多级页表、页表基址寄存器 |
| 4 | PTE.P=0 → 缺页异常 | OS 选帧（置换）→ 读页 → 改 PTE 与 TLB | 缺页处理、置换算法、脏位回写 |
| 5 | PA 切 tag/index/offset 查 Cache | 命中 → 取数 | 映射方式、比较器个数、V 位 |
| 6 | 未命中 → 访存并装入块（可能替换） | 脏块写回 | 写策略、替换算法 |

一次访存可叠加两次 miss（TLB miss + Cache miss），代价分别计算——这是 44 题给分点，也是 43 题周期数题的算法。

## 2. 同一地址被切两次

$$\underbrace{[\ \mathrm{VPN}\ |\ \text{page offset}\ ]}_{\text{VA}\to\text{翻译}}\qquad \underbrace{[\ \mathrm{tag}\ |\ \mathrm{index}\ |\ \text{block offset}\ ]}_{\text{PA}\to\text{Cache}}$$

三条不变量：

1. **两个 offset 不同宽**：页内偏移 $=\log_2$ 页大小（4 KB → 12 位），块内偏移 $=\log_2$ 块大小（64 B → 6 位）。题面常只给一半，混用就错。
2. **index 与 tag 都从 PA 取**：408 按 PIPT（先翻译、后查 Cache），TLB 在翻译之前，Cache 在翻译之后。
3. **块 ≤ 页时，块内偏移就是页内偏移的低位**：一页 4 KB / 块 64 B → 一页 64 块。

算例（32 位 VA、4 KB 页、64 B 块、4 路、Cache 32 KB）：VPN 20 位 / 页内偏移 12 位；512 行 = 128 组 → index 7 位、块内偏移 6 位、tag $32-7-6=19$ 位。

## 3. 三件套的同构

| 维度 | Cache | 页表 / VM | 同在哪 | 差在哪 |
|---|---|---|---|---|
| 映射 | 直接 / 全相联 / 组相联 | 单级 / 多级 / 反置 | 都用地址位段把候选集缩小 | 表：一次索引到位；树：逐级解引用 |
| 替换 | LRU / FIFO / 随机，候选 = 组内 n 路 | LRU / Clock / 改进 Clock / FIFO，候选 = 帧 | 判据都是「最近性」 | 候选规模 $n\le16$ vs $10^5$ |
| 写 | 全写（写直达）/ 写回，配写分配 / 非写分配 | 脏位（修改位）+ 延迟写回 | 写回同构：推迟到换出 | VM 没有写直达 |
| 有效位 | $V=1$ 才算命中 | $P=1$ 才算有效翻译 | 都用来排除残留数据 | $V=0$ = 没装过；$P=0$ = 映射合法但不在内存 → 缺页 |
| 依据 | 时间 / 空间局部性 | 同一前提，尺度更大 | 同一根因 | — |

`V=0` 与 `P=0` 的语义差是本组最值钱的一行：Cache 的无效行没有后备，页表的无效项有后备（磁盘）。

## 4. 四条分界（决定算法为什么不同）

| 分界 | Cache | 页 | 后果 |
|---|---|---|---|
| 谁处理 miss | 硬件，对指令透明 | OS：陷入、选帧、发起 I/O | 页侧能上「策略」，Cache 侧只能是固定硬件算法 |
| 代价 | 约 100 周期 | 约 $10^5$–$10^6$ 周期 | 页侧必须近似 + 预取 + 工作集；Cache 侧敢用精确 LRU |
| 粒度 | 64 B | 4 KB | 一页 = 64 块，两个 offset 因此不同宽 |
| 候选集 | 组内 n 路 | 全部帧（局部置换时 = 本进程帧） | n 小 → 精确计数；候选大 → Clock 一位了事 |

### 4.1 为什么 Cache 侧没有「驻留集 / 工作集 / 回收」

这三个概念都是**为了应对高代价、异步、多租户**才长出来的管理动作。先分清身份：

| 概念 | 身份 | 谁定 | 回答什么 |
|---|---|---|---|
| **驻留集** | 策略量（配额） | OS 分配策略（固定/可变） | 这个进程**给**多少帧 |
| **工作集** | 测量量（需求） | 观察窗口 $\Delta$ 内的实际引用 | 这个进程**要**多少帧 |
| **回收** | 事前释放 | 内核后台（kswapd、水位） | 在为时已晚之前先腾出多少 |

三者构成一个闭环：测工作集 $\to$ 与驻留集比 $\to$ 调配额或回收。**Cache 侧这个环长不起来，因为四个前提一个都不具备**：

| 前提 | VM 侧具备 | Cache 侧不具备 |
|---|---|---|
| 所有权 | 页框属于进程地址空间，多进程竞争 $\to$ 必须分配、必须公平 | 行按物理地址索引，全局共享无归属 $\to$ 没有「给谁多少」这个变量 |
| 错误代价 | 缺页 $10^5$–$10^6$ 周期 $+$ I/O | miss 约 100 周期，硬件同步补齐 |
| 决策周期 | 定时器 / 陷入 / 后台线程，可周期决策 | 纯硬件，只在「换行那一刻」有一个决策点 |
| 反馈信号 | 缺页率、访问位、工作集估计 | 只有命中/缺失一位，无周期统计 |

于是三件事被三个更便宜的机制顶替：

| 管理动作 | VM 的做法 | Cache 的替代 |
|---|---|---|
| 分配 | 驻留集配额 $+$ 局部置换 | 替换算法即时裁决：组内 LRU 自动把行让给最活跃的块，无需配额 |
| 需求估计 | 工作集（窗口 $\Delta$） | 局部性本身：每次访问重新竞争，硬件不必知道「需要多少」 |
| 回收 | 后台按水位提前释放 | 装入时选牺牲者（反应式回收）$+$ 写回时同步写脏行 |

**判据**：策略层的存在不取决于系统复杂度，取决于**错误的代价**——小到「错了就重来」（100 周期），贪心即时裁决就够；大到「错一次就卡住」（$10^5$ 周期 $+$ I/O），才必须事前规划与闭环反馈。与之配套：**Cache 没有「抖动」这种失效模式**，最坏只是变慢——换出的是副本，不是唯一的页。

**反证（概念在什么条件下回来）**：一旦把代价与多租户塞回 Cache，驻留集就复活——多核共享 LLC 要 QoS 隔离 $\to$ 按路划分/配额（Intel CAT 一类）；页着色（page coloring）用物理页颜色控制集合占用，是同一思想；脏行后台清洗 $\approx$ 提前回收；硬件预取 $\approx$ 预读。而「cache 工作集」（程序足迹、容量 miss 分析）在性能分析里一直存在，差别在于它是**被测量**的，不是**被分配**的。

408 口径：OS 第三章「页框分配与回收」要求驻留集、工作集、抖动；计组第三章 Cache 只要映射/替换/写策略，**不要求**任何分配或回收概念——不是漏写，是两层分工的必然。

## 5. 页置换算法

| 算法 | 判据 | 性质 | 408 考法 |
|---|---|---|---|
| OPT | 未来最久不用 | 理论下界，不可实现 | 算「最少缺页次数」当基准 |
| FIFO | 进入次序 | 有 Belady 异常（帧数↑ 缺页↑） | 反例题 |
| LRU | 过去最久未用 | 无 Belady；精确实现贵（时间戳/栈） | 手算缺页率 |
| Clock（NRU） | 访问位 + 环形指针 | 近似 LRU，每页 1 位 | 手算扫描过程 |
| 改进 Clock | (访问位, 修改位) 四级 | 优先淘汰 (0,0)，减少写回 | 判断淘汰次序 |

三个附加概念：局部 vs 全局置换（固定分配 vs 可变分配）；**工作集** $=$ 时间窗口 $\Delta$ 内实际引用的页集合，用来定驻留集的大小（实测需求 vs 分配配额，见 §4.1）；**抖动** $=$ $\sum$ 工作集 $>$ 可用帧数，缺页率暴涨。

## 6. Cache 替换 vs 页替换：三点实质不同

1. **候选集**：组内 n 路 vs 全部帧。Cache 的替换是局部决定，页置换是全局决定（局部置换也要先分配帧）。
2. **换出代价**：块换出只丢副本（脏块才写主存）；页换出可能写盘。
3. **元数据住在哪**：Cache 的 LRU 位住在 Cache 行里（每组 $n\lceil\log_2 n\rceil$ 位，位数口径见 [[标准错误答案清单]] §三章）；页的访问位住在 **PTE** 里，由 MMU 每次访问置 1。

由 1、2 直接推出：**Cache 可以用精确 LRU，页置换只能近似**——不是教材喜好，是候选集与代价逼出来的。

## 7. 一起比较时容易混轴的几组

| 这一组 | 真同构 | 不可类推 | 收口 |
|---|---|---|---|
| 多级页表 ↔ 组相联 | 都用位段分层缩小候选 | 树（逐级取基址）vs 单级并行比较 | 思想同构，别拿组相联公式算多级页表大小 |
| 反置页表 ↔ 全相联 | 都没有 index 位，靠内容匹配 | 反置页表按**帧号**索引，查进程页号要 hash | 同构在「无 index」，不同在「谁做匹配」 |
| 段页式 ↔ 两级表 | 两套表串联 | 段表按段号、页表按页号；段表项给出页表基址 | 两次查表 ≠ 多级页表 |
| 写缓冲 ↔ 写直达 | 都保证写入主存 | 缓冲只藏等待，写次数不变 | 写直达 + 写缓冲 ≠ 写回 |

明确排除：磁盘调度（I/O 排队，不是缓存层）、分支预测 BTB（缓存跳转历史，408 不考）。混进来只会让「同构」变成比喻。

## 9. 四条「对照才犯」的错

1. TLB 命中就当数据到手（实为串联）。
2. 两个 offset 同宽（12 位 vs 6 位）。
3. 用虚拟地址查 Cache（408 按 PIPT）。
4. 用 Cache 替换的位数公式去算页置换，或反过来（候选集不同）。
5. 让脏位 / 修改位参与命中判断（它只决定换出时写不写）。

单点易错（比较器个数、LRU 位宽、CLOCK 位数、TLB 与 PTE.P 的关系）不在此重述，见 [[标准错误答案清单]] §三章。
