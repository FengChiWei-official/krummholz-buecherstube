# OSI 与 TCP-IP：分层对照与功能反查

> **原材料（or/）**：AI 散文，供你消化成卡。**主线**：两族不是同一类东西——OSI 是规定性的参考模型，TCP/IP 是描述性的协议族；因此「某功能属于哪层」在 OSI 里由模型裁定，在 TCP/IP 里由实现与端到端论证裁定。全文每提一层都注明是哪个协议族的名词。

**名词约定**（下文一律用此标注；`同名` = 两族叫法相同）：

- 物理层（OSI 名词；TCP/IP 无独立层，并入网络接口层）
- 数据链路层（OSI 名词；TCP/IP 并入网络接口层 Network Access Layer）
- 网络层（OSI 名词）↔ 网际层 Internet Layer（TCP/IP 名词）——**同一位置，两个名字**
- 传输层（两族同名）
- 会话层 · 表示层（仅 OSI 名词；TCP/IP 无对应层）
- 应用层（两族同名）

## 一、差异：不在层数，在规范的来源

| 维度 | ISO/OSI | TCP/IP |
|---|---|---|
| 性质 | 参考模型（ISO 7498）：先规定七层各该提供什么，再要求协议去填 | 协议族先行，模型是事后描述（RFC 1122/1123） |
| 层数 | 7 | 4（教学五层 = 拆开网络接口层后的折中） |
| 形状 | 七层等宽的矩形，层间是**服务原语**（request/indication/response/confirm） | **沙漏**：IP 之上什么都跑，IP 之下什么都跑；上三层压成一层 |
| 上三层 | 会话 / 表示 / 应用各自独立 | 全并入应用层，功能被「搬家」而非消失 |
| 网络层服务 | 连接型（CONS/CLNP）与无连接型（CLNS）都定义 | 只有无连接 IP（尽力而为） |
| 可靠性放哪 | 各层都可逐跳做 | 逐跳只检测（FCS、IPv4 头校验和），**保证**交给端到端（TCP） |
| 编址 | NSAP / TSAP（服务访问点） | IP 地址 + 端口 |
| 落地 | 协议基本没赢，模型作为词汇活下来 | 协议全赢，模型跟着协议走 |

**一句话**：OSI 回答「这一层应该提供什么」，TCP/IP 回答「这件事实际在哪个实现里做」。所以问「会话层的功能在哪」时，OSI 的答案是「会话层」，TCP/IP 的答案是「应用层协议自己实现（SIP 的 dialog、HTTP 的 session、TLS 的会话恢复）」。

## 二、每层的功能（两族并排）

| 层（族名） | 干什么 | 典型协议 / 设备 | 这一层的状态 |
|---|---|---|---|
| 物理层（OSI；TCP/IP 并入网络接口层） | 把比特变成信号送过介质：编码、电/光/射频、速率、双工、拓扑 | 10BASE-T 的曼彻斯特编码、光模块、中继器、集线器 | 无（不记任何东西） |
| 数据链路层（OSI；TCP/IP 并入网络接口层） | 成帧、MAC 寻址、介质访问控制、逐跳差错检测 | Ethernet、PPP、802.11、交换机、网桥；ARP 骑在边界上 | 每跳的帧序号/窗口（HDLC、802.11） |
| 网络层（OSI）＝网际层（TCP/IP） | 逻辑寻址、路由选择、异构网互联、分片 | IP、ICMP、OSPF（IP 协议号 89）、BGP（跑在 TCP 179 上） | 路由表、转发表、分片重组（目的主机） |
| 传输层（两族同名） | 进程到进程的通信：端口复用、分段重组、连接管理、可靠交付、流量与拥塞控制 | TCP、UDP、QUIC（用户态实现） | 连接、序号、窗口、重传定时器 |
| 会话层（仅 OSI） | 对话控制（单工/半双工）、会话建立/维持/释放、同步检查点、令牌 | OSI 会话协议；RPC 的会话、SIP dialog 是它的功能替身 | 会话标识、同步点 |
| 表示层（仅 OSI） | 语法与编码转换、压缩、加密（OSI 安全体系把加密放这里） | ASN.1、XDR；MIME/JSON/TLS/gzip 是它的功能替身 | 编码上下文、密钥 |
| 应用层（两族同名） | 面向用户的服务；在 TCP/IP 里还要背会话与表示 | HTTP、DNS、SMTP、SSH、DHCP、BitTorrent | 应用会话、缓存、认证 |

**五层（教学/408 口径）的来历**：物理层、数据链路层取自 OSI，网络层即 TCP/IP 的网际层，传输层同名，上三层按 TCP/IP 合成应用层。也就是说：**五层不是第三个模型，是两族的拼接**——凡说「五层的会话层」都是错的。

**作用域三词**（考试最常混）：数据链路层（OSI）= 相邻结点之间；网络层（OSI）/网际层（TCP/IP）= 主机到主机；传输层（两族）= 进程到进程（端到端）。注意口径分歧：部分 TCP/IP 教材把传输层叫 host-to-host、把应用层叫 process-to-process（[[Structure of Computer Network]] 就是这种口径）；408 按「传输层端到端/进程间」答。

## 三、反查：一个功能可能落在哪些层

**先立判据**——层不是能力的归属地，而是**状态与信任的边界**。同一功能换层实现 = 换谁持有状态、谁的失效域、谁能复用。三条判据：

1. **端到端论证**（Saltzer–Reed–Clark）：只有端点才知道「是否真的送达/是否真的完整」，所以在低层实现可靠性、加密、顺序，只是**优化或提示**，不是保证。
2. **复用 vs 精度**：越往下，一次实现服务所有上层（经济），但语义越粗；越往上，语义越准，但每个应用重造一遍。
3. **失效域**：低层实现失败会连累所有上层；所以「低层做检测、高层做保证」是常态，反过来很少见。

| 功能 | 可能实现的层（族名） | 具体例子 | 放到那层的代价/边界 |
|---|---|---|---|
| 差错检测 | 物理层（OSI）、数据链路层（OSI）、网络层（OSI）、传输层（同名）、应用层（同名） | 物理：信号判决与 FEC；链路：Ethernet FCS（CRC-32）、802.11 帧校验；网络：IPv4 头校验和（只护头，IPv6 删掉）；传输：TCP/UDP 校验和（含伪首部）；应用：BitTorrent 分片哈希 | 越低越是逐跳、越快丢弃；越高越端到端，但重复计算、且只能事后发现 |
| 可靠交付（确认+重传） | 数据链路层（OSI）、网络层（OSI，仅 CONS）、传输层（同名）、应用层（同名） | 链路：HDLC ARQ、802.11 每帧 ACK；网络：OSI CONS 定义过，IP 不做；传输：TCP；应用：HTTP 幂等重试、消息队列 ack | 逐跳可靠 ≠ 端到端可靠（中间队列溢出照样丢）；应用层重试必须自己判重 |
| 流量控制 | 数据链路层（OSI）、网络层（OSI，CONS）、传输层（同名）、应用层（同名） | 链路：滑动窗口、Ethernet PAUSE 帧（802.3x）；网络：ICMP source quench（已废弃）；传输：TCP rwnd；应用：HTTP/2 每流窗口 | 只有端点的接收缓冲是真正要保护的对象 → 传输层是唯一「查得准」的位置 |
| 拥塞控制 | 数据链路层（OSI）、网络层（OSI）、传输层（同名）、应用层（同名） | 链路：交换机 PAUSE、802.1Qau（已废）；网络：ECN 标记、RED 丢弃、DiffServ；传输：TCP CUBIC/BBR；应用：DASH 码率自适应 | 中间设备只能**标记/丢弃**，无法知道端到端还该发多快；真正调速必须端点做 |
| 分段与重组 | 数据链路层（OSI）、网络层（OSI）、传输层（同名）、应用层（同名） | 链路：MTU 的来源、ATM 53 B 信元、802.11 分片；网络：IP 分片（中途可分，只在目的主机重组）；传输：TCP 按 MSS 切；应用：HTTP chunked/range、QUIC STREAM 帧 | 越往下切，重组代价越分散；IP 分片最怕「丢一片全废」，所以现代做法是端点先按 MTU 切（PMTUD） |
| 复用 / 多路分解 | 数据链路层（OSI）、网络层（OSI）、传输层（同名）、应用层（同名） | 链路：VLAN tag（802.1Q）、LLC SAP；网络：IP 头 protocol 字段（6=TCP、17=UDP、1=ICMP）；传输：端口；应用：HTTP/2 stream id、Host 头、TLS SNI | 每层都能再分一次，但分解键的粒度不同：MAC→VLAN→IP→端口→应用会话 |
| 连接管理 | 数据链路层（OSI）、网络层（OSI，CONS）、传输层（同名）、会话层（仅 OSI）、应用层（同名） | 链路：PPP 的 LCP；网络：CONS 连接、MPLS LSP；传输：TCP 三次握手/四次挥手；会话层：OSI 的会话建立与同步点；应用：SIP dialog、WebSocket | 连接 = 状态；状态放越低，越难按「用户是谁」区分，也越难回收 |
| 加密与完整性 | 数据链路层（OSI）、网络层（OSI）、表示层（仅 OSI）、应用层（同名） | 链路：MACsec（802.1AE）、WPA3；网络：IPsec ESP/AH；表示层：OSI 安全体系规定的位置；应用：TLS、PGP、S/MIME | 逐跳加密每过一个中间设备就要解密再加密；端到端加密中间设备看不见，但做不了流量整形与缓存 |
| 压缩 | 数据链路层（OSI）、网络层（OSI）、表示层（仅 OSI）、应用层（同名） | 链路/网络边界：ROHC 头压缩（LTE/5G）、PPP 压缩；表示层：OSI 规定的位置；应用：gzip/brotli、图片编解码 | 头压缩省的是每包固定开销，收益在小包；内容压缩省的是带宽，代价是 CPU 与延迟 |
| 寻址与命名 | 数据链路层（OSI）、网络层（OSI）、传输层（同名）、应用层（同名） | 链路：MAC（平面、烧录）；网络：IP（层次、可聚合）；传输：端口（进程地址）；应用：域名/URI（DNS 自己就是应用层协议） | 平面地址不可聚合 → 路由表爆炸；层次地址可聚合，但换网就要换地址（移动性问题） |
| 同步 / 检查点 | 会话层（仅 OSI）、传输层（同名）、应用层（同名） | 会话层：主/次同步点；传输层：TCP 序号（字节流位置，不是业务检查点）；应用：HTTP range 断点续传、rsync 滚动校验 | 低层的「位置」不知道业务边界；业务级续传必须应用自己记账 |
| 组播 / 广播 | 数据链路层（OSI）、网络层（OSI）、应用层（同名） | 链路：广播/组播 MAC；网络：IP 组播（IGMP）；应用：pub/sub、gossip（在覆盖网络里自建分发树） | 越往下越省重复发送，但组成员管理越难；应用层组播绕开路由器支持，代价是自建拓扑 |

**读法**：这张表不是「功能可以在任何层」的相对主义——每一行真正的答案是**一个**：保证必须落在端点（传输层或应用层），低层的同名机制只是优化。例外是「逐跳才有意义」的东西（FCS、MAC 寻址、VLAN），它们天生属于低层，端到端反而做不到。

## 四、为什么 OSI 的会话层/表示层会「消失」

不是功能没了，是**功能搬进了应用层**，而且是按协议各搬各的：

- 会话 → SIP 的 dialog、HTTP 的 cookie/session、TLS 的会话恢复、数据库连接池；传输层只给「连接」这一半。
- 表示 → MIME 的类型标注、JSON/Protobuf 的编码、TLS 的加密、gzip 的压缩；传输层只给字节流。
- 代价：TCP/IP 里每个应用协议都要重新决定「怎么表示、怎么续会话」，这正是应用层「最复杂」的来源；收益是中间设备（路由器、NAT、防火墙）不必理解这些格式。

## 五、408 落点

1. **异同三句**：规范来源不同（模型 vs 协议族）；层数不同（7 vs 4，教学 5）；OSI 的会话/表示在 TCP/IP 并入应用。
2. **各层功能**用五层答，但每层的名词要指回来源：数据链路层是 OSI 的切法，网际层是 TCP/IP 的叫法。
3. **「某功能在哪层」**：先问「这是保证还是优化」，再问「谁持有状态」——两问定层，然后举该层的具体协议（如「可靠交付：TCP 保证；Ethernet FCS 只保证一跳」）。
4. 别把「路由协议」当网络层协议：OSPF 直接用 IP（协议号 89），BGP 跑在 TCP 179 上——**功能是网际层（TCP/IP）的，载体是传输层与应用层**的，这本身就是反查表的一行。
