# 自举链路：复位矢量 → 第一个进程

> **原材料（or/）**：AI 散文，供你消化成卡。链路是你写的（已接受），修正与核心分析是我给的命题，**正文与结论仍由你写**。

## 一、链路（你的版本，已接受）

复位矢量 → POST → MBR 0x7C00 → bootloader 切保护模式 → 建 GDT / 临时 IDT / 页表 → 开分页（+ 进长模式）→ 建最终 IDT → 进内核 → 起第一个进程 → 之后被中断驱动。

## 二、四处卡壳的修正（已谈定）

1. **主板不加载 BIOS**：固件本就在主板 ROM/SPI flash 里；主板的作用是按硬连线约定把 PC 置到复位矢量，该地址被芯片组映射到固件。这是「合同先于电路」的第一个实例。
2. **POST 在找启动设备之前**：复位 → POST → 按启动顺序找设备 → 读第一个扇区到 0x7C00 → 跳转。
3. **实模式只属于 BIOS 与早期 bootloader**。三态，不是两态：
   实模式 →（bootloader 设 CR0.PE）→ **保护模式（未开分页，线性地址 = 物理地址）** →（内核建页表、设 CR0.PG）→ 分页。
4. **顺序与术语**：建临时 IDT/GDT → 建页表 → 开分页 → 建**最终** IDT → start_kernel。实模式那张叫 **IVT**（0x0000，每项 4 字节），保护/长模式那张叫 **IDT**（IDTR 指向，每项 8/16 字节）。

## 三、还缺的三条边

1. **GDT**——保护模式的前提（段描述符表），链路里原本缺席。
2. **开分页前必须关中断（CLI）**：IDT 未建好时来一个中断就跳飞。
3. **恒等映射——开分页瞬间的鸡与蛋**：设 `CR0.PG` 那条指令的物理地址，必须已被映射到它自己的虚拟地址，否则下一条取指就崩。第一张页表至少要恒等映射当前执行的代码。
4. （附）**分页不是可选优化，是进现代模式的门票**：x86_64 长模式要求先开 PAE 分页——32 位保护模式（未分页）→ 建页表 → 开分页 → 进 64 位。

## 四、链路的核心（命题，待你定稿）

**核心 = 自举：机器用一条硬连线约定启动自己，然后把「改写解释规则的权力」逐级移交给软件。**

三层特殊意义：

1. **可见性刚好够加载下一级**：复位矢量只够取一条指令；实模式只够 1MB；保护模式给 4GB 线性；分页给任意虚拟地址；长模式给 64 位。每级只要求刚好看见下一级——这是自举的一般形式（编译器自举、包管理器自举同形）。
2. **特权从「无人拥有」到「OS 拥有」= 元层的诞生**：机器从"被约定驱动"变成"能自己改写约定"（页表、IDT、特权级都由它定）。这才是「存储程序」的完整含义——不只是程序存在内存里，而是**连"什么算程序、地址怎么解释"都能被存储的位串改变**。
3. **顺序即安全**：每级都必须"先建合同、后开通道"（GDT/IDT/页表先就位才能开中断；开分页那条指令先被映射）。自举的失败模式几乎全是**顺序错**，不是逻辑错。

**合流点**：自举是两条链同时爬升——**距离链**（ROM → 磁盘 → 内存 → Cache → 寄存器）与**能力链**（可见性 + 特权），它们在**第一个用户进程**处合流：两级名字（虚拟/物理）与两级权限（用户/内核）都已就位，OS 退居幕后，只等中断唤醒。

**边界**：
- UEFI 把移交前置（固件已给保护模式/长模式/分页），级数变少、本质不变。
- 虚拟机/容器里没有真复位，第一级约定换成 hypervisor 的 ABI。
- 移交**不彻底**：SMM（固件）与 hypervisor 保留后门特权——"移交"是分层的、带保留条款。
- 说"通用性由此实现"要限定：通用性还依赖统一编址与可扩展编码；自举只是让它**可被重新定义**的那一环。
