# 程序的三个视角：可执行文件、虚拟内存、物理内存（408）

> **原材料（or/）**：按 408 操作系统「内存管理 / 虚拟内存」与计组「存储系统」整理：一个程序从磁盘上的可执行文件，到进程的虚拟地址空间，再到物理页框，分别长什么样；变量在各处的存在性与可变性。
> 408 用简化模型：代码段/数据段/堆/栈 + 页表/页框；真机 ELF 只作锚点，地址以题干为准。
> 主线：**编译 → 链接 → 装入 → 运行**；三视图的桥是**页表 + 缺页**。

对应考纲：OS「内存管理 / 虚拟内存」（装入与链接、分页/分段/段页式、请求分页、缺页、置换）；计组 ch3「存储系统 / 虚拟存储器」、ch5「指令执行 / 异常」。

## 0. 一条主线与三个视角

| 阶段 | 输入 | 输出 | 主要位置 | 408 术语 |
|---|---|---|---|---|
| 编译 | `.c` 源文件 | 汇编/目标文件 `.o` | 磁盘 | 编译、汇编 |
| 链接 | `.o` + 库 | 可执行文件 | 磁盘 | 静态链接、动态链接 |
| 装入 | 可执行文件 | 进程映像 | 虚拟内存 | 绝对装入、可重定位装入、动态运行时装入 |
| 运行 | 指令 + 数据 | 页表翻译、缺页 | 物理内存 | 页表、TLB、缺页、置换 |

| 视角 | 你看到什么 | 单位 | 回答的问题 |
|---|---|---|---|
| 外存 | 可执行文件（节/段、符号、重定位） | 字节/节 | 程序最初有什么？哪些字节在文件里？ |
| 虚拟内存 | 进程地址空间（代码段/数据段/堆/栈） | 页/段 | 地址怎么排？权限是什么？ |
| 物理内存 | 页框（物理块）+ 页表 | 页框 | 真正在哪？谁共享？缺页怎么办？ |

```
外存（磁盘）                虚拟内存                 物理内存
┌──────────────┐          ┌──────────────┐          ┌──────────────┐
│ .text        │──装入──→ │ 代码段        │──页表──→ │ 页框 ...      │
│ .rodata      │          │ 只读数据段    │          │              │
│ .data        │          │ 数据段        │          │              │
│ .bss         │          │ BSS           │          │              │
│ （无字节）    │          │ 堆 / 栈       │          │              │
└──────────────┘          └──────────────┘          └──────────────┘
```

边界：真机还有 VMA、页缓存、COW、ASLR、多级页表；408 题面通常只给「段/页/页框 + 页表」的简化模型。名字按题面，不按 Linux。

## 1. 外存视角：可执行文件里有什么

可执行文件保存的是**初始映像**，不是运行中的进程。它只保证「程序开始执行时，这些字节从哪来」；堆、栈、BSS 的运行时形态不在文件里。

408 不考 ELF 内部结构；下面用 `.text` 等名字，只是把「代码 / 只读数据 / 已初始化数据 / 未初始化数据」四类说清楚，答题时写「代码段/数据段/只读数据段/BSS」即可。

### 1.1 四种最常考的节

| 节 | 内容 | 文件中有字节？ | 可写？ | 装入后 |
|---|---|---|---|---|
| `.text` | 机器指令 | 有 | 否（R-X） | 代码段 |
| `.rodata` | 只读常量、字符串字面量、跳转表 | 有 | 否（R--） | 只读数据段 |
| `.data` | 已初始化且非零的全局/静态变量 | 有 | 是（RW-） | 数据段 |
| `.bss` | 未初始化或零初始化的全局/静态变量 | **无**（`SHT_NOBITS`） | 是（RW-） | 数据段/BSS |

- `.bss` 在文件里只占一个「节头」，不占字节；装入时由 OS 把「内存大小 − 文件大小」的部分清零。
- `.symtab`、`.debug_*`、`.comment` 不装入内存；它们只给链接器/调试器看。
- `.data` 里的「初值」是文件字节；运行时写它不会改可执行文件（私有映射/COW）。

### 1.2 文件里的「段」：`p_filesz` 与 `p_memsz`

可执行文件的 program header 用 `PT_LOAD` 描述「哪一段文件映射到哪一段虚拟地址」：

| 字段 | 含义 | 408 读法 |
|---|---|---|
| `p_offset` | 文件偏移 | 这段从文件哪里开始 |
| `p_vaddr` | 虚拟地址 | 装到进程哪里 |
| `p_filesz` | 文件中有多少字节 | 真正从磁盘读的字节数 |
| `p_memsz` | 内存中占多少字节 | 包含 BSS 补零 |
| `p_flags` | R/W/X | 代码段只读可执行，数据段可写 |

`p_memsz > p_filesz` 的差值就是 BSS（以及页对齐填充）。例：某段 `p_filesz = 0x278`、`p_memsz = 0x290`，差 `0x18 = 24` 字节，就是 `.bss` 的大小。

408 常问：「`.bss` 占不占可执行文件空间？」——不占文件字节，但占内存；`p_memsz` 包含它。

### 1.3 节与段的区别（408 不深究，但别混）

| | 节（section） | 段（segment） |
|---|---|---|
| 视角 | 链接 | 装载 |
| 单位 | `.text`、`.data`、`.bss` | `PT_LOAD`（R/RX/RW） |
| 对齐 | 节对齐 | 页对齐 |
| 谁用 | 链接器 | 装入器/OS |

408 的「代码段/数据段」通常是**逻辑区域**，不等于 ELF 的 section，也不等于 x86 的段寄存器。看到「段」先问：是逻辑段、ELF 装载段，还是段式管理的段。

边界：真实 ELF 还有 `.rodata`、`.got`、`.plt`、`.dynamic`、重定位表；408 只需要知道「代码只读、常量只读、已初始化数据可写、未初始化数据不占文件」。

## 2. 虚拟内存视角：section 在地址空间中的分布

虚拟地址空间是**每进程一份**；物理页框是**全机一份**；页表是两者之间的映射表。408 的「进程映像」= PCB + 程序段 + 数据段；用户地址空间里看到的是代码段/数据段/堆/栈，PCB、页表、内核栈在内核空间。

### 2.1 典型 32 位进程地址空间

下面是 Linux 的 3G/1G 划分；408 题面可能只画用户空间，地址以题干为准。

```
0xFFFFFFFF  ┌──────────────────┐
            │ 内核空间          │
0xC0000000  ├──────────────────┤
            │ 栈（向低地址增长）│
            │ mmap / 共享库     │
            │ 堆（向高地址增长）│
            ├──────────────────┤
            │ .bss             │
            │ .data            │
            │ .rodata          │
            │ .text            │
0x08048000  ├──────────────────┤
            │ 未映射 / 保留     │
0x00000000  └──────────────────┘
```

| 区域 | 典型内容 | 权限 | 增长方向 | 408 说法 |
|---|---|---|---|---|
| 代码段 | `.text` | R-X | — | 只读、可执行、可共享 |
| 只读数据段 | `.rodata`、字符串字面量 | R-- | — | 只读 |
| 数据段 | `.data`、`.bss` | RW- | — | 可写、每进程私有 |
| 堆 | `malloc`/`new` | RW- | 向高地址 | 动态分配 |
| mmap/共享库 | `.so` 的代码/数据 | 按映射 | 通常向低 | 共享库 |
| 栈 | 局部变量、参数、返回地址 | RW- | 向低地址 | 函数调用 |
| 内核 | OS 代码/数据 | 内核 | — | 用户不可访问 |

示例地址（32 位 Linux，题面可能不同）：

| 符号 | 示例虚拟地址 | 所在区域 |
|---|---|---|
| `main` | `0x08048400` | 代码段 |
| 字符串 `"hi"` | `0x08048500` | 只读数据段 |
| 全局 `g` | `0x0804A000` | 数据段 |
| 全局 `b`（BSS） | `0x0804A004` | 数据段/BSS |
| 堆对象 `*p` | `0x0804B000` | 堆 |
| 局部 `x` | `0xBFFFFEFC` | 栈 |

408 题面若给地址，就按题面算；这些地址只是「从低到高：代码 → 只读数据 → 数据/BSS → 堆 → 共享库 → 栈」的示意。

把文件节对到虚拟区域：`.text → 代码段（R-X）`、`.rodata → 只读数据段（R--）`、`.data/.bss → 数据段（RW-）`；`.symtab`、`.debug_*` 不映射。

### 2.2 地址翻译：页号 + 页内偏移

32 位、页大小 4 KiB：

```
逻辑/虚拟地址 = 页号（20 位） + 页内偏移（12 位）
物理地址     = 页框号（20 位） + 页内偏移（12 位）
```

例：`VA = 0x12345678`

- 页号 = `0x12345`，偏移 = `0x678`。
- 查页表：`页表项[0x12345] = 0x0A3B`（页框号）。
- `PA = 0x0A3B000 + 0x678 = 0x0A3B678`。

两级页表（10 + 10 + 12）：

- 页目录索引 = `0x12345 >> 10 = 0x48`；
- 页表索引 = `0x12345 & 0x3FF = 0x345`；
- 偏移 = `0x678`。

页表项至少包含：**有效位/存在位、物理页框号、保护位（读/写/执行）、脏位、访问位**。有效位为 0 就是缺页。

TLB 是页表项的 Cache：缓存最近用过的「页号 → 页框号 + 权限」，命中时地址翻译不必访问内存中的页表；未命中才查页表。

页表大小（408 常算）：32 位、4 KiB 页、4 B 页表项 → 页表项数 $2^{20}$，单级页表 $2^{20}\times4\text{B}=4\text{MB}$；两级页表把「常驻的页表页」降下来，但地址翻译多一次访存。

### 2.3 分页、分段、段页式

| | 分页 | 分段 | 段页式 |
|---|---|---|---|
| 划分 | 固定大小页 | 逻辑段（代码/数据/栈…） | 先分段，段内分页 |
| 地址 | 页号 + 偏移 | 段号 + 偏移 | 段号 + 页号 + 偏移 |
| 表 | 页表 | 段表（基址+长度） | 段表 + 页表 |
| 碎片 | 内部碎片 | 外部碎片 | 内部碎片 |
| 共享/保护 | 页级 | 段级（逻辑单位） | 段级 + 页级 |

408 的「代码段/数据段」在分页下会拆成页；在分段下是逻辑段；段页式先按逻辑段分，再在段内分页。

段页式的地址：`段号 + 段内页号 + 页内偏移`。先查段表得到该段的页表基址，再查页表得到页框号，最后拼页内偏移。

边界：真机 x86-64 是 4/5 级页表、48/57 位虚拟地址；408 的 32 位、两级页表是简化模型。题面给几位就按几位拆。

## 3. 物理内存视角：页框、页表、缺页

物理内存里没有「进程」这个连续对象：一个进程是**一组页框 + 页表**——代码页、数据页、BSS 页、堆页、栈页、页表页，外加内核里的 PCB 等对象。把这些页串起来的是页表，不是地址连续性。

| 对象 | 物理形态 | 共享 | 回收 |
|---|---|---|---|
| 代码页 | 页框，内容来自 `.text` | 同一程序的多进程可共享 | 可丢弃，下次从文件重读 |
| 只读数据页 | 页框，内容来自 `.rodata` | 可共享 | 可丢弃 |
| 数据页 | 页框，初值来自 `.data` | 写后私有（COW） | 可换出 |
| BSS 页 | 页框，初值全零 | 读时可用共享零页 | 可换出 |
| 堆/栈页 | 匿名页框 | 每进程/线程私有 | 可换出 |
| 页表页 | 页框，存 PTE | 每进程私有 | 进程退出释放 |
| 共享库代码 | 页框，来自 `.so` | 多进程共享 | 可丢弃 |
| 共享库数据 | 页框，写后 COW | 写后私有 | 可换出 |

408 把可共享的代码叫「可重入代码/纯代码」；共享库的代码页就是例子：多个进程的页表指向同一批页框，谁也不改它。

### 3.1 缺页：装入的继续

1. CPU 访问虚拟地址，查页表，有效位 = 0 → **缺页异常**。
2. OS 找到该页在外存的位置（可执行文件 / 交换区 / 文件映射）。
3. 若内存有空闲页框，分配一个；否则按页面置换算法淘汰一页。
4. 把页读入页框，更新页表项（页框号、有效位、保护位）。
5. 重新执行触发缺页的指令。

408 区分：**缺页不一定置换**（有空闲页框就直接装入）；**置换只在没有空闲页框时发生**。

驻留集 = 当前在内存中的页集合；408 的页框分配和置换算法都围绕它。保护：分页靠 PTE 的读/写/用户位，分段靠段表基址 + 长度；越界或越权 → 异常。

### 3.2 写时复制（COW）

`fork` 后，父子进程的私有可写页先共享同一批页框，页表项改成只读；任一方写时触发保护异常，OS 复制一页、改页表、恢复写权限。408 可能把 COW 作为 `fork` 的优化提及；它解释了「为什么 `fork` 不立即复制整个地址空间」。

边界：408 的页框分配/置换算法（OPT/FIFO/LRU/CLOCK）是本章另一条线；这里只定位「缺页发生在三视图的哪一格」。

## 4. 装载过程：从文件到进程

### 4.1 编译、链接、装入

| 阶段 | 做什么 | 产物 | 408 关键词 |
|---|---|---|---|
| 编译 | 高级语言 → 汇编/目标代码 | `.o`（可重定位目标文件） | 编译 |
| 链接 | 合并目标文件与库，解析符号、重定位 | 可执行文件 | 静态链接、动态链接 |
| 装入 | 把可执行文件映射成进程映像 | 进程 | 绝对装入、可重定位装入、动态运行时装入 |
| 运行 | 取指、取数、执行、缺页 | 页框 | 页表、TLB、缺页 |

### 4.2 三种装入方式

| 方式 | 地址何时确定 | 是否修改程序 | 能否移动 | 支持虚拟内存 |
|---|---|---|---|---|
| 绝对装入 | 编译时 | 否 | 否 | 否 |
| 可重定位装入（静态重定位） | 装入时 | 是（加载器改地址） | 否 | 否 |
| 动态运行时装入（动态重定位） | 运行时 | 否（基址寄存器/MMU 翻译） | 是 | 是 |

公式：

```
绝对装入:      PA = 逻辑地址
静态重定位:    PA = 逻辑地址 + 装入基址      （装入时一次算好）
动态重定位:    PA = 逻辑地址 + 基址寄存器     （运行时每次翻译）
```

408 常问：「哪种装入方式支持虚拟内存？」——动态运行时装入；它允许程序在内存中移动，也允许页不在内存。

### 4.3 链接方式

| 方式 | 时机 | 库代码在哪 | 特点 |
|---|---|---|---|
| 静态链接 | 装入前 | 复制进可执行文件 | 无运行依赖，体积大 |
| 装入时动态链接 | 装入时 | 共享库映射进地址空间 | 共享、启动时解析 |
| 运行时动态链接 | 运行时 | 按需加载共享库 | 灵活，运行时有开销 |

### 4.4 装入时发生了什么

1. 读可执行文件头，找到代码/只读数据/数据/BSS 段。
2. 建立进程的页表（或段表），把各段映射到虚拟地址。
3. 建立堆、栈区域；栈顶放参数/环境变量。
4. 若动态链接，映射共享库，解析符号。
5. 设置 PC = 入口地址，SP = 栈顶；若是动态链接，PC 先指向动态链接器，再由它转到程序入口。
6. 之后按需调页：第一次取指/取数才把页装入页框。

关键：**装入不是把整个文件读进内存**。408 的请求分页模型就是「先建页表，访问时才缺页装入」。

### 4.5 时间切片：同一份数据在 T0–T7

| 时刻 | 外存 | 虚拟内存 | 物理内存 |
|---|---|---|---|
| T0 源码 | `.c` 文本 | 无 | 无 |
| T1 目标文件 | `.o` 的 `.text/.data/.bss` + 重定位 | 无 | 无 |
| T2 可执行文件 | 链接后的节/段；`.bss` 无字节 | 无 | 无 |
| T3 装入 | 读文件头/段 | 建页表、代码/数据/BSS/堆/栈区域 | 可能只装入入口页 |
| T4 首次取指 | 代码在文件里 | PC 指向代码段，页表项可能无效 | 缺页 → 分配页框 → 读代码页 |
| T5 首次读数据 | `.data`/`.rodata` 在文件里 | 数据段地址已定 | 缺页 → 读数据页 |
| T6 首次写 | 文件不变 | 数据段可写 | COW/匿名页；BSS 写时分配 |
| T7 `fork`/退出 | 文件还在 | 复制/拆除页表 | COW 共享；匿名页释放，文件页可回读 |

这条时间轴就是「可执行文件 → 进程 → 页框」的展开；408 的装入/缺页/置换都落在其中一格。

## 5. 运行过程：一个程序的三个视角

```c
int g = 10;                 // .data
int b;                      // .bss
const char *s = "hi";       // s 在 .data；"hi" 在 .rodata

int main(void) {
    int x = 3;              // 栈
    int *p = malloc(4);     // 堆
    *p = x + g;             // 读栈/数据段，写堆
    return 0;
}
```

示例地址（32 位，题面可能不同）：

| 符号 | 虚拟地址 | 区域 | 文件里有没有 |
|---|---|---|---|
| `main` | `0x08048400` | 代码段 | 有（`.text`） |
| `"hi"` | `0x08048500` | 只读数据段 | 有（`.rodata`） |
| `g` | `0x0804A000` | 数据段 | 有（`.data`） |
| `b` | `0x0804A004` | 数据段/BSS | **无字节**，内存补零 |
| `s` | `0x0804A008` | 数据段 | 有（指针初值） |
| `x` | `0xBFFFFEFC` | 栈 | 无 |
| `p` | `0xBFFFFEF8` | 栈 | 无 |
| `*p` | `0x0804B000` | 堆 | 无 |

运行 trace：

| 步骤 | 外存 | 虚拟内存 | 物理内存 |
|---|---|---|---|
| 1 装入 | 读 ELF 头、段表 | 建页表，映射代码/只读数据/数据/BSS，建堆/栈 | 可能只装入口页 |
| 2 取 `main` 第一条指令 | 代码页在文件里 | PC → 代码段虚拟地址 | 页表查页框；缺页则读代码页 |
| 3 执行 `x = 3` | 无 | 栈地址 | 栈页缺页 → 分配页框 → 写 |
| 4 读 `g` | `.data` 在文件里 | 数据段地址 | 缺页 → 读数据页；TLB/Cache 命中可省 |
| 5 `malloc(4)` | 无 | 堆区域扩大 | 不立即分配页框 |
| 6 写 `*p` | 无 | 堆地址 | 堆页缺页 → 分配页框 → 写 |
| 7 `return` | 无 | 栈帧回收，PC 回返回地址 | 栈页仍驻留 |
| 8 退出 | 文件还在 | 拆页表/地址空间 | 匿名页释放；代码/数据页可回读 |

一条指令可能两次地址翻译：**取指一次、取数一次**。`mov eax, [g]` 的取指走代码段，取数走数据段；两次都可能缺页，TLB 命中则省去页表访存。

408 计组还会问：虚拟地址 → 物理地址 → Cache。简化口径：先查 TLB，未命中查页表；得到物理地址后查 Cache，未命中访问主存。TLB 是页表的 Cache，Cache 是主存的 Cache。

边界：真实 CPU 有指令 Cache/数据 Cache、页表遍历缓存、多级 TLB；408 题面通常只给「TLB + Cache + 主存」的层次，按题面画。

## 6. 变量的存在性与可变性

### 6.1 总表

| 变量/对象 | 存储期 | 文件中有字节？ | 文件中的节 | 虚拟内存区域 | 可写？ | 外存中的其他副本 | 408 考点 |
|---|---|---|---|---|---|---|---|
| 函数代码 | —（代码） | 有 | `.text` | 代码段 | 否（R-X） | 可执行文件 | 代码段只读 |
| 字符串字面量 | 静态 | 有 | `.rodata` | 只读数据段 | 否（R--） | 可执行文件 | 字面量不可改 |
| 文件作用域 `const` | 静态 | 有 | `.rodata` | 只读数据段 | 否 | 可执行文件 | const 在只读段 |
| 已初始化全局 | 静态 | 有 | `.data` | 数据段 | 是 | 可执行文件 | 初值非零 → `.data` |
| 零/未初始化全局 | 静态 | **无** | `.bss` | 数据段/BSS | 是 | 无文件字节；可能 swap | BSS 不占文件 |
| 静态局部已初始化 | 静态 | 有 | `.data` | 数据段 | 是 | 可执行文件 | static 局部 |
| 静态局部未初始化 | 静态 | 无 | `.bss` | 数据段/BSS | 是 | 无；可能 swap | static 局部 |
| 自动局部 | 自动 | 无 | 无 | 栈 | 是 | 可能 swap | 栈 |
| 堆对象 | 动态 | 无 | 无 | 堆 | 是 | 可能 swap | `malloc` |
| 指针变量 | 视存储期 | 有/无 | `.data`/`.bss`/栈 | 对应区域 | 是（除非 const 指针） | 视 | 指针 vs 指向对象 |
| `const` 指针 | 静态/自动 | 有/无 | `.rodata`/`.data.rel.ro`/栈 | 对应区域 | 否 | 视 | const 的位置 |
| TLS 变量 | 静态 | 有/无 | `.tdata`/`.tbss` | TLS | 是 | 文件模板 | 408 不考，边界 |

三条「存在性」结论：

- **文件里有字节**：`.text`、`.rodata`、`.data`（以及 `.o` 里对应的节）。
- **文件里没有字节、内存里有**：`.bss`（补零）、栈、堆（运行时创建）。
- **外存里的其他副本**：栈/堆/BSS/COW 页被换出时在 swap；代码/只读数据/`.data` 的初值在可执行文件里；共享库在 `.so` 文件里。

| 外存形态 | 存什么 | 例子 | 408 关系 |
|---|---|---|---|
| 源文件 | 文本 | `.c` | 编译输入 |
| 目标文件 | 节 + 符号 + 重定位 | `.o` | 链接输入 |
| 可执行文件 | 初始映像（代码/只读数据/已初始化数据） | `a.out` | 装入 |
| 共享库 | 可共享的代码/数据 | `.so` | 动态链接 |
| 交换区 | 换出的匿名页 | 栈/堆/BSS/COW 页 | 虚拟内存 |
| 普通文件 | 持久数据 | 数据文件 | 文件管理（另一章） |

存在性三态：

| 对象 | 可执行文件 | 内存 | swap |
|---|---|---|---|
| 代码、只读数据、已初始化数据 | 有字节 | 有页 | 一般不换出（可回读文件） |
| BSS、栈、堆 | 无字节 | 有页 | 可能换出 |
| 共享库代码/数据 | `.so` 有字节 | 有页 | 代码可回读；数据可能换出 |

### 6.2 可变性：页权限 + 语言 const

| 对象 | 页权限 | 语言层 | 写入后果 |
|---|---|---|---|
| 代码段 | R-X | 不可写 | 保护异常 |
| 只读数据段 | R-- | `const`/字面量 | 保护异常（或未定义行为） |
| 数据段/BSS | RW- | 可写 | 数据段写时 COW；BSS 首次写分配匿名页 |
| 堆/栈 | RW- | 可写 | 正常；按需分配 |
| `const char *p` | 指针页可写（静态 `.data`；自动栈） | 指针可写，`*p` 不可写 | 改指针可以；改 `*p` 不行 |
| `char * const p` | 静态只读页；自动栈可写 | 指针不可写，`*p` 可写 | 改指针不行 |
| `const char * const p` | 静态只读页；自动栈可写 | 都不可写 | 都不可写 |

注意两个「可写」不是一回事：

- **页可写**：硬件允许写；`.data`/BSS/堆/栈是 RW。
- **语言允许写**：`const`/字符串字面量在语言层不允许写；即使页可写，也是未定义行为。

### 6.3 决策树：一个 C 对象落在哪

先分清「对象」：字符串字面量本身、指向它的指针、用它初始化的数组，是三个不同的对象，要分别过树。

```text
Q0 这个对象是字符串字面量本身吗？
   （不是“指向它的指针”，也不是“用它初始化的数组”）
├─ 是 → .rodata
└─ 否
   Q1 它有静态存储期吗？
      （文件作用域，或函数内 static）
   ├─ 否 → 栈（自动存储期）
   └─ 是
      Q2 它不可写吗？
         （文件作用域 const，或 static const）
      ├─ 是 → .rodata
      └─ 否
         Q3 初值非零吗？
         ├─ 是 → .data
         └─ 否（零初值 / 无初值）→ .bss
```

常用声明：

| 声明 | 对象 | 落点 | 说明 |
|---|---|---|---|
| `const char *s = "hi";` | `s` 指针 | `.data` | 指针可写；字面量在 `.rodata` |
| `const char *s = "hi";` | `"hi"` | `.rodata` | 字面量独立 |
| `char a[] = "hi";`（文件作用域） | `a` 数组 | `.data` | 字面量是初始化器 |
| `const char a[] = "hi";`（文件作用域） | `a` 数组 | `.rodata` | 数组本身 const |
| `int g = 1;` | `g` | `.data` | 非零初值 |
| `int g;` / `int g = 0;` | `g` | `.bss` | 零/无初值 |
| `const int c = 1;`（文件作用域） | `c` | `.rodata` | 只读 |
| `static int s = 1;`（函数内） | `s` | `.data` | 静态局部 |
| `static int s;`（函数内） | `s` | `.bss` | 静态局部 |
| `int x;`（函数内） | `x` | 栈 | 自动 |
| `const int c = 1;`（函数内） | `c` | 栈 | const 不等于静态 |
| `char a[] = "hi";`（函数内） | `a` 数组 | 栈 | 字面量只作初始化器 |
| `char *p = "hi";`（函数内） | `p` 指针 | 栈 | `"hi"` 在 `.rodata` |

字符串字面量在 C 里是 `char[]`，所以 `char *p = "hi";` 能编译；但字面量所在页只读，写入是未定义行为。C++ 里它是 `const char[]`，`char *p = "hi";` 直接不合法。

边界：`const` 在 `*` 左边修饰指向对象，在 `*` 右边修饰指针本身；带重定位的 const 指针在真机可能落 `.data.rel.ro`，重定位后由 RELRO 保护——408 只需答「只读数据段」。

## 7. 408 常见问法与陷阱

| 问法 | 答法 |
|---|---|
| `.bss` 占可执行文件空间吗？ | 不占文件字节；`p_memsz > p_filesz`，内存补零 |
| `static` 局部和全局变量有什么区别？ | 都是静态存储期，节相同（`.data`/`.bss`）；链接属性/作用域不同 |
| `const` 变量能改吗？ | 不能；放在只读数据段，写入保护异常 |
| 字符串字面量能改吗？ | 不能；C 里类型是 `char[]`，但写入未定义行为 |
| 局部变量在可执行文件里吗？ | 不在；栈在运行时创建 |
| `malloc` 后立即占物理页吗？ | 不；先扩堆区域，首次写才缺页分配 |
| 共享库的代码和数据分别怎么共享？ | 代码页共享；数据写时 COW，每进程私有 |
| 哪种装入方式支持虚拟内存？ | 动态运行时装入（动态重定位） |
| 缺页一定要置换吗？ | 不；有空闲页框就直接装入，没有才置换 |
| 逻辑地址、虚拟地址、物理地址？ | 按题面术语；OS 常把 CPU 生成的地址叫逻辑/虚拟地址，内存总线上的叫物理地址 |
| 分页和分段怎么选？ | 分页固定大小、内部碎片；分段逻辑单位、外部碎片；段页式折中 |
| 页表多大？ | 32 位、4 KiB 页、4 B 项 → $2^{20}\times4\text{B}=4\text{MB}$；多级页表降低常驻 |

三个高频陷阱：

1. **把「文件里的段」当成「内存里的段」**：`.bss` 文件无字节但内存有；栈/堆文件里根本没有。
2. **把「可写」当成「会写回文件」**：`.data` 的写是私有 COW，不改可执行文件；只有共享映射才写回文件。
3. **把「缺页」当成「页面置换」**：缺页是页表项无效；置换是内存满了选 victim。

术语提醒：408 OS 常把进程看到的地址叫**逻辑地址/虚拟地址**，把内存总线上的叫**物理地址**；计组把 MMU 翻译前的叫**虚拟地址**。段式管理里的「逻辑地址 = 段号 + 段内偏移」是另一层意思。考试按题面术语，不纠结名字。

边界：408 题面若给具体地址/页大小/页表级数，一律按题面算；上面的 32 位地址只是示意。

## 8. 一页总结

| 数据 | 外存（可执行文件） | 虚拟内存 | 物理内存 |
|---|---|---|---|
| 代码 | `.text` 有字节 | 代码段，R-X | 代码页，可共享/可回读 |
| 只读常量/字面量 | `.rodata` 有字节 | 只读数据段，R-- | 只读页，可共享/可回读 |
| 已初始化全局/静态 | `.data` 有字节 | 数据段，RW- | 数据页，写后 COW |
| 未初始化/零全局/静态 | `.bss` 无字节 | 数据段/BSS，RW- | 零页 → 匿名页 |
| 堆 | 无 | 堆，RW- | 匿名页，按需分配 |
| 栈 | 无 | 栈，RW-，向低增长 | 匿名页，按需分配 |

三句话：

1. **可执行文件只保存初始映像**：代码、只读数据、已初始化数据有字节；BSS、堆、栈没有。
2. **虚拟内存是地址空间**：代码段/只读数据段/数据段/BSS/堆/栈按地址排，页表把页号翻译成页框号。
3. **物理内存是页框**：按需分配，缺页装入，满了置换；共享代码页，私有数据页 COW。

答题顺序：先判「这个对象在文件里有没有字节」→ 再判「在虚拟内存哪个段、可不可写」→ 最后判「物理页框什么时候分配、缺页怎么处理」。
