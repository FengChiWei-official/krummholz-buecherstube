# I/O 与链路计算：指标类型（元参考）

> **原材料（or/）**：用户列出的计算点（缓冲区、磁盘固有量、寻道、发到信道、链路、端到端）＋ 408 里能算的全部 I/O 与传输题 ＋ 计组内部的两条链（总线、流水线，§7）。**元参考**：不讲某个具体题，只把「这些计算其实只有六种指标、四种运算」抽出来。
> 一句话：**先认指标类型，再套运算；公式记不住没关系，类型认错必错。**

## 0. 六类指标（所有 I/O 与传输题只问这六个）

| 类型 | 定义式 | 典型量 | 运算 | 最常见的错 |
|---|---|---|---|---|
| **容量** | 层数 × 每层数 × 单元大小 | 磁盘容量、最大文件、缓冲区大小 | 乘法链 | 少乘一层（盘片 vs 记录面）、把 B 当 bit |
| **速率** | 数据量 ÷ 时间 | 数据率、磁盘传输率、带宽 | 除法 | 单位（B vs bit）、rpm → r/s 没除 60 |
| **延迟** | 各串行段之和 | 平均访问时间、RTT、端到端时延 | 加法 | 把并行段也加进去（单缓冲） |
| **效率** | 有用量 ÷ 总量 | 信道利用率、CPU 占用率、RAID 利用率 | 比例 | 分母漏项（ACK 时间、开销） |
| **并发** | 不等式约束 | 缓冲区大小、窗口大小、并行通道数 | $\ge$ / $\le$ | 单位不统一（bit vs 帧） |
| **瓶颈** | $\min$（各段速率） | 端到端吞吐 | 取最小 | 把瓶颈当平均 |

通用式（几乎所有题都是它的特例）：

$$T_{\text{总}}=\underbrace{\sum_{i}T_i^{\text{串行}}}_{\text{延迟}}+\underbrace{\frac{S}{R_{\text{瓶颈}}}}_{\text{发送/传输}}+\underbrace{T_{\text{排队}}}_{\text{可忽略时略}}$$

## 1. CPU 与 I/O 方式：算的是「CPU 时间占多少」

| 方式 | 谁在等 | CPU 开销公式 | 类型 |
|---|---|---|---|
| 程序查询 | CPU 轮询 | $T_{CPU}=N_{\text{查询}}\times t_{\text{一次查询}}$，$N_{\text{查询}}=$ 数据量 ÷ 每次传送量 | 速率（反向） |
| 程序中断 | CPU 每单元被打断一次 | $T_{CPU}=N_{\text{中断}}\times t_{\text{中断服务}}$ | 速率（反向） |
| DMA | 控制器搬块 | $T_{CPU}=t_{\text{预处理}}+t_{\text{后处理}}$（每块一次） | 延迟 |

三者的比较题永远落在同一句：**中断用 CPU 时间换并行度，DMA 用硬件换 CPU 时间**。求「最大数据率」时把公式倒过来即可——中断方式的上限是 $1/t_{\text{中断服务}}$ 个单元每秒。

## 2. 磁盘：固有属性先算，寻道与旋转再算

**固有属性（与访问顺序无关）**

| 量 | 公式 |
|---|---|
| 容量 | 记录面数 × 每面磁道数 × 每道扇区数 × 每扇区字节数 |
| 数据传输率 | 每道容量 × 转速（r/s），转速 $r=\text{rpm}/60$ |
| 平均旋转延迟 | 半圈 $=1/(2r)$ |
| 平均访问时间 | 平均寻道时间 + 平均旋转延迟 + 传输时间 |
| 位密度 / 道密度 | 每道位数 ÷ 道周长 / 磁道数 ÷ 径向长度 |

算例（7200 rpm，每道 100 扇区 × 512 B）：$r=120$ r/s，传输率 $=100\times512\times120\approx6.1$ MB/s，平均旋转延迟 $=1/240\approx4.2$ ms。

**寻道（与访问顺序有关）**

| 算法 | 判据 | 算法代价 | 要算的量 |
|---|---|---|---|
| FCFS | 到达顺序 | 无调度 | 总移动道数 |
| SSTF | 最近者优先 | 有饥饿 | 总移动道数 |
| SCAN（电梯） | 单向扫到底再反向 | 边界多走 | 总移动道数（含折返） |
| CSCAN | 单向扫，回程直接跳回起点 | 回程不算服务 | 总移动道数（无回程） |

结论型指标只有两个：**总移动道数**与**平均寻道长度 = 总移动 ÷ 请求数**。折返点是否计入、回程走不走，是这三种算法唯一的区别——也几乎是唯一的错点。

## 3. 缓冲区：算的是「串行段里有几段能并行」

设 每块：$C$ = CPU 处理，$T$ = 从设备读入缓冲，$M$ = 从缓冲送到用户区。

| 方案 | 每块时间 | 为什么 |
|---|---|---|
| 无缓冲 | $C+T+M$ 全串行 | 三段互斥 |
| 单缓冲 | $\max(C,\,T)+M$ | 处理与读入可重叠，传送仍独占 |
| 双缓冲 | $\max(C+M,\,T)$ | 传送也并进去了 |

**缓冲区大小的约束**（并发型，不是等式）：缓冲要吃掉「生产者与消费者的速率差 × 持续时长」。

$$S_{\text{缓冲}}\ \ge\ (R_{\text{生产}}-R_{\text{消费}})\cdot t_{\text{持续}}$$

速率相等时下界为 0，但实际至少留一块——这是「容错」而不是「计算」。

## 4. 信道与链路：四个量，两对必须分清

| 量 | 公式 | 注意 |
|---|---|---|
| 奈氏（理想低通） | $C=2W\log_2 V$ | 无噪声、码元数 $V$ |
| 香农 | $C=W\log_2(1+S/N)$ | $S/N$ 由 dB 换算：$10\log_{10}(S/N)$ |
| 发送时延 | 数据量 ÷ 发送速率 | 与距离无关 |
| 传播时延 | 距离 ÷ 传播速度（铜/光纤约 $2\times10^8$ m/s ≈ $5\ \mu s$/km） | 与数据量无关 |
| 时延带宽积 | 传播时延 × 带宽（bit） | 「管道里能装多少」，不是带宽 |

两对必须分清（也是计网最大的失分点）：

1. **发送时延 vs 传播时延**：前者是「把比特推出去」，后者是「比特在路上」。带宽大只缩短前者。
2. **带宽 vs 吞吐**：带宽是标称上限，吞吐是 $\min$(路径上各段带宽)——瓶颈型。

## 5. 端到端：效率型最多

| 场景 | 公式 | 类型 |
|---|---|---|
| 停等协议利用率 | $\dfrac{T_d}{T_d+RTT}$（$T_d$ 为发送时延，忽略 ACK 发送时间） | 效率 |
| 满速所需窗口 | $W\ \ge\ R_{\text{带宽}}\times RTT$（bit） | 并发 |
| 窗口下的有效数据率 | $\dfrac{W}{RTT}$ | 速率 |
| 序号位宽与窗口 | GBN：$W\le2^n-1$；SR：$W\le2^{n-1}$ | 约束 |
| 逐跳总时延 | $\sum$(每跳 发送 + 传播 + 处理 + 排队) | 延迟 |

停等利用率常被写成 $\frac{1}{1+a}$（$a=RTT/T_d$）——两个记号是同一件事，题目给哪个用哪个。

## 6. 文件与 RAID：乘法链，先定「一块能装几个」

| 量 | 公式 | 例（块 4 KB，指针 4 B） |
|---|---|---|
| 一块的指针数 | $n=$ 块大小 ÷ 指针大小 | 1024 |
| 一级索引最大文件 | $n\times$ 块大小 | 4 MB |
| 二级 / 三级 | $n^2\times$ / $n^3\times$ 块大小 | 4 GB / 4 TB |
| RAID0 / 1 / 5 容量 | $N$ / $N/2$ / $(N-1)$ × 单盘 | 5 盘 → 5 / 2.5 / 4 盘容量 |
| RAID5 利用率 | $(N-1)/N$ | 80% |

## 7. 总线与流水线：计组内部的两条「链」

这两块不属于 I/O 与网络，但指标与上面完全同型：**总线 = 一条被多方分时共享的链**（同一时刻只有一对主从在通信，时间整段相加，同 §4 的带宽/占用）；**流水线 = 一条串行工位链**（可重叠，只有填充段不可重叠，同 §3 的 $\max$ + 气泡）。推导与时空图画法见 [[流水线-时空图与性能指标]]，与其他并行技术的同构加速比见 [[并行技术-通用性质与各自的指标口径]]——本节只回答「归到哪一类、单位在哪、坑在哪」。

### 7.1 总线：一个速率、一个延迟、一个效率

记 $W$ = 数据线位数，$f$ = 总线时钟频率，$m$ = 每个时钟周期传送次数（DDR/双沿取 2），$T_b$ = 一个总线周期的时长（题给一拍即 $1/f$；若一个总线周期含 $n$ 拍，则 $T_b=n/f$）。

| 量 | 公式 | 类型 | 什么时候用 |
|---|---|---|---|
| 总线带宽（峰值） | $B=\dfrac{W}{8}\cdot f\cdot m$ | 速率 | 题问「最大数据率」 |
| 一次传输的占用 | $t=N\cdot T_b$（$N$ = 占用的总线周期数） | 延迟 | 题问「传完要多久」 |
| 单次传输的 $N$ | $N_{\text{addr}}+N_{\text{data}}$ | 延迟 | 地址与数据**分时复用**同一条通路 |
| 突发传输的 $N$ | $1+N_{\text{data}}$ | 延迟 | 块首一次地址，后续地址隐含递增 |
| 利用率 / 有效带宽 | $\eta=\dfrac{N_{\text{data}}}{N}$，$B_{\text{eff}}=\eta B$ | 效率 | 题问「实际能达到多少」 |

其中 $N_{\text{data}}=\dfrac{\text{数据位数}}{W\cdot m}$（除不尽向上取整）。

四个坑，按出现频率排：

1. **bit 与 Byte**：$W$ 是位、$B$ 是字节每秒——除以 8 只做一次。
2. **漏乘 $m$**：「每周期传送 2 次」「双沿触发」不乘，带宽直接砍半。
3. **地址周期加不加**：题面给单总线（分时复用）就加，给地址线与数据线独立就不加；这一句之差能让总时间差近一倍。
4. **峰值当有效**：问「实际能传多少」要乘 $\eta$，不是报 $B$。

算例（$W=32$、$f=100$ MHz、$m=1$，传 256 个 32 位字 $=1$ KB）：$B=4\text{ B}\times100\text{ MHz}=400$ MB/s；突发 $N=1+256=257$ → $t=2.57\ \mu s$、有效 $398$ MB/s；单次 $N=512$ → $t=5.12\ \mu s$、有效 $200$ MB/s。同一组硬件，只因「地址要不要各来一次」，有效带宽差一倍。

### 7.2 流水线：一条延迟主公式，其余都是除法

$$T=\sum_i s_i+(n-1)\tau,\qquad \tau=\max_i s_i\ (+\text{锁存器})$$

| 量 | 公式 | 类型 | 陷阱 |
|---|---|---|---|
| 流水线周期 $\tau$ | $\max_i s_i$ | **瓶颈** | 只由最慢段定；改快别的段，$\tau$ 不动 |
| 总时间 $T$ | $(n-1)\tau+\sum_i s_i$ | **延迟** | 非均匀段用 $\sum_i s_i$，不是 $k\tau$ |
| 吞吐率 $TP$ | $n/T$；峰值 $1/\tau$ | 速率 | 短程序到不了峰值 |
| 加速比 $S$ | $T_{\text{串}}/T=n\sum s_i/T$；均匀时 $\dfrac{nk}{n+k-1}$ | 效率 | 上界 $\min(k,n)$ |
| 效率 $E$ | $S/k=\dfrac{n}{n+k-1}$ | 效率 | 时空图占格比，$n\to\infty$ 才趋 1 |
| 气泡 $b$ | $T$ 加上 $b\tau$ | 延迟 | 每个气泡 $=1$ 拍，等价于「多一条指令」 |

两处说法要接回 §0：**$\tau$ 就是「瓶颈型取最小速率」取倒数**（最慢段决定稳态）；**$S$ 的上界 $k$ 是同一句话**——其他段再快，也只多出空转的格。

若题给分支行为：理想 $CPI=1$ 时，平均气泡 $=p_{\text{分支}}\cdot q_{\text{预测错}}\cdot m_{\text{罚拍}}$，于是 $CPI=1+p\,q\,m$——把气泡折成「每条指令多几拍」，仍归延迟型。

算例（与 [[流水线-时空图与性能指标]] §3 同一组参数，便于对表）：$k=5$、$n=100$、每段 2 ns → $T=208$ ns、$S=4.81$、$E=96.2\%$、$TP\approx0.48$ 条/ns。

## 8. 三种运算的识别口令

| 看到题干的词 | 类型 | 立刻做什么 |
|---|---|---|
| 「容量」「多少块」「最大文件」 | 容量 | 画乘法链，逐层数 |
| 「每秒」「速率」「带宽」 | 速率 | 统一到 bit 或 B，再除 |
| 「时间」「多久」「延迟」 | 延迟 | 列出所有串行段，逐段加 |
| 「利用率」「效率」「占 CPU 多少」 | 效率 | 分子分母都写全 |
| 「至少多大」「够不够」 | 并发/约束 | 写不等式，别写等式 |
| 「实际能达到多少」 | 瓶颈 | 取各段最小值 |
| 「总线带宽」「每拍传几次」 | 速率 | $W/8\times f\times m$；先定 $m$ 再算 |
| 「几个总线周期」「总线占用」 | 延迟 | 数**占用周期**（地址 $+$ 数据），不数数据个数 |
| 「加速比」「吞吐率」「效率」 | 效率 $+$ 速率 | $S=T_{\text{串}}/T$、$E=S/k$、$TP=n/T$ |
| 「停几拍」「气泡」「冒险代价」 | 延迟 | 每个气泡 $=1\tau$，直接加进 $T$ |

最后提醒一句：**单位是这类题的第一道关**。bit/B、rpm/r·s⁻¹、ms/s、dB/倍率，四组换算吃掉的分不比公式少。
