# 算法交叉比较：替换 × 调度 × 分配/回收（对照稿）

> **原材料（or/）**：把 408 里全部「选谁下台 / 选谁先做 / 放哪一块 / 何时解除」的算法摆成矩阵——替换（Cache/TLB/页/GC）、调度（CPU/磁盘）、分配（内存/页框/文件/空闲空间/Cache 写分配）、回收（分配的对偶：页框/缓存/块/连接）。**对照稿**：只做交叉，不复述单个算法；机制差异见 [[Cache-TLB-页替换-同构与分界]]，指标换算见 [[IO与链路计算-指标类型]]。
> 一句话：**四族各有自己的核心指标**——替换看命中率、调度看等待与寻道、分配看碎片与搜索代价、回收看回收代价与抖动。判据、信息、代价、失效四轴填完，表就是自己长出来的。

## 0. 四轴法

| 轴 | 问什么 | 决定 |
|---|---|---|
| 判据 | 用什么信号选下一个 | 算法家族（最近 / 最少用 / 最短 / 到达序） |
| 信息 | 这个信号要存哪、存多少位 | 精确还是近似（LRU 时间戳放不进页表 → Clock） |
| 代价 | 每次决策谁执行、多贵 | 硬件并行比较 vs 软件扫描 |
| 失效模式 | 会不会出现反常（Belady、饥饿） | 可证明的边界 |

## 1. 替换算法矩阵（四条链一起看）

| 算法 | 判据 | 需要的信息 | 谁执行 | 栈算法 | Cache | TLB | 页 / GC |
|---|---|---|---|---|---|---|---|
| OPT | 未来最久不用 | 未来访问序列（不可得） | — | 是 | — | — | 页（基准） |
| FIFO | 进入次序 | 队列（环形指针） | 皆可 | **否** | 有 | 有 | 页（有 Belady） |
| LRU | 过去最久未用 | 时间戳或栈 | 硬件可做 | 是 | **常用** | **常用** | 页（太贵） |
| LFU | 最少使用次数 | 计数器 | 软件 | **否** | 有 | 少 | 少 |
| 随机 | 任意 | 一个随机数 | 硬件极简 | 否 | 有 | 有 | 少 |
| Clock（二次机会） | 访问位 + 指针扫 | 每页 1 位 | 软件/硬件 | 否（近似 LRU） | 有 | 有 | **页主力** |
| 改进 Clock | (访问位, 修改位) 四级 | 每页 2 位 | 软件 | 否 | — | — | **页（省写回）** |

三条交叉结论：

1. **只有栈算法免于 Belady**：OPT 与 LRU 是栈算法，帧数增加缺页数不增；FIFO、LFU、随机都不是。这就是「FIFO 有 Belady 异常」的严格来源，而不只是经验现象。
2. **精度由「判据要存多少位」决定**：Cache 候选只有 $n\le16$ 行，存精确次序可负担；页有 $10^5$ 个，每页只能给 1 位 → Clock。**不是 Clock 更先进，是预算更紧**。
3. **同族不同应用**：LRU 在 Cache/TLB 是硬件常态，在页里只能当基准或近似目标；两者的差别全在 [[Cache-TLB-页替换-同构与分界]] §4 那四条分界（谁处理、代价、粒度、候选集）。

Belady 反例（FIFO，引用串 $1,2,3,4,1,2,5,1,2,3,4,5$）：

| 帧数 | 缺页次数 | 说明 |
|---|---|---|
| 3 | 9 | 基准 |
| 4 | **10** | 帧变多，缺页反而多 |

同期用 LRU 算同串：3 帧 10 次、4 帧 8 次，单调不增。原因不是巧合——**栈算法的定义就是：$m$ 帧内的页面集合恒为 $m+1$ 帧内集合的子集**，所以加帧只可能少缺页。FIFO 不满足这条包含关系，才出现了 9→10。

## 2. CPU 调度矩阵

| 算法 | 判据 | 抢占 | 优化目标 | 饥饿 | 408 要算 |
|---|---|---|---|---|---|
| FCFS | 到达序 | 否 | 公平、无开销 | 无 | 周转、等待（护航效应） |
| SJF | 服务时间最短 | 否 | 平均等待最小（同时到达时） | **有** | 平均周转/等待 |
| SRTN（抢占 SJF） | 剩余时间最短 | **是** | 平均等待最小 | **有** | 甘特图 + 逐段剩余 |
| HRRN | 响应比 $=(W+S)/S$ | 否 | 兼顾长短（防饥饿） | 无 | 每次选择算响应比 |
| RR | 轮转，时间片 $q$ | **是** | 响应时间 | 无 | 甘特图、$q$ 的影响 |
| 优先级 | 优先级值 | 可抢占/不可 | 按重要性 | **有**（低优先级） | 抢占点判断 |
| 多级反馈队列 | 队列级 + 时间片递增 | 是 | 兼顾响应与吞吐 | 可调 | 逐队列降级过程 |

四条必须记住的性质：

1. **SJF 的最优性有条件**：同时到达时平均等待最小；到达时间不同时，「最短」要按剩余（SRTN）才算。
2. **$q$ 的两个极端**：$q\to\infty$ 退化为 FCFS，$q\to0$ 变成切换开销主导——RR 的题永远在问这个区间内的行为。
3. **HRRN 是「防饥饿的 SJF」**：等待越久响应比越高，长作业最终会被选中。
4. **抢占点**：新进程到达、时间片用完、优先级变化——甘特图错位几乎都错在这三处之一。

| 算法 | 判据 | 可"就近插入" | 折返 / 回程 | 饥饿 | 要算的量 |
|---|---|---|---|---|---|
| FCFS | 请求序 | 否 | — | 无 | 总移动道数 |
| SSTF | 最近磁道 | **是**（等价抢占） | — | **有** | 总移动道数 |
| SCAN（电梯） | 单向扫到端点 | 是（沿途顺路） | 端点折返 | 无 | 含折返的移动量 |
| CSCAN | 单向扫到端点 | 是 | 回程直接跳回起点（不计服务） | 无 | 无回程的移动量 |
| LOOK | 扫到最远请求即返 | 是 | 最远请求处折返 | 无 | 不扫空段 |
| C-LOOK | 单向 + 直接跳回最小请求 | 是 | 回程不计 | 无 | 教材扩展 |

## 4. 分配矩阵：连续分区四算法

「放哪一块」的第一层是**内存连续分配**——四个算法只差在「从哪开始找、挑哪个空洞」。

| 算法 | 判据 | 搜索方式 | 碎片去向 | 失效模式 |
|---|---|---|---|---|
| 首次适应 FF | **第一个**够大的空闲区 | 按地址递增线性扫 | 外部 | 低地址越切越碎，搜索变慢 |
| 邻近适应 NF（循环首次） | 从**上次结束处**起找第一个够大的 | 环形扫 | 外部 | 空间分布均匀了，但大空洞被切散 |
| 最佳适应 BF | **最小**够用的空闲区 | 需全表（或按容量排序） | 外部 | 留下大量微小不可用碎片 |
| 最坏适应 WF | **最大**的空闲区 | 需全表（或大顶堆） | 外部 | 大空闲区被消耗，大作业后来进不来 |

教材结论：**首次适应通常综合最好**——最简单、最快、且倾向于把大空闲区留在高地址。最佳适应「看起来最省」但碎片化最严重，这是四个算法里最反直觉的一条。

## 5. 分配矩阵：结构选择（连续 / 非连续 / 文件 / 空闲空间）

**A. 非连续分配：碎片类型的判据**

| 方式 | 切分 | 产生的碎片 | 翻译代价 |
|---|---|---|---|
| 固定分区 | 等长但预先划分 | **内部** | 无 |
| 动态分区 | 变长按需 | **外部**（需紧凑） | 无 |
| 分页 | 等长 | **内部**（最后一页） | 页表一次 |
| 分段 | 变长逻辑 | **外部** | 段表一次 |
| 段页式 | 先段后页 | 内部（页内） | 两次 |

一句话判据：**等长切分 → 内部碎片；变长切分 → 外部碎片。** 段页式之所以要把段套在页上，就是用「页内的内部碎片」换掉「段间无法消除的外部碎片」。

**B. 页框分配策略（虚拟内存）**

| 策略 | 分配 | 置换范围 | 后果 |
|---|---|---|---|
| 固定分配局部置换 | 每进程帧数固定 | 本进程 | 帧数难定：少了抖动，多了浪费 |
| 可变分配全局置换 | 动态 | **全局** | 可能抢别人的帧 → 连锁缺页 |
| 可变分配局部置换 | 动态 | 本进程 | 兼顾，需工作集估计 |

帧数分配算法（平均 / 按比例 / 按优先级）只是这三种策略里的一个参数，考概念不考算术。

**C. 文件分配（外存）**

| 方式 | 结构 | 随机访问 | 碎片 | 元数据代价 |
|---|---|---|---|---|
| 连续分配 | 起始块 + 长度 | $O(1)$ | **外部** | 无 |
| 链接·隐式 | 每块尾部存下一块指针 | $O(n)$ | 无 | 指针吃掉块内空间 |
| 链接·显式（FAT） | 链接表单独存放并常驻内存 | $O(1)$ 查表 | 无 | **FAT 占内存** |
| 索引（单级/多级/混合） | 索引块存块号 | $O(1)\sim O(k)$ | 无 | 索引块开销 |

三种方式的取舍轴是**随机访问 vs 元数据开销 vs 碎片**，三选二：连续最快但有外部碎片；链式无碎片但随机访问差；索引两头兼顾但要占索引块（最大文件大小的计算见 [[IO与链路计算-指标类型]] §6）。

**D. 空闲空间管理**

| 方法 | 结构 | 分配代价 | 408 计算点 |
|---|---|---|---|
| 空闲表 | 连续空闲区的表 | 查表 + 拼接 | 拼接后的表项 |
| 空闲链表 | 链式串空闲块 | 遍历 | 遍历次数 |
| **位示图** | 每块 1 位 | 位扫描（可加速） | **块号 ↔ (字号, 位号)** |
| 成组链接 | 组长块 + 组内链接 | 常数级 | 组链结构 |

位示图换算是这类题的唯一公式（字长 $n$ 位、块号从 0 起）：字号 $=\lfloor b/n\rfloor$，位号 $=b\bmod n$；若块号从 1 起，则字号 $=\lfloor (b-1)/n\rfloor+1$，位号 $=(b-1)\bmod n+1$。

**E. Cache 的写分配**（分配策略在 Cache 层的实例）

| 写未命中策略 | 动作 | 常配对的写策略 |
|---|---|---|
| 写分配（write allocate） | 先把块取上来再改 | 写回（write back） |
| 非写分配（no-write-allocate） | 直接写主存，不取块 | 写直达（write through） |

## 6. 回收：分配的对偶

分配建立「编号 → 物理」的映射，回收解除它。但**回收 ≠ 删除**，判据只有一条：

> **回收后能否原样重建？** 能 → 回收（后备还在）；不能 → 删除（连后备一起取消）。

| 资源 | 虚拟化手段 | 回收单位 | 处置 | 后备（重建源） | 触发 |
|---|---|---|---|---|---|
| 页框 | 虚存 + 页表 | 页 | 脏页写回 swap/文件，干净页直接丢 | swap 区、文件 | 按需（缺页）+ 后台（低水位） |
| 页表页 | 多级页表 | 页 | 空表页回收 | VMA 可重建 | 撤销映射时 |
| Cache 行 | tag / 组号 | 块 | 脏块写回 | 主存 | miss 时替换 |
| TLB 项 | VPN + ASID | 项 | 直接失效（无写回） | 页表 | 替换、上下文切换 |
| SSD 物理页 | FTL | 块（GC 时） | 块级擦除 | LBA 映射（数据已搬走） | GC 触发 / TRIM |
| 磁盘块 | 空闲空间管理 | 块 / 簇 | 直接释放 | **无**（数据消失） | 删除、截断 |
| 缓冲池块 | 池 | 块 / 对象 | 丢弃（可重读） | 源数据 | 池满、超时 |
| 文件描述符 / 连接 | 表 | 项 | 关闭 | 可重开 | 进程退出、超时 |
| DHCP 租约（类比） | 地址池 | 地址 | 到期收回 | 可再分配 | 租约到期 |

**三级处置，代价递增**：

| 级 | 条件 | 动作 | 例子 |
|---|---|---|---|
| 丢 | 干净 / 有副本 | 解除映射即可 | 干净页、TLB 项、缓冲池 |
| 写回 | 脏 | 先落后备再解除 | 脏页、脏块、改进 Clock 优先淘汰 (0,0) |
| 擦除 | 块级、介质要求 | 整块擦除 | SSD 的 GC |

这条链解释了三个「策略为什么长这样」：改进 Clock 为什么先淘汰 $(访问位,修改位)=(0,0)$；数据库 checkpoint 为什么先刷脏页；SSD 为什么把「丢弃（TRIM）」与「擦除（GC）」拆成两级。

**两类触发**：

| 触发 | 时机 | 优点 | 代价 | 失效形态 |
|---|---|---|---|---|
| 按需 | 缺页 / 池满才回收 | 不浪费带宽 | 延迟尖峰 | 抖动（回收速度 < 需求速度） |
| 后台 | 低水位、周期扫描 | 平滑 | 持续占带宽 | 预回收过多 → 又被用掉 |

三条结论：

1. **回收粒度必须等于分配粒度**，否则回收出来的东西不能用（页框对页、SSD 块对擦除、簇对文件块）。
2. **over-commit 是前提**：虚拟量 > 物理量，回收才有意义；后备不足时策略只剩「降级」——OOM、拒绝连接、限流。
3. **看稳态，不看单次代价**：抖动就是「回收速率 < 分配速率」的稳态崩溃，与调度里的饥饿、替换里的 Belady 属同一类「策略使系统进入病态」。

## 7. 四族交叉：判据同构，指标不可移植

| 维度 | 替换（谁下台） | 调度（谁先做） | 分配（放哪块） | 回收（何时解除） |
|---|---|---|---|---|
| 判据 | 最近 / 最少用 / 未来 | 最短 / 到达序 / 轮转 / 优先级 | 最先 / 最佳 / 最坏 / 结构 | 能否重建 + 处置级（丢 / 写回 / 擦） |
| 核心指标 | 命中率、缺页率 | 周转、等待、响应、磁头移动 | **碎片率、搜索代价、利用率** | 回收代价、回收率、抖动 |
| 典型失效 | Belady、抖动 | 饥饿、护航效应 | 外部/内部碎片、分配失败 | 抖动、OOM、写放大 |
| 元数据成本 | 1–2 位/项 | 队列与就绪表 | 表/位图/索引块 | 脏位、访问位、引用计数 |
| **能否事后补救** | 不能 | 不能 | **能**：紧凑、碎片整理 | **它本身就是补救**：回收是分配失败的兜底 |

最后一行是这一族的分水岭：替换与调度的决定一旦做出就写进历史，分配有「整理」这个动作（内存紧凑、磁盘碎片整理），而**回收本身就是补救动作**——它是分配失败时的兜底：物理量不够，就从已分配的资源里要回来。SSD 的 GC 因此可两读：选块看是替换，搬页看是回收。

| 对应关系 | 真同构 | 不能类推之处 |
|---|---|---|
| FCFS ↔ FCFS | 同一条「到达序」判据，都是基准 | 磁盘无「周转时间」概念，只算磁头位移 |
| SJF ↔ SSTF | 都是「最短/最近优先」，都**饥饿** | SJF 的服务时间已知且固定；磁盘请求的「距离」随磁头位置动态变化 |
| 最佳适应 ↔ ？ | 都追求「不浪费」 | BF 的代价是碎片，不是命中率——指标不在一个坐标系 |
| SCAN / LOOK ↔ **无** | 常被类比成「轮转」，但对象不同 | SCAN 轮的是**空间**（磁道），RR 轮的是**时间**（CPU） |

**指标不可移植**是这条线上最大的越界：CPU 调度算 周转 / 带权周转 / 等待 / 响应；磁盘调度只算 **总移动道数** 与 **平均寻道长度**；分配算 **碎片与搜索代价**。把「平均周转时间」套到磁盘调度、或把「命中率」套到分区分配上，答案必然是错的。

## 8. 指标公式（四族各一套）

| 族 | 指标 | 公式 |
|---|---|---|
| CPU | 周转时间 | 完成 − 到达 |
| CPU | 带权周转 | 周转 ÷ 服务 |
| CPU | 等待时间 | 周转 − 服务 |
| CPU | 响应时间 | 首次开始 − 到达 |
| CPU | 平均值 | $\sum/n$，题问「平均」时答案必须是平均 |
| 磁盘 | 总移动道数 | $\sum\lvert \text{本道} - \text{上次道}\rvert$ |
| 磁盘 | 平均寻道长度 | 总移动 ÷ 请求数 |
| 磁盘 | 平均访问时间 | 平均寻道 + 平均旋转延迟 + 传输（见 [[IO与链路计算-指标类型]] §2） |
| 分配 | 碎片率 | 内部/外部碎片字节 ÷ 分区总量 |
| 分配 | 搜索代价 | 一次分配扫描的表项数：FF/NF 线性、BF/WF 全表 |
| 分配 | 内存利用率 | 已分配字节 ÷ 总分区块（连续分配时分母含不可用碎片） |
| 回收 | 回收代价 | 丢弃 ≈ 常数；写回 = 一次后备写；擦除 = 块级搬迁（含写放大） |
| 回收 | 回收率 | 单位时间回收的页/块数（与分配速率比较才是判据） |
| 回收 | 抖动判据 | 回收速率 < 缺页（分配失败）速率 → 系统进入抖动 |
