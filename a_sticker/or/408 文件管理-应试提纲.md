## 1. 术语骨架（先把词对齐，后面全是它的展开）

| 408 术语          | 是什么                                           | 常见考法                 |
| --------------- | --------------------------------------------- | -------------------- |
| **文件**          | 具名的相关信息集合，是逻辑上最小的分配单位                         | 文件 vs 记录 vs 数据项 的层次  |
| **FCB**         | 文件控制块：名字 + 类型 + 位置 + 大小 + 时间 + 权限 + 指针        | 目录项里放 FCB 的优缺点       |
| **索引结点**（inode） | 把 FCB 里「除名字外」的元数据抽出成独立结构，目录项只留 `名字 + inode 号` | 为什么减少磁盘访问            |
| **目录项**         | 目录文件中的一条记录（磁盘结构！）                             | 与内存缓存区分，见 §11        |
| **目录**          | 目录项的集合，本身也是一个文件                               | 单级/两级/树形/图形          |
| **用户打开文件表**     | 每进程一张：`fd → 系统表项指针`                           | fd 是这张表的下标           |
| **系统打开文件表**     | 全局一张：打开计数、读写位置、访问权限、inode 指针                  | 多次 open / fork 的偏移语义 |
| **内存索引结点**      | inode 被读入内存后的副本，供打开文件表指向                      | 与目录项、与系统表项的区别        |

一句话链：**路径 → 目录项 → inode → 物理块**。每一跳都是一次可能的磁盘访问，所有 I/O 次数题都在数这条链。

## 2. 文件的逻辑结构（用户视角）

| 结构 | 组织 | 检索代价 | 适用 |
|---|---|---|---|
| 无结构（流式） | 字节流，无记录边界 | 由应用自己定 | 可执行文件、文本 |
| 顺序文件·串结构 | 记录按写入顺序 | 顺序查找平均 $(N+1)/2$ 次 | 批量追加 |
| 顺序文件·顺序结构 | 记录按关键字排序 | **折半 $\log_2 N$** | 定长记录、需快速检索 |
| 索引文件 | 建索引表，表项指向记录 | 查索引后直接定位；索引表本身有序可折半 | 变长记录 |
| 索引顺序文件 | 分组：组内顺序 + 组间索引 | 平均约 $\sqrt{N}$ | 大文件折中 |
| 直接文件（哈希） | 关键字 → 地址 | 理想 $O(1)$，有冲突 | 按名直取 |

易错：**逻辑结构决定「怎么找记录」，物理结构决定「记录落在哪些块」**。两者可以任意组合，题目问「哪种结构支持随机访问」时先分清问的是哪一层。

## 3. 目录

### 3.1 结构演进与各自解决的问题

| 结构 | 解决什么 | 遗留问题 |
|---|---|---|
| 单级目录 | 最基本：一张表 | 重名冲突；查找 $O(N)$ |
| 两级目录 | 主目录（用户）+ 用户目录 | 用户间不能共享、不能分组 |
| 树形目录 | 层次、路径、当前目录 | 不能共享同一文件 |
| 无环图目录 | 硬链接共享 | 需引用计数；不能有环 |
| 通用图目录 | 允许环 | 需环检测/垃圾回收，遍历要防重复 |

### 3.2 两种实现

| 实现 | 查找 | 插入/删除 | 备注 |
|---|---|---|---|
| 线性列表 | $O(N)$，需逐项比较 | 简单 | 小目录实际更快（无哈希计算） |
| 哈希表 | 期望 $O(1)$ | 需处理冲突、扩容 | 大目录；哈希值需由文件名算出 |

### 3.3 目录项里放什么（高频计算）

| 方案 | 目录项大小 | 影响 |
|---|---|---|
| 目录项直接含 FCB | 大（几十~上百字节） | 一个盘块装的项少 → 查找要读更多盘块；打开时还要把 FCB 拷进内存 |
| 目录项只含 `名字 + inode 号` | 小（约 16 B） | 一个盘块装更多项 → **平均读盘次数下降**；inode 单独按号读取（可缓存） |

模板题：目录 640 项、盘块 4 KiB、FCB 式目录项 64 B、inode 式 16 B。

- FCB 式：$640\times64=40$ KiB → 10 块 → 平均查 5 块（顺序查找，命中位置均匀）
- inode 式：$640\times16=10$ KiB → 3 块 → 平均约 1.5 块
- 再各自 + 1 次读 inode + 1 次读数据块；若 inode 已在内存则不+1

注意「平均」= 一半，题目问「最多/最少」时分别取满/取 1。

一次 open 要读几次盘的完整记账见 §16.5。

## 4. 文件共享与保护

### 4.1 硬链接 vs 软链接

| 维度 | 硬链接 | 软链接（符号链接） |
|---|---|---|
| 本质 | 新目录项指向**同一 inode** | 新文件，内容是**目标路径字符串** |
| 链接计数 | inode 上 `count` 加 1 | 不增加目标计数 |
| 目标删除后 | 数据仍可访问（count 未到 0） | **悬空**，访问报错 |
| 跨文件系统 | 不行（inode 号只在各自 FS 内有效） | 可以 |
| 指向目录 | 一般不许可（防环） | 可以 |
| 访问开销 | 与普通文件相同 | 多一次路径解析 |

具体到 inode 号与删除后的结果，见 §16.6。

### 4.2 打开文件表的共享语义（必背）

| 操作             | 系统打开文件表         | 读写位置   | 结论                      |
| -------------- | --------------- | ------ | ----------------------- |
| 同一进程 `open` 两次 | **两项**          | 各自独立   | 一个读完不会让另一个接着读           |
| `fork` / `dup` | **共享同一项**，计数 +1 | **共享** | 子进程读走 4 字节，父进程从第 5 字节继续 |
| 两个进程各自 `open`  | 两项              | 独立     | 互不影响                    |
| 关闭 fd          | 计数 −1，到 0 才删项   | —      | 计数不为 0 时 inode 与数据都还在   |

这条和 Linux 的 `struct file` / `f_ref` 完全同构（见 §11），408 只考表项与计数。

### 4.3 保护

- 访问类型：读 / 写 / 执行 / 追加 / 删除 / 列目录。
- 访问控制矩阵：按**行**拆 → 能力表（每主体一张"我能动谁"）；按**列**拆 → 访问控制表 ACL（每对象一张"谁能动我"）。
- 口令、加密：开销小但粒度粗 / 强度高但每次访问解密。
- Linux 九位 `rwx rwx rwx`：属主、组、其他；数字 4/2/1。
- 目录权限的特例：**`x` 表示可进入/可搜索路径**，`r` 才表示可列目录项；只有 `r` 没有 `x` 能列出名字却不能访问其下文件。

## 5. 文件系统的层次结构（自上而下 7 层）

| 层 | 做什么 | 输入 → 输出 | 常见问法 |
|---|---|---|---|
| 用户接口 | 接系统调用 | 路径/句柄 → 请求 | 「谁处理 open 请求」 |
| 文件目录系统 | 按路径查目录项，得 inode | 路径 → inode | 「路径名 → 索引结点」 |
| 存取控制验证 | 查权限 | 用户 + inode → 允许/拒绝 | 「权限检查在哪层」 |
| 逻辑文件系统与文件信息缓冲区 | 记录号 → 逻辑块号；缓冲区管理 | 逻辑记录 → 逻辑块 | 「逻辑结构在哪层生效」 |
| 物理文件系统 | 逻辑块号 → 物理块号 | 逻辑块 → 物理块 | **最常考：块号转换** |
| 辅助分配模块 | 空闲块的分配与回收 | 需要块 → 块号 | 「位示图/成组链接由谁管」 |
| 设备管理模块 | 调设备驱动、发起 I/O | 物理块 → 磁盘操作 | 「哪层碰硬件」 |

记法：**路径 → 权限 → 逻辑 → 物理 → 分配 → 设备**；上层只给请求，下层只给块。

## 6. 文件的物理结构（= 分配方式）

### 6.1 三种基本方式

| 方式 | 目录项/结构 | 随机访问 | 第 $i$ 块访问代价 | 问题 |
|---|---|---|---|---|
| 连续分配 | 起始块 + 长度 | ✅ 直接算 $start+i$ | 1 次（目录已在内存） | **外部碎片**；增长要搬迁 |
| 隐式链接 | 每块末尾存下一块指针 | ❌ 只能顺序 | $i$ 次读盘 | 指针占空间（可用 $B-4$）；可靠性差 |
| 显式链接（FAT） | 指针集中在 FAT 表，**常驻内存** | ✅ 查表在内存进行 | 1 次（表在内存） | FAT 表占内存；表大小 = 块数 × 表项 |
| 索引分配 | 每文件一个索引块（块号数组） | ✅ | 1 次索引块 + 1 次数据块 | 小文件索引块浪费；大文件要多级 |

**适用判据（三问）**：文件长度会不会变？访问以顺序为主还是随机为主？介质能不能原地改写？

| 判据 | 连续分配赢在 | 连续分配输在 |
|---|---|---|
| 长度固定、不可原地改写 | 没有增长/搬迁问题 | — |
| 顺序读为主 | 整段连续，寻道/跳转最少 | — |
| 需要随机访问 | 目录项只存「起始块 + 长度」，第 $i$ 块 $O(1)$ | 删除留洞 → **外部碎片**，要紧缩 |
| 文件频繁增删 | — | 搬迁与碎片整理成本高 |

经典例子：**CD-ROM（只读光盘）**。刻录时布局一次成形，ISO 9660 目录项就是「起始 LBA + 长度」；之后不能原地改，文件不会增长；主要用途是顺序读（音轨、视频、安装镜像），而光驱随机定位要移动光头并等 CLV 转速调整，代价远高于顺序读。三个条件全中，连续分配是唯一合理选择。

反例：通用磁盘的文件会增长、会删、会并发写，所以用「多段连续」折中——ext4 的 extent、NTFS 的 runs 本质都是把连续分配切成若干段，段内仍是 $O(1)$ 定位。

### 6.2 FAT 表大小（必考）

表项数 = 磁盘块数；表项宽度取「能表示最大块号」的最小字节数（4 B 常见）。

例：1 TB 盘、块 4 KiB → $2^{28}$ 块 → 表项 $2^{28}\times4\text{B}=1$ GiB。**FAT 是每盘/每分区一张，不是每文件一张。**

8 块盘、8 个格子的 FAT 表见 §16.1——那一张表就能看出「链在内存里追」。

### 6.3 索引分配的三档

设块大小 $B$、指针 $p$ 字节，索引块可放 $n=\lfloor B/p\rfloor$ 个指针。

| 形式 | 最大文件 |
|---|---|
| 单级索引 | $n\times B$ |
| $k$ 级索引 | $n^k \times B$ |
| 混合索引（UNIX: 10 直接 + 1 一级 + 1 二级 + 1 三级） | $(10+n+n^2+n^3)\times B$ |
| 链接索引 | 多个索引块串起来，按需读，支持大文件但不能一次定位 |

模板：$B=4$ KiB、$p=4$ B → $n=1024$。

- 最大文件 $=(10+1024+1024^2+1024^3)\times4\text{KiB}$
- $=2^{30}$ 块 × 4 KiB + $2^{20}$ 块 × 4 KiB + $1024$ 块 × 4 KiB + 10 块 × 4 KiB
- $=4$ TiB + 4 GiB + 4 MiB + 40 KiB

访问偏移换算（inode 已在内存）：直接块覆盖 40 KiB；一级间接覆盖到 4 MiB+40 KiB；二级间接覆盖到 4 GiB。所以访问 1 GiB 处 → **读 1 个二级间接块 + 1 个一级间接块 + 1 个数据块 = 3 次 I/O**。inode 不在内存则 +1。

## 7. 空闲空间管理

### 7.1 位示图

每位对应一个物理块（0 空闲 / 1 分配，**以题目声明为准**）。

- 容量：块数 bit = 块数/8 字节；按字长 $w$ 计需 $\lceil \text{块数}/w\rceil$ 个字
- 换算（0 起）：字号 $=\lfloor b/w\rfloor$，位号 $=b\bmod w$；（1 起要先把块号减 1）
- 例：$2^{28}$ 块、字长 32 → $2^{23}$ 个字 = 8 Mi 个字（32 MiB）；块 1000 → 字号 31、位号 8

一个字节装 8 个块的位示图见 §16.2。

### 7.2 成组链接

- 空闲块按每组 100 块分组，**每组有一块携带下一组的块号与块数**；内存超级块/专用块只保存当前这一组。
- 分配：从栈顶取一块；若取的正是携带下一组信息的那块，先把它的内容读进内存成为新的一组，再把它分配出去。
- 回收：栈未满（<100）直接压栈；栈已满（=100）则把栈中 100 个块号写进新回收的块，该块成为新组链块，栈中只留它一个。
- 代价：$N$ 个空闲块、每组 $k$ → 分配穷尽需 $N/k$ 次读盘。

把 100 缩成 3 的分组例子（含完整分配顺序）见 §16.4。

### 7.3 空闲链表

所有空闲块串成链（可成组）。分配/回收简单，但**要顺序找**，且链指针占块内空间。

## 8. 磁盘

### 8.1 结构与地址

盘片 → 磁道（同心圆）→ 扇区；同半径的磁道集合 = **柱面**。

- 地址三元组：`(柱面号, 盘面号, 扇区号)`；按柱面优先编号 → 减少寻道。
- 容量 = 盘面数 × 每道扇区数 × 扇区大小 × 磁道数。

### 8.2 存取时间

$$\text{存取时间}=\underbrace{\text{寻道时间}}_{ \text{移动磁臂} }+\underbrace{\text{旋转延迟}}_{ \text{等扇区转到头下} }+\underbrace{\text{传输时间}}_{ \text{读写} }$$

- 平均旋转延迟 = **半圈** = $\dfrac{1}{2}\cdot\dfrac{60}{r}$ 秒（$r$ 为 rpm）
- 例：7200 rpm → 一圈 8.33 ms → 平均旋转延迟 4.17 ms
- 传输时间 = $\dfrac{\text{读取字节数}}{\text{传输率}}=\dfrac{\text{扇区数}}{\text{每道扇区数}}\times$ 一圈时间

### 8.3 调度算法

| 算法 | 规则 | 缺点 |
|---|---|---|
| FCFS | 按请求顺序 | 磁头来回跑 |
| SSTF | 每次选最近的 | **可能饥饿**；贪心不一定最优 |
| SCAN（电梯） | 单向扫到**端点**再反向 | 端点附近请求被优待 |
| LOOK | 扫到**最远请求**就反向（不到端点） | — |
| C-SCAN | 单向扫，回程**快速返回不服务** | 回程是否计入要看清 |
| C-LOOK | 只扫到最远请求，然后跳回最小请求继续单向 | — |

算例（磁道 0–199，磁头 100，请求 30/50/90/120/180，递增方向）：

| 算法 | 顺序 | 总移动 |
|---|---|---|
| FCFS | 30→50→90→120→180 | 220 |
| SSTF | 90→120→180→50→30 | 250（**比 FCFS 差**：贪心陷阱） |
| SCAN | 120→180→199→90→50→30 | 268 |
| LOOK | 120→180→90→50→30 | 230 |
| C-SCAN | 120→180→199→\*0→30→50→90 | 189（不含回程）/388（含 199 道回程） |
| C-LOOK | 120→180→\*30→50→90 | 140（不含跳回） |

$\sum|\text{下一道}-\text{当前道}|$ 就是总移动；乘每道寻道时间再加旋转与传输即总时间。**起点方向、端点、回程是否计入**这三件事题目一定会给，别自己假设。

### 8.4 减少旋转延迟的布局技巧

- 交替（交错）编号：单缓冲隔 1 个扇区编号、双缓冲隔 2 个，避免「处理完一个扇区，下一个已转过去，要等一整圈」。
- 目的只有一个：**减少旋转延迟**，不是减少寻道——这是最常见的错误选项。

## 9. 磁盘管理

| 步骤 | 做什么 |
|---|---|
| 低级格式化（物理） | 划分磁道/扇区，写扇区头尾与校验，设定交错因子；出厂/整盘一次 |
| 分区 | 把盘划成独立区域，写分区表（MBR：446 引导代码 + 64 分区表 + 2 结束标志 = 512 B） |
| 高级格式化（逻辑） | 建文件系统：超级块、空闲空间管理结构、根目录、inode 表/FAT |

- **引导块**：ROM 中的自举程序读 0 号块（引导扇区）→ 装入引导程序 → 装入 OS。含引导块的分区叫活动分区。
- **坏块**：硬件法（扇区备用、重映射）；软件法（FAT/位示图标记、保留区）。低级格式化发现的坏块用备用扇区替换，对 OS 透明。

### 盘上布局（全局结构，理解即可）

| 区 | 内容 |
|---|---|
| 引导块 | 自举代码 |
| 超级块 | 文件系统整体参数：块大小、总块数、inode 数、空闲块数、状态 |
| 空闲空间管理 | 位示图 / FAT / 成组链接的组链块 |
| inode 表 | 索引结点数组（UNIX 系） |
| 根目录 | 目录树起点 |
| 数据区 | 文件块 |

## 10. 提高文件访问速度

| 手段 | 机制 | 代价/风险 |
|---|---|---|
| 磁盘缓存（页缓存） | 内存保存最近读写的磁盘块 | 占内存；写回策略影响一致性 |
| 提前读（read-ahead） | 顺序访问时预取下一块 | 随机访问时浪费 |
| 延迟写（write-back） | 攒批再写，减少 I/O | 掉电丢数据 |
| 优化物理布局 | 连续分配、簇、按柱面组织 | 碎片管理成本 |
| 虚拟盘（RAM disk） | 内存模拟磁盘 | 掉电全丢，容量受限 |

## 11. Linux 对照（**不考**，只做记忆锚）

| 408 概念 | Linux 实现 | 差异提示 |
|---|---|---|
| FCB / 索引结点 | `struct inode`（560 B 头 + FS 私有尾） | 语义相同：身份 + 元数据 + 块映射 |
| 目录项（磁盘记录） | 目录文件的**数据块内容** | ⚠️ 不要和 `dentry` 混：`dentry` 是**内存缓存对象**（192 B），不是磁盘结构 |
| 系统打开文件表 | `struct file`（每次 open 一条，`f_pos` 偏移，`f_ref` 计数） | 与 408 的系统表项一一对应 |
| 用户打开文件表 | `files_struct` 内联 64 槽 + `fdtable` | fd 就是数组下标 |
| 内存索引结点 | inode 缓存（`inode_hashtable`，按 `(sb, ino)` 哈希） | 可回收，按需从盘重读 |
| 超级块 | 盘上超级块 + `struct super_block` | 挂载实例的全局描述 |
| 位示图 | 块位图 / inode 位图 | 同理：位号 ↔ 块号 |
| 成组链接 | ext4 块组 + 组描述符 | 思路同源（分组 + 链） |
| 混合索引 | 早期 ext2/3 间接块；现代 ext4 用 extent | 考试按间接块算，实现已换 |

细节见 [[ISA 与 OS 的数据结构与内存分布]]。

## 12. 易错点清单（考前 10 分钟扫这一段）

1. 平均旋转延迟 = **半圈**；一圈时间 = $60/r$ 秒。
2. 传输时间跟「读多少扇区」和转速有关，别漏。
3. 索引块能放 $n=\lfloor B/p\rfloor$ 个指针——**向下取整**，剩下的是浪费。
4. 混合索引最大文件要算 $10+n+n^2+n^3$，别忘直接块；单位换算 TiB/GiB/MiB。
5. FAT 表 = 块数 × 表项宽，**每分区一张**，且常驻内存（所以随机访问快）。
6. 位示图「字号/位号」按块号从 0 还是 1 起，题目一定明说；1 起要先减 1。
7. 成组链接分配时，携带下一组信息的那块要**先读进内存再分配**；回收满 100 块才生成新组链块。
8. 硬链接删到计数 0 才释放数据；软链接目标删了就悬空。
9. `fork` 后父子**共享**读写位置；两次 `open` 各自独立。
10. 目录项改为「名字 + inode 号」减少的是**目录扫描的读盘次数**，inode 本身仍要读一次。
11. SCAN 到端点，LOOK 到最远请求；C-SCAN 回程不服务（是否计入距离看题）。
12. 交替编号针对**旋转延迟**，不是寻道。
13. 连续分配是**外部碎片**；索引/链接分配的浪费在指针与索引块。
14. 低级格式化写扇区结构，高级格式化建文件系统结构；引导块在 0 号块。
15. 文件「逻辑结构」是记录组织，「物理结构」是块分配；「随机访问」问题要分清问哪层。
16. 目录 `x` 权限 = 可进入/搜索；只 `r` 不可访问下级。
17. 系统打开文件表存**读写位置**，inode 不存（inode 存大小/位置/权限）。
18. 索引分配支持随机访问，但大文件要走多级间接，访问代价随级数增加。
19. 「随机访问」≠「随机播放」：**只读 + 定长 + 跳跃式播放 → 连续结构**（2013 真题 24：CD-ROM 视频随机播放，答案 A 连续结构）。理由：跳转要 $O(1)$ 定位，跳转之后又是一长段顺序流，只有连续同时满足；索引还要先多读一次索引块，光盘上一次寻道就是几十毫秒。

## 13. 三道模板题的完整写法（照着抄格式）

**T1 最大文件**：块 8 KiB、指针 8 B、inode 有 12 直接 + 1 一级 + 1 二级。

- $n=\lfloor 8192/8\rfloor=1024$
- 最大 $=(12+1024+1024^2)\times8\text{KiB}=1036\times8\text{KiB}+1024^2\times8\text{KiB}$
- $=8288\text{ KiB}+8\text{ GiB}\approx8.01$ GiB（写清每一项来源，别把 1036 块当成 1 MiB 糊过去）

**T2 访问偏移的 I/O 次数**：同上参数，inode 已在内存，访问 20 KiB 处。

- 直接块覆盖 $12\times8=96$ KiB → 20 KiB 落在直接块 → **1 次读数据块**。
- 若访问 5 MiB：直接 96 KiB 之后，一级间接覆盖 $1024\times8\text{KiB}=8$ MiB → 仍在一次间接 → 1 次索引块 + 1 次数据块 = **2 次**。

**T3 调度距离**：见 §8.3 算例，答题时先写「起点、方向、端点、回程口径」再列顺序与距离。

## 16. 最小例子（先把图像建起来）

> 每节一个小到能口算的例子。公式都是这些例子的放大版：先把 8 块盘走一遍，再看 4 TiB 就不会晕。

### 16.1 FAT 表最简形态（8 块盘）

盘只有 8 个块，FAT 就是 **8 个格子的数组**：每格存「下一块」的块号，`FF` = 到此为止，`00` = 空闲。目录项只记首块。

| 块号 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 用途 | 保留 | 空闲 | A 第 1 块 | B 第 1 块 | 空闲 | A 第 2 块 | A 第 3 块 | B 第 2 块 |
| FAT 值 | `FF` | `00` | `05` | `07` | `00` | `06` | `FF` | `FF` |

- 目录项：`A → 首块 2，长度 3 块`；`B → 首块 3，长度 2 块`。
- 读 A 的第 3 块：`2 → FAT[2]=5 → FAT[5]=6 → FAT[6]=FF` 停。**3 次查表全在内存，只有最后 1 次读盘。**
- 删除 A：把 `FAT[2]`、`FAT[5]`、`FAT[6]` 清零即可——所以 FAT 删除快、恢复难。
- 对比隐式链接：同样三块，指针在每块末尾，读第 3 块要**真的读盘 3 次**。FAT 的全部价值就是把这条链搬进内存。
- 表大小：8 块 × 1 B 表项 = 8 B；表项换 4 B 就是 32 B。公式只有一句「块数 × 表项宽」。

### 16.2 位示图（一个字节 8 块）

`1 = 占用`，bit $i$ 对应块 $i$。占用块 0、2、5、6：

| 位号 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 值 | 1 | 0 | 1 | 0 | 0 | 1 | 1 | 0 |

- 这一字节 = `0b0110_0101` = `0x65`；空闲块 = 1、3、4、7。
- 分配最小空闲块：找第一个 0 → 块 1 → 置 1 → 变成 `0x67`。
- 字号/位号（字长 8）：块 5 → 字号 0、位号 5。字长 32 时块 1000 → 字号 31、位号 8。

### 16.3 索引分配（6 块文件）

块 256 B、指针 4 B → 每个索引块装 64 个指针；inode 有 4 个直接块 + 1 个间接块。

- 文件 6 块：直接块 `8,9,10,11`；间接块 14 的内容是 `[12, 13, 0, …]`。
- 读第 5 块 = 读索引块 14 + 读块 12 → **2 次盘**（inode 已在内存）。
- 上限 = $(4+64)\times256\text{B}=17$ KiB。换成 4 KiB 块、4 B 指针、10 直接 + 三级间接，就是 §6.3 的 $4\text{ TiB}+4\text{ GiB}+4\text{ MiB}+40\text{ KiB}$。

### 16.4 成组链接（每组 3 块）

把「每组 100 块」缩成 3 块，链就看得见了。每组第一个块是**组链块**，记录下一组：

| 组 | 可分配块（栈内顺序） | 组链块里记的下一组 |
|---|---|---|
| 1 | 11, 12, 10 | 13, 14, 15（存在块 10 里） |
| 2 | 14, 15, 13 | 16, 17, 18（存在块 13 里） |
| 3 | 17, 18, 16 | 空 |

内存超级块栈 = `[11, 12, 10]`（栈顶先分配）。装载规则：**携带下一组信息的那一块放栈底**，所以它总是最后才被分配——这保证「读下一组」发生在「交出组链块」之前。

- 分配顺序：`11 → 12 → 10`；拿 10 之前**先读 10 的内容**得到 `13,14,15` 入栈，然后才把 10 交出去 → `14 → 15 → 13`（同理会读 13）→ `17 → 18 → 16`。
- 回收：栈已满 3 个时，把栈里 3 个块号写进新回收的块，该块成为新组链块，栈 = `[x]`。
- 代价：9 个空闲块分 3 组 → 分配穷尽要 3 次读盘。

### 16.5 一次 open 的读盘记账

`/a/b/c.txt`，每级目录占 1 块，全都没缓存：

```
读根目录块      → 得到 a 的 inode 号
读 a 目录块     → 得到 b
读 b 目录块     → 得到 c 的 inode 号
读 c 的 inode   → 得到首块号
读 c 的数据块   → 内容
= 5 次读盘
```

每命中一次目录项缓存或 inode 缓存，就减一次；这也是「目录项改成 名字+inode 号」能提速的原因——它减少的是**前三次**里的块数。

### 16.6 硬链接与软链接（具体到 inode 号）

| 名字 | 目录项指向 | 说明 |
|---|---|---|
| `a.txt` | inode 7 | 数据 `hello`，nlink = 2 |
| `b.txt` | inode 7 | 硬链接，与 a.txt 是同一个 inode |
| `c.txt` | inode 9 | 软链接，inode 9 的内容是字符串 `/a.txt` |

- `rm a.txt`：摘掉一条目录项，`nlink` 2→1；`b.txt` 照常读到 `hello`。
- 此时访问 `c.txt`：解析 `/a.txt` 失败 → **悬空**，报错。
- 再 `rm b.txt`：nlink 归 0，数据块与 inode 7 才真正释放。

### 16.7 超级块最小九字段

| 字段 | 例值 |
|---|---|
| 魔数 | `0xEF53` |
| 块大小 | 1024 B |
| 总块数 | 8192 |
| 空闲块数 | 6542 |
| inode 总数 | 2048 |
| 空闲 inode 数 | 2036 |
| inode 表起点 | 块 98（占 98–609） |
| 根目录 inode 号 | 2 |
| 文件系统状态 | clean |

这些值不是编的：本机 `mkfs.ext4 -b 1024 8MiB` 造出的镜像里就是 8192 块、2048 个 inode、6542 空闲块、inode 表在块 98；块位图在 66、inode 位图在 82（`dumpe2fs` 可读，具体数字随 mkfs 版本变）。超级块的全部作用就是**让挂载方不必扫描整盘**。

### 16.8 删除一个文件的三步

```
1. 摘目录项：名字 → inode 号 这一条消失（路径不再可达）
2. inode 链接计数 -1
3. 计数归 0 且没有打开者 → 释放数据块（位示图/FAT 清零）+ 释放 inode
```

只要第 3 步的「没有打开者」不成立，数据就还在——这就是「文件删了但空间没回来」的全部机制。
