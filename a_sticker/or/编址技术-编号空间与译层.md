# 编址技术：编号空间与译层（元参考）

> **原材料（or/）**：用户口述的「编址元问题」提纲，加上计组 ch3/ch4、OS ch3、计网 ch4 的既有材料对照。**元参考**：它不是某一个考点，而是把「编号 → 位置」这件事在所有层上的共同结构抽出来；单层细节见各层自己的笔记。
> 一句话：**编址 = 一个编号空间 + 一层译 + 一段等长偏移**。三个问题定一切：一个编号多大、中间隔几层、查不到时谁付钱。

## 0. 三个问题（任何编号都问这三句）

| 问题 | 决定什么 | 变了会怎样 |
|---|---|---|
| 一个编号多大（粒度） | 编号总数 = 空间 ÷ 粒度 | 块 64 B vs 页 4 KB：同一空间，编号位数差 6 位 |
| 中间隔几层译 | 谁在查表，查几次 | 0 层 = 直连；1 层 = 页表；k 层 = 多级页表 |
| 查不到时谁付钱 | 失效代价与处理者 | Cache miss 由硬件、缺页由 OS，差 3–4 个数量级 |

这三问既能解释「为什么这样切」，也能立刻定位「408 里这句话错在哪」——错答通常是把某一层的粒度、层数或失效代价搬到另一层上。

## 1. 计组里所有的编号点（一张总表）

| 编号空间 | 一个编号对应 | 位宽由谁定 | 译层 | 何时翻译 | 失效后果 |
|---|---|---|---|---|---|
| 硬件地址（内存） | 一个存储单元 | 地址线根数 | 片内行/列译码 + 片选译码 | 每次访存 | 无（最底层） |
| 物理地址 PA | 主存里一个单元 | 物理地址线 | 无（终点） | — | — |
| 虚拟地址 VA | 页号 + 页内偏移 | 虚拟地址宽度、页大小 | MMU + 页表 | 每次访存 | 缺页 → OS |
| 页框号 PPN | 一个物理页 | 物理内存 ÷ 页大小 | 页表项内容 | — | — |
| 寄存器号 | 一个寄存器 | 指令格式里的字段宽度 | 寄存器堆译码 | 译码时 | 无（编码非法则报错） |
| I/O 端口号 | 一个端口 | 统一编址（并入地址空间）或独立编址 | 地址译码 / IN-OUT 指令 | 每次 I/O | 无 |
| 中断向量号 | 一个服务程序入口 | 向量表长度 | 向量表（表项 = 入口地址） | 响应时 | 未定义向量 |
| Cache 行 | tag + 组号 + 块内偏移 | Cache 容量、块大小、相联度 | 硬件比较器 | 每次访存 | miss → 装块 |
| 磁盘 CHS | 柱面/磁头/扇区 | 盘面数、道数、每道扇区 | 磁盘控制器 | 每次 I/O | 寻道失败 |
| LBA | 一个扇区 | 扇区总数 | 控制器固件 | I/O 时 | 坏块重映射 |
| 文件逻辑块 | 一个块（整数个扇区） | 文件系统块大小 | inode / 位图 | read/write | 需分配 |
| IP 地址 | 一个接口 | 前缀 + 主机号 | 路由表 | 每一跳 | 不可达 |
| MAC 地址 | 一个接口 | 48 位固定 | 交换机表 | 每条链路 | 泛洪 |

横向读这张表，规律只有两条：

1. **相邻两层的偏移宽度往往相同**（等长中间层，§4）；
2. **越靠上，失效代价越大、处理者越"软"**（软件 → OS → 硬件），这条和 [[Cache-TLB-页替换-同构与分界]] 的分界线是同一条。

## 2. 逐层：同一个字节的五种编号

以一个字节为例，从程序到磁盘，它能被叫出五个名字：

| 层 | 名字 | 结构 | 谁会说这个名字 |
|---|---|---|---|
| ① 虚拟地址 | VA | VPN + 页内偏移（32 位 → 20 + 12） | 程序、指令、汇编 |
| ② 物理地址 | PA | PPN + 页内偏移（28 位 → 16 + 12） | MMU、Cache 控制器 |
| ③ Cache 位置 | tag + 组号 + 块内偏移 | $19+7+6=32$ | Cache 硬件 |
| ④ 磁盘位置 | CHS 或 LBA | 柱面/磁头/扇区 或 线性扇区号 | 磁盘控制器 |
| ⑤ 文件位置 | 逻辑块号 + 块内偏移 | 块号由 inode 的索引结构给出 | 文件系统 |

两个不变量：

- **②③ 的块内偏移就是 ①② 的页内偏移的低位**（块 64 B、页 4 KB ⇒ 低 6 位相同）。原因是块对齐在页内，不是巧合。
- **①→② 只翻高位**：页内偏移直接穿过。这就是为什么 Cache 的 tag/组号必须取自 **PA** 而不是 VA（PIPT）——低位不参与翻译，高位已被改写。

磁盘侧同理：文件逻辑块 → LBA 只翻块号，块内偏移穿过；LBA → 扇区编号只翻扇区号，扇区内偏移穿过。**每插一层，翻译的位段就往上收一段**。

## 3. 编址的物理实现：用中介层换布线

把一个编号变成一个物理位置，只有四种手法：

| 手法 | 选择线 | 器件 | 延迟 | 例子 |
|---|---|---|---|---|
| **one-hot**（单热） | 每个目标一根，$2^n$ 根 | 无 | 0 级 | 每片一根 CS、总线 grant、单热编码状态机 |
| **译码器**（$2^n$ 空间映射） | $n$ 根输入 → $2^n$ 根输出 | 1 个译码器 | 1 级 | 片选 2-4 译码、行/列译码 |
| **多级树** | $n$ 位分段，每级一张小表 | $k$ 级表 | $k$ 次访存 | 多级页表、目录树、B+ 树 |
| **内容寻址**（无 index） | 无选择线，全并行比较 | 比较器阵列 | 1 级但贵 | 全相联 Cache、TLB |

**中介层减少布线**是这张表的主题：

- one-hot：线数 $O(2^n)$，逻辑最简、零延迟——只在目标少或必须最快时用（片选直连、三态选择）。
- 译码器：把 $2^n$ 根压成 $n$ 根 + 一个器件，$n\to2^n$ 的**唯一收益就是线数**，代价是一级延迟。
- 多级树：把「一张 $2^{20}$ 项的表」压成「两次访存 + 两张小表」，收益是**空间**（多级页表），代价是更多次访存。
- 内容寻址：不压缩线数，直接消除 index——所以只有候选集小的时候敢用（全相联、TLB）。

同一条轴，三种压缩对象：**译码器压线数、多级树压表大小、CAM 压查找级数**。408 的存储器扩展题全落在前两格。

## 4. 编址的逻辑实现：等长中间层的六个好处

「等长」指：**上层一个单位 = 下层整数个单位，且切分点对齐**。等长的直接后果是**偏移不变**——翻译只需改写高位，低位原样穿过。

| 中间层 | 上层编号 | 下层编号 | 等长点 | 收益 |
|---|---|---|---|---|
| 虚拟内存 | VPN | PPN | 页内偏移不变 | 隔离、容量解耦、共享、COW、权限 |
| 磁盘重映射 | LBA | 扇区 | 扇区等长（512 B/4 KB） | 坏块重映射、RAID、快照、虚拟磁盘 |
| 文件系统 | 逻辑块 | LBA | 块 = 整数个扇区 | 碎片管理、稀疏文件 |
| 页缓存 | 页 | 文件块 | 页 = 整数个块 | 与虚存共用回收机制 |

六个好处可以归成三对：

1. **改名不改号**：重定位、迁移、扩容后程序里的编号不用重算（编译期编号 ≠ 运行期物理位置）。
2. **容量与身份解耦**：虚拟空间可以大于物理空间（虚存）、逻辑卷可以跨盘（LVM/RAID）——编号空间先定，再决定底下放几个物理设备。
3. **可插入策略**：因为中间那层是一张表，所以能在表项上挂标志位——有效位、权限位、脏位、共享计数。**没有表就没有策略**，这是「OS 能管内存」的结构性原因。

**反例（中间层不等长）**：分段是变长切分，段长由程序决定 → 翻译要加段基址、空隙要拼接 → 外部碎片。所以段页式是「先按逻辑分段，再按等长分页」，把不等长的那层套在等长层之上。

**对照（不是等长层）**：IP/CIDR 是前缀聚合，前缀长度可变，路由查表要最长前缀匹配——它压缩的是**路由表规模**，不是偏移。把它和虚存并称「同构」是比喻，不是结构。

## 5. 编号的算术：寻址方式也是编址

有效地址的计算，本质是**两个编号空间之间的线性变换**：

| 寻址方式 | 运算 | 编号含义 |
|---|---|---|
| 直接 | $EA=A$ | 同一空间内的常量偏移 |
| 基址 / 变址 | $EA=(R)+A$ | 以寄存器为原点的相对编号 |
| 相对 | $EA=(PC)+A$ | 以「下一条指令」为原点——基准是取指后的 PC，不是本条地址 |
| 段:偏移 | 段基址 + 偏移 | **二维编号压成一维**，压的过程就是一次译层 |

最后一行值得单列：段式之所以是「二维」，正因为它的两个编号分量语义不同（段 = 逻辑单位，偏移 = 段内位置），一次加法就是那个译层。

## 6. 指令编码：字段即编号，译码即译层

一条指令就是**一张位段表**，每个字段都是一个独立的小编号空间：

| 字段 | 编号什么 | 位数 | 译层 |
|---|---|---|---|
| opcode | 操作（指令种类） | $\lceil\log_2(\text{指令数})\rceil$ | 译码器 → 控制信号 |
| rs / rt / rd | 寄存器 | $\lceil\log_2(\text{寄存器数})\rceil$ | 寄存器堆的读写选择 |
| funct / 扩展位 | 操作码的细分 | 按需 | 二级译码（与 opcode 合看） |
| imm / 偏移 / 地址 | 数据或地址 | 由寻址方式定 | 进入 §5 的算术 |

所以「取指 → 译码」这一步的实质是：**把指令字里的位段各自送去各自的译层**。字段宽度不是任意的，它由「编号空间的容量」反推——这和「容量 → 地址线根数」是同一条公式。

### 6.1 水平型 vs 垂直型微指令：同一个编号空间的两种压缩

微指令是「控制信号空间」的一次编码。两种格式的差别，只在**一位管几个信号**：

| 维度 | **水平型**微指令 | **垂直型**微指令 |
|---|---|---|
| 一位管几个控制信号 | 1 位管 1 个（直接编码时） | 一个字段管多个，需字段内译码 |
| 微指令字长 | 长（控制信号多） | 短 |
| 并行度 | 高：一条微指令可同时给多个部件发信号 | 低：常需多条微指令串行完成 |
| 译层深度 | 0–1 级 | 深（字段译码，甚至间接再查表） |
| 微程序条数 | 少（一条干更多事） | 多 |
| 与 §3 对照 | ≈ one-hot | ≈ 译码器 / 多级树 |

三种微指令编码方式正是「译层深度」的三个刻度：

| 编码方式 | 一个字干什么 | 译层 | 对应 §3 的手法 |
|---|---|---|---|
| **直接编码** | 每一位就是一个控制信号 | 0 级 | one-hot |
| **字段直接编码** | 字段内互斥信号共用一个字段，字段需译码 | 1 级 | 译码器 |
| **字段间接编码** | 字段的含义还要再查一次表 | ≥2 级 | 多级树 |

这正是 §4 那条「等长中间层」在控制侧的同构：**压缩微指令字长，代价是增加译层**；反过来，字长换译层。多级页表用「多一次访存」换「表变小」，微指令用「多一级译码」换「字变短」——同一条交换。

### 6.2 控制存储器：又一张「编号 → 内容」的表

微地址是「微指令空间」的编号，控制存储器（CM）是它的表：

```
微地址 ──► CM（表）──► 微指令字 ──► 译码/直接驱动 ──► 控制信号
   ↑
微地址形成部件（下址字段 + 顺序 + 分支条件）  ← 微指令自身的位段又是一个编号空间
```

于是控制通路也落进 §0 那三问：**编号多大**（微地址位数 = $\log_2$ CM 字数）、**隔几层译**（直接编码 0 层，字段编码 1 层）、**查不到怎么办**（微地址越界 = 非法微指令，硬件异常）。

### 6.3 正名

「水平 / 垂直」是**微指令**的分类词，不用于机器指令格式。考题若写「水平型指令编码」，指的是微指令的编码方式（或微指令字长取向），不是指令字长的另一种格式。

## 8. 边界：什么时候「同构」是假的

三处不能类推：

1. **失效代价跨层不可比**：Cache miss ≈ 100 周期、缺页 ≈ $10^5$ 周期，所以 Cache 敢用精确 LRU、页置换只能近似（[[Cache-TLB-页替换-同构与分界]] §4）。
2. **位宽不守恒**：VA 32 位 → PA 28 位是正常的，地址空间大小与物理内存大小互相独立（[[标准错误答案清单]] 已有此错答）。
3. **策略位只住在"表"上**：虚拟内存有页表所以有权限位；Cache 有行所以有 V/D 位；IP 没有"表项"（路由表是转发用的，不是地址的一部分），所以 IP 地址本身不带策略。
