# IO 通路 · 实体与总线

> **原材料（or/）**：AI 整理的 408 计组 ch7 参考资料，待消化成卡。考纲口径见 [[计算机组成考纲]] 第七章；本文不写电路电气细节与寄存器位域。

## 0. 一句话

I/O = 把「值由外部决定的位置」投影进地址空间。

对 CPU 而言，I/O 与访存是**同一个动作**——读/写一个地址。差别只有两条：**地址译码落到哪个空间**（端口空间还是存储空间）、**数据何时有效**（主存总是准备好，设备不一定）。

此定义抄自 [[抽象硬件系统与它的 IO 约定]] §二，本篇只把它实体化：那「一个地址」沿线依次落在谁手里，每层各自用什么单位说话。

## 1. 六层实体

判据：每一层只回答两个问题——**谁给它地址**、**谁解释位串**。

| 层 | 实体 | 单位 | 谁给它地址 | 谁解释位串 |
|---|---|---|---|---|
| 设备 | 盘片/磁头、键盘矩阵、帧缓冲 | 扇区、字符、像素 | 无地址；由控制器寻址 | 设备自身 |
| 设备控制器 | 状态/数据/控制寄存器 + 局部缓冲 | 寄存器宽度、DMA 块 | CPU 或驱动 | 控制器固件 |
| I/O 接口与端口 | 端口地址、握手信号线 | 端口字节/字 | CPU 的 `in`/`out` 或 MMIO | 接口逻辑 |
| 总线 | 事务 {地址, 读/写, 数据, 控制} | 总线宽度 32/64 位 | 主设备 + 仲裁器 | 协议 |
| 桥 / 内存控制器 / MMU | 地址窗口与重映射 | 物理地址 | 硬件 | 硬件 |
| 内存与 CPU | cache line / 字 | 64 B / 字 | 硬件 | 硬件 |

层数不是设计口味，是**速率差约六个量级**逼出来的：机器节拍在 ns 级，盘和人在 ms 级，中间必须有人缓冲、有人翻译、有人替它等（见 [[计组融贯性诊断]] 的根张力表）。

## 2. 数据实体链

```mermaid
flowchart LR
    B["字节"] -->|"控制器：凑成一个扇区 512 B / 4 KiB"| S["扇区"]
    S -->|"块层：2^k 个扇区成块，给出 LBA"| L["逻辑块"]
    L -->|"fs / MMU：页成为映射单位"| P["页"]
    P -->|"DMA：整块搬进内存，不经 CPU"| Buf["缓冲区"]
    Buf -->|"驱动：拷入用户空间或直接映射"| U["用户虚拟地址"]
```

不变量：位串在层间只被**重新分组**，内容不变。这是同一张「表示先于电路 / 透明性」的实例——每层只认自己的单位，看不见上层的含义。

一次 `read(fd, buf, 4096)` 走过的实体路径（把上面五条边落成动作）：

| 步 | 谁 | 动作 | 单位 |
|---|---|---|---|
| 1 | fs | 把文件偏移换成「哪几个逻辑块」 | 逻辑块 |
| 2 | 块层 | 合并/排序，写成一次 I/O 请求 | LBA 区间 |
| 3 | 驱动 | 把请求写成控制器命令：读哪几个扇区、搬到哪个内存地址 | 扇区 + 物理地址 |
| 4 | 控制器 | 寻道/旋转/读盘，DMA 把整块写进内存，完成后发中断 | 扇区 → 内存块 |
| 5 | 内核 | 把页里的数据拷到 `buf`（或直接映射），唤醒等待的进程 | 页 → 用户虚拟地址 |

注意第 3 步：**驱动唯一要给出的东西是「设备内地址」和「内存地址」**——这条链上没有任何一层知道这 4096 字节是文本还是坐标。

链接：[[Sector]] · [[Logical Block]] · [[Page Table]]。

## 3. 三种地址

| 名字 | 谁产生 | 典型值 | 谁译码 |
|---|---|---|---|
| 端口地址 | 指令给出（独立编址） | `0x60` | 芯片组 |
| 物理地址 | CPU 算出（统一编址 / MMIO） | `0xFEE00000` | 地址译码器 |
| 设备内部地址 | 控制器固件 | 柱面/磁头/扇区 | 控制器 |

[[Physical Address as Global Identity]] 已给出判据：**物理地址 ≠ 内存地址**——物理空间里混着 DRAM 与设备寄存器；CPU 对外只发物理地址，翻译在片内完成。

## 4. 编址方式（考纲 ch7 第一问）

| 方式 | 地址空间 | 访问指令 | 优点 | 缺点 | 典型 |
|---|---|---|---|---|---|
| 统一编址（存储器映射） | 与主存共用一个地址空间 | 普通 load/store，可用全部寻址方式 | 无需专门 I/O 指令、编程灵活 | 占主存地址空间、需译码区分设备与内存、程序里难分辨访存与 I/O | ARM、RISC-V、PCIe BAR |
| 独立编址（I/O 映射） | 独立的端口空间 | 专用 `in`/`out` | 不占主存空间、I/O 指令短、程序易区分、I/O 地址线少译码简单 | 需专用指令、寻址方式受限、需额外 `M/IO̅` 类控制信号 | x86 |

判据一行：看有没有**独立的 I/O 指令**与**独立的端口地址空间**。有 = 独立编址；只有普通访存指令能用 = 统一编址。真机上两者可并存（x86 既有 MMIO 也有端口空间），所以「哪种编址」问的是**这次访问走哪条路**。

## 5. IO 与总线

1. **事务四要素** {地址, 读/写, 数据, 控制}：主设备发起，从设备应答。读是「给地址，收回数据」，写是「给地址 + 数据，收回应答」。
2. **为什么多主**：DMA 控制器与网卡要自己搬数据，不能永远等 CPU 代劳；多方竞争唯一的总线，于是必须有**仲裁**（集中式 / 分布式）。这是「异步与差错边界」的必然结果，不是额外功能。
3. **定时**：同步（统一时钟，快，距离短）与异步（握手，慢，距离长）——同一条总线上不同设备速率差太大，握手才通用。
4. **中断请求是总线的旁路**：它不产生地址事务，只拉一根信号线；CPU 在指令边界采样（详见 [[中断与异常-机制]] §3）。
5. **北桥已消失**（2009 起内存控制器进片内）：判据落在「谁译码地址」，不落在芯片名字（[[Physical Address as Global Identity]] 的修正条）。

## 6. 三个根张力 → 三种机制

| 张力 | 机制 | 本篇落点 |
|---|---|---|
| 异步（不同源） | 握手、中断、仲裁 | §5 |
| 速率差（不同速） | 缓冲、DMA、中断 | [[IO 方式-条件与状态转移]] |
| 可能出错（差错边界） | 校验、超时、重试 | 只记一句：与「数据没准备好」共用同一套流程——暂停主线、委托慢的一方、回来续上 |

## 7. 与文件系统实体文的同构

[[Links of File System Entities]] 写的是「设备 → 块层 → fs → OS，每层一个单位」；本篇写的是「设备 → 控制器 → 接口 → 总线 → 内存，每层一个单位」。两者做的是同一个动作：把上一层的请求翻译成下一层的单位，翻译时只关心单位，不关心内容。

差别只有一条：**FS 的层是软件分配出来的**（`mkfs` 定块大小、inode 定索引方式，可以改），**I/O 的层是电路与协议约束出来的**（总线宽度、扇区大小、握手时序，改了就是换硬件）。所以文件系统的层次表可以重画，I/O 的层次表只能遵守。
