# IO 方式 · 条件与状态转移

> **原材料（or/）**：AI 整理的 408 计组 ch7 参考资料，待消化成卡。考纲口径见 [[计算机组成考纲]] 第七章；本文不写电路电气细节与寄存器位域。

## 0. 判据：谁在等

四种方式不是四种技术，而是「**等待**」的四种处理：

| 方式 | 谁在等 | CPU 在此期间 |
|---|---|---|
| 程序查询 | CPU 自己等 | 空转轮询状态寄存器 |
| 程序中断 | 谁也不等，设备反过来通知 | 去跑别的程序 |
| DMA | 谁也不等，搬运工自己在搬 | 预置参数后去跑别的程序 |
| 通道 | 谁也不等，且一次能搬一组 | 只发一条启动命令 |

一句话：**问题从来不是「怎么搬数据」，而是「设备慢、CPU 快，这段差值记在谁账上」**。

## 1. 三种考纲方式

| 方式 | 谁发起传输 | 传输单位 | 完成通知 | CPU 介入 | 数据通路 | 适用 |
|---|---|---|---|---|---|---|
| 程序查询 | CPU | 字/字节 | 无，CPU 反复读状态 | 每单位一次 | 经 CPU 寄存器 | 极低速，或设备总是就绪 |
| 程序中断 | 设备 | 字/字节 | 中断 | 每单位一次服务 | 经 CPU 寄存器 | 低速、随机到达 |
| DMA | DMA 控制器（CPU 只预置） | 块 | 中断，仅结束/出错 | 每块两次（初始化 + 收尾） | 设备 ↔ 内存直接 | 高速块设备 |

DMA 的「直接」指**不经过 CPU 寄存器**，但**要占用总线**——它没有让总线变快，只是让 CPU 不必逐字参与（[[IO 通路-实体与总线]] §5 第 2 条）。

## 2. 条件 → 转移

| 当前 | 条件 | 转移到 | 谁做 |
|---|---|---|---|
| 执行指令 | 查询到设备就绪 | 读/写数据 | CPU（软件循环） |
| 执行指令 | 设备就绪 + 中断请求 + 未屏蔽 + 开中断 + 指令结束 | 中断响应（隐指令 → 服务程序） | 硬件 |
| 执行指令 | DMA 请求 + 总线空闲 | 让出总线 / 挪用周期 | 仲裁器 + DMA 控制器 |
| 运行 | 发起 I/O 且不忙等 | 阻塞 | 内核（系统调用） |
| 阻塞 | I/O 完成中断 | 就绪 | 内核（中断处理出口） |
| 运行 | 时间片到 / 更高优先级到来 | 就绪 | 内核（调度） |

表里第 2 行的四个条件是中断响应的判据，写在 [[中断与异常-机制]] §3.2，本表只挂一行，不重复推导。第 4–6 行是进程状态机的边，与 `[[Process State]]` 同一件事：**I/O 方式决定了等待记在谁的账上，谁在等就决定了状态怎么转**。

## 3. 查询 vs 中断：代价判据

- 查询浪费的周期 ≈ 轮询次数 × 读状态的开销。
- 中断的代价 ≈ 每单位一次隐指令（压 PC/PSW、跳转）+ 服务程序的进出。

判据是比较这两个量：**事件密度 × 单次服务开销** 与 **轮询周期的倒数** 谁大。设备几乎总是就绪、事件极密（如逐字符的极低速设备），查询更省——因为它省掉了「每单位一次上下文进出」；事件稀疏且不可预测（键盘、磁盘完成），中断更省——因为等待期间 CPU 能去跑别的程序。

边界：具体数值计算归真题，本篇只给判据；考纲的计算题问的都是「谁等了多少时间」，把它记在等的一方的账上就不会错。

## 4. DMA 的三种工作方式

| 方式 | CPU 访存影响 | 适用 |
|---|---|---|
| 停止 CPU 访存 | CPU 停止，整块期间不访存 | 简单、块大；浪费 CPU |
| 周期挪用（周期窃取） | DMA 抢一个存取周期，CPU 该周期延后但状态不丢 | 主流；块不大且 CPU 要并行工作 |
| 交替访问 | CPU 与 DMA 分时使用总线（各占半个存取周期） | 透明 DMA，硬件代价高 |

### 4.1 DMA 与中断的四点区别

| 维度 | DMA | 中断 |
|---|---|---|
| 请求对象 | 总线 | CPU 的处理 |
| 响应时机 | 一个存取周期结束即可 | 一条指令执行结束 |
| 数据通路 | 设备 ↔ 内存（不经 CPU 寄存器） | 经 CPU 寄存器 |
| 优先级 | 高于中断，且不受中断屏蔽字约束 | 受屏蔽字与优先级裁决 |

第四点是考点：**屏蔽字管的是中断源，不是总线主设备**——DMA 请求不是中断请求，所以「屏蔽了所有中断」并不阻止 DMA 抢总线。

## 5. 边界：通道

通道是能执行**通道程序**的 I/O 处理器，CPU 只发启动/停止，一串块搬完才通知一次。它把「每块一次中断」降为「每组一次」，是把控制权下放给专门状态机的极限形态。

408 考纲只到 DMA，通道只作趋势记忆锚（同 [[抽象硬件系统与它的 IO 约定]] §二 的「搬运不需要智能」：下放到极致，就是给它一套指令）。

## 6. 效率口径

所有 I/O 效率题的骨架只有一句：**算出在总时间里，CPU 有多少比例在等**。查询 = 全程等；中断 = 只在每单位的服务时间被占用；DMA = 只在初始化与收尾被占用。所以 CPU 开销恒为 查询 > 中断 > DMA（效率与吞吐的顺序反之）。等待期间谁在跑，由 [[Multiprogramming]] 回答。
