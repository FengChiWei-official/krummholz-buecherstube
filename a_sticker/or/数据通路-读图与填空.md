# 数据通路：图怎么读、空怎么填

> 暂存稿（`a_sticker/or/`）。用途：408 里「给一张数据通路图 $+$ 挖几个空」这类题，给一套固定顺序的读图法与填空判据。自己搭路（只给部件清单、按算法画图）的口径在 [[标准错误答案清单]] 第五章那条，本篇不重复。
> 状态：**只讲不写**。口径：[[计算机组成考纲]] 第四章/第五章；单总线、多总线、MIPS 三型通用。

## 〇 结论先行

1. 图里只有**六种笔画**：线、三态门、MUX、寄存器、变换器、存储器/寄存器堆。认全它们，图就变成可读的句子。
2. **读图 = 找时序边界**（谁在哪一拍被锁存），不是找线。线只回答「值从哪来」，沿才回答「什么时候算数」。
3. 空只有**五类**：缺线、缺控制信号、缺部件、缺位宽、缺节拍。每类有唯一判据，不靠印象。
4. 最硬的两条判据：**一个输入口只有一个来源**（两个来源必须过 MUX）、**一条总线同一时刻只有一个驱动者**。这两条否决绝大多数「随手多连一根线」。
5. 写完必过**八项自查**；其中「地址只从 MAR/PC 出」「读写使能与数据同拍」各值 2 分。

## 一 图的语法：六种笔画

| 笔画 | 画法 | 语义 | 读图时的动作 |
|---|---|---|---|
| **线** | 细线 $+$ 单向箭头 | 值流动；分叉 $=$ 扇出（同时送多处，不复制） | 箭头即方向；扇出不需缓冲 |
| **三态门** | 线上加一道横杠 $+$ 控制端 | 谁能把值放上总线（**驱动权**） | 每个门必有一个使能 $\to$ 常是空 |
| **MUX** | 梯形，多入一出 $+$ 选择端 | 多选一 | 选择端 $=$ 控制信号；**两个来源必过它** |
| **寄存器** | 矩形 $+$ 时钟三角 | 值的暂存点 $=$ **时序边界** | 跨拍必须过它；无时钟三角 $=$ 组合逻辑 |
| **变换器** | ALU 梯形、加法器方框、移位器 | 值改变 | 两个输入口、一个输出口，**每口各一个来源** |
| **存储器/寄存器堆** | 大矩形，地址口 $+$ 数据口 $+$ 写使能 | 按地址存取值 | 寄存器堆 **2 读口 1 写口**；主存由 MAR 给地址、MDR 出/入数据 |
| 译码器 | 矩形，$n$ 入 $2^n$ 出 | 字段 $\to$ one-hot 选择线 | 输出直接接写使能/三态使能 $\to$ 填空常在这里 |

一个最小的可读片段（单总线机器的心脏）：

```
ALU 输出 ──[三态]──┐
                   ├── 内部总线 ──┬──[三态]──> MAR
移位器输出 ─[三态]─┘              └──[三态]──> 寄存器堆写口
```

读法：两个驱动者（互斥）、一个共享总线、两个接收者。**图上的每个空，都落在这三处的某一处。**

### 1.1 MUX / 三态门 / 译码器：区别、联系、用途

| 元件 | 输入 | 输出 | 选择信号管什么 | 未选中时 | 本质 |
|---|---|---|---|---|---|
| **MUX** | $2^n$ 路数据 + $n$ 位选择 | 1 路数据 | 选择端 $=$ **数据的编号** | 无（永远有一路通） | 集中式数据开关 |
| **三态门** | 1 路数据 + 使能 | 1 路，或**高阻 Z** | 使能 $=$ **是否交出驱动权** | 高阻（不是 0） | 分布式驱动开关 |
| **译码器** | $n$ 位编号 | $2^n$ 根，**仅一根有效** | 无——输出本身就是选择线 | 其余全 0（不是高阻） | 编号 → one-hot 选择线 |

三者的联系是一条链：**编号 → 译码器 → 选择线 → 分别驱动 MUX 的选择端 / 三态门的使能端 / 寄存器的写使能。**

```
编号 n 位 ─► 译码器 ─► one-hot 选择线 ─┬─► MUX.select    ─► 选中的数据
                                        ├─► 三态.enable   ─► 放到总线上的数据
                                        └─► 寄存器.写使能 ─► 下一拍被锁存
```

**「从 $N$ 个源里选一个」有三种物理做法**，408 题常混用；混用不算错，但代价不同：

| 做法 | 结构 | 线数 | 争用风险 | 延迟 |
|---|---|---|---|---|
| 集中 MUX | $N{:}1$ 多路选择 | 每组数据线都进 MUX | 无，结构上天然互斥 | 固定一级 |
| 分布式三态 + 总线 | 每个源一个三态门，输出共线 | 总线只 1 组 | **有**，全靠使能互斥 | 门延迟 + 总线电容 |
| one-hot 与门屏蔽 | 每源与自己的选择线相与再或 | 最宽 | 无 | 与/或两级 |

分界一句话：**译码器把「编号」变成「选择线」，MUX 与三态门把「选择线」变成「数据」**。所以一条总线上可以挂多个三态门，但只能有一个 MUX 的输出——前者的互斥靠使能，后者靠结构。

**典型用途速查**

| 元件 | 出现在图里的位置 |
|---|---|
| MUX | ALU 的 A/B 入口（寄存器 vs 立即数）、PC 下一值来源、寄存器堆写回源、地址来源（PC / 寄存器） |
| 三态门 | 单总线机器每个驱动者的出口、MDR 与总线的双向缓冲、多源共享数据线 |
| 译码器 | 寄存器堆读写选择、操作码 → 控制信号、地址译码（选片 / 选行）、中断向量选择 |
| 数据分配器 demux | $=$ 译码器 $+$ 数据使能（1 路进、$2^n$ 路出），与 MUX 互逆 |
| 编码器 | $2^n$ 路请求 → $n$ 位编号，与译码器互逆；典型：中断请求 → 向量号 |

**五个易错**

1. 三态未选中是**高阻**，不是 0；当 0 用就等于「线与」。
2. MUX 永远有一路通，三态可以全不通（总线浮空）——判「总线此刻无驱动」只能用后者。
3. 译码器输出 one-hot，不可能同时给两个寄存器写使能；填空里出现两根同拍写使能就是错。
4. 译码器**没有数据输入**；一旦有数据输入，它就叫 demux。
5. 一条总线两个以上驱动者 → 必须靠使能互斥；填空题里「少一个三态门」就是总线冲突。

## 二 读图四步（每步在纸上产出一份清单）

**Step 1 列出所有寄存器。** PC、IR、MAR、MDR、A、B、PSW、通用寄存器堆……每个时钟沿就是一次状态更新，沿的个数就是「拍」的候选数。

**Step 2 列出每条总线的驱动者。** 总线下面写「谁能驱动它」。两个以上驱动者就记下**互斥**约束——这正是填空最爱考的地方。

**Step 3 给每个输入口标来源。** ALU 的 A/B 口、MAR 的入、MDR 的入、寄存器堆的写口、存储器的地址/数据口。**没有来源的口就是空。**

**Step 4 一条指令走一遍。** 按 取指 $\to$ 译码/取数 $\to$ 执行 $\to$ 访存 $\to$ 写回 五段，逐拍写「谁驱动、谁锁存」。**走不通的那一拍就是题目。**

> 走两遍：数据流画一张、控制流画一张。教材图本来就把这两层叠在一起，分开画才看得出哪根线是使能。

## 三 填空题的五个类型

| 空的样子 | 考什么 | 判据（答案的唯一来源） |
|---|---|---|
| 两部件之间缺一根线 | 数据流是否成立 | 目标输入口无其他来源 $\to$ 必须连；已有来源 $\to$ 要过 MUX |
| MUX 选择端 / 三态使能端空着 | 控制信号从哪来 | 来源只有三种：**指令字段**（译码器输出）、**控制器时序信号**、**状态标志**（PSW） |
| 路径上缺一个部件 | 缺什么能力 | 要选 $\to$ MUX；要暂存 $\to$ 寄存器；要变宽/变窄 $\to$ 符号/零扩展；要算地址 $\to$ 地址加法器 |
| 线宽没标 | 位宽口径 | 机器字长 vs 存储字长 vs 指令字长；地址线宽由主存容量定 |
| 节拍划分空着 | 单周期 / 多周期 | 单总线一个周期只能用一次总线 $\to$ 取指至少 3 拍 |

**填空三问**（问完就填完）：

1. 这个口要的是**值**还是**地址**？——地址只能来自 MAR / PC / 地址加法器。
2. 这个值**这一拍就能得到**，还是**上一拍存的**？——后者必须过寄存器。
3. 同一拍还有没有第二个东西要驱动同一条线？——有，就分拍或加暂存器。

## 四 六条判据（把图钉死）

1. **一个输入口只有一个来源**：两个来源必须经过 MUX。这条否决 90% 的「多连一根线」。
2. **一条总线同一时刻只有一个驱动者**：三态门互斥；题目给两个来源，考的就是分拍。
3. **组合逻辑不跨时钟沿**：一拍内可串 ALU $\to$ 移位 $\to$ MUX，结果必须在沿前稳定；跨拍必须过寄存器。
4. **ALU 两个输入必须同拍可得**：若两个操作数都来自单端口部件（只读一次的主存、单写口寄存器堆），先暂存一个到 A/B。
5. **地址只从 MAR/PC 出**：教材模型把地址通路与数据通路分开；把地址送上数据总线是典型错图。
6. **写使能与写数据同拍**：读是组合的（给地址即出数），写是时序的（沿到才生效）；使能错一拍，写进去的是上一拍的值。

外加一条结构性约束（出自 [[Links of the Datapath]]）：**一个周期不能用两次同一个部件**——它是结构冒险的源头，也直接推出「单总线机器不可能是单周期」（除非指令只有一个源、一个目的）。

## 五 五段骨架（背下来，逐段套）

| 段 | 标准动作 | 常见空 |
|---|---|---|
| **取指** | PC $\to$ MAR $\to$ 主存 $\to$ MDR $\to$ IR；PC $+$ 1 $\to$ PC | 地址从谁出；PC 何时加；MDR $\to$ IR 是否要另起一拍 |
| **译码/取数** | IR 的 rs/rt 字段 $\to$ 寄存器堆读口；imm $\to$ 扩展器 | 字段到寄存器号是否要译码；符号/零扩展 |
| **执行** | A/B $\to$ ALU $\to$ 结果 | ALU 的 B 口来自 rt 还是 imm（MUX 选择端） |
| **访存** | ALU 结果 $\to$ MAR；MDR $\to$ 主存（写）或 主存 $\to$ MDR（读） | 读/写使能；store 时 rt 先送 MDR |
| **写回** | 结果 $\to$ 寄存器堆写口（写使能 $+$ rd 号） | 写口地址取 rd 还是 rt；写使能何时有效 |

R 型、Load、Store、分支、跳转的差别只在两处：**ALU 的 B 口来源**，以及**结果去了寄存器堆还是 MAR**。其余骨架相同——所以一条指令会写，五条都会写。

## 六 三型图的差异（先认型，再读图）

| | 单总线 | 多总线（双/三总线） | MIPS 型 |
|---|---|---|---|
| 一拍能搬几个值 | 1 | 2–3 | 由段决定 |
| 周期数 | 多（取指 $\ge$ 3 拍） | 少 | 单周期：一指令一拍，周期 = 最长路径 |
| 填空特征 | 大量「分拍」空 | 大量「MUX 选择」空 | 大量「段间寄存器 / 控制信号」空 |
| 主要考点 | 节拍表 | 同拍搬运是否合法（两个源能不能同时动） | 关键路径定时钟周期 |

## 七 写完的八项自查

1. 每个部件的**每个输入口**都标了来源？
2. 每个三态门都有使能，且同一拍**只有一个开着**？
3. 每个 MUX 都有选择端，来源合法（字段/控制器/标志）？
4. 每个跨拍的值都过了寄存器？
5. 地址只从 MAR / PC / 地址加法器出？
6. 写使能与写数据同拍，写口地址来自正确字段？
7. 同一拍没有用同一个部件两次？
8. 位宽一致（ALU 宽 / 数据总线宽 / 地址线宽）？
